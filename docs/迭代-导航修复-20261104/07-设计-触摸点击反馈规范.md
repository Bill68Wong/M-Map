## 0. 结论摘要

1. **项目里已经有一套按压反馈**（`globals.css:462-560`、`:1232-1262`），不是从零开始。但它有三个真缺陷：释放时长 **240ms 超过本轮 200ms 上限**；释放曲线带 **1.9 过冲**，与项目自己「禁弹跳曲线」的注释（`globals.css:197`）冲突；反馈强度按元素随机分布（卡片 0.96 / chip 不缩但换色 / 列表行只变底色 / 地图元素零反馈），没有分层。
2. 本规范把它收成 **三层通道**：**状态层（必需，即时）→ 形变（可选，仅小元素）→ 涟漪（可选，仅大面积卡片）**。三个通道各自独立可关，因此 `prefers-reduced-motion`、低端机、键盘触发都能退化而不失去"按下已被受理"的确认。
3. **形变不是全项目都做**。判据是一条硬规则：**元素短边 ≤ 56px 才允许缩放**；大于此的一律只做状态层。理由：350px 宽的卡片缩 4% 是 14px 的内容位移，会读成"卡片在动"而不是"我按了它"；且非整数缩放下文字会重新栅格化、在 90ms 内发虚。
4. **涟漪只用在卡片**，不用于按钮、列表行、chip、地图。按钮 48px 高，涟漪在 90ms 内就撑满，与整块状态层在视觉上不可区分，属纯成本；长列表每行涟漪会让滚动时满屏闪光（用户明确不要）。
5. **地图元素单独一档：只加环，不缩放、不涟漪**。理由有两条硬的：站点 11px / 轻轨 13px，缩放会**改变命中区**且让标记**偏离真实坐标**（地图上"点动了一下"等于谎报位置）；涟漪会漫出图形并压住线路。加环用 `box-shadow`（不影响布局与命中），并且**不改任何 z-index**。
6. **触觉默认不做**。iOS Safari 不支持 Vibration API（待真机验证），更重要的是：本项目已把"震动"专门留给**到站提醒**（设计文档 §2.4「横幅 + 震动、禁声音」），每次点击都震会稀释这个唯一的安全信号。
7. 交付一份可断言的契约：**`data-pressed="true"` 属性 + A1–A13 十三条判据**。其中 **A12「所有按压相关 transition-duration ≤ 200ms」会直接把现有的 240ms 判红** —— 这是本轮必须改的那一处。

## 2. 三层通道模型（本规范的总纲）

```
① 状态层（STATE LAYER）      必需 · 0ms · 任何元素都有
       ↓ 提供"按下已被受理"的最小确认；reduced-motion 下它是唯一通道
② 形变（SCALE）              可选 · 仅短边 ≤ 56px 的元素
       ↓ 提供"物理按下"的手感；reduced-motion 下关闭
③ 涟漪（RIPPLE）             可选 · 仅大面积卡片（T3）
       ↓ 提供"触点即因果"的空间定位；reduced-motion 下关闭
```

**为什么必须是三层而不是一套统一参数**：三者失效条件不同。状态层是颜色/明度（不怕动画禁用、不怕低端机）；形变依赖 transform（reduced-motion 要关）；涟漪依赖合成层（低端机与长列表要关）。如果只有一个通道，任何一次降级都会变成"完全没有反馈"。

**通道叠加纪律**：**涟漪与整块状态层互斥**（同一时刻只开一个），避免叠加后墨量翻倍。T3 卡片：正常 = 涟漪；reduced-motion / 键盘触发 = 状态层（同一个 0.12 常量）。其余档：只有状态层（+ 形变）。

## 3. 三要素规范（逐量给值与依据）

### 3.1 形变（scale）

| 档 | 值 | 依据 |
|---|---|---|
| 常规按钮 / 次按钮 | `0.97` | 48px 高按钮上 3% = **1.44px**。人眼对小于 2% 的尺寸变化不可辨（约 1px @48px），对大于 5% 会读成"元素被缩小"而不是"被按下"。3% 是"可辨但不改形"的区间中点。 |
| 图标按钮 | `0.94` | 沿用既有值（`globals.css:516-518`）。44px 圆键 6% = 2.6px；圆形元素在同样百分比下比矩形更易感知（周长/面积比更大），故给比矩形更大的比例才等效。 |
| 卡片 | `1.00`（**不缩放**） | 推荐卡宽约 350px，4%（现状 0.96）= **14px** 横向收缩。这已不是"按下去"，是"内容在动"。且 `transform: scale()` 在非整数倍下会重新栅格化文字，90ms 内文字发虚。YouTube 方案卡、Google Maps 地点卡均只做状态层，不缩放。 |
| 列表行 | `1.00` | 行是"选中"语义不是"按下实体"；且长列表连续点击时行间缩放会互相干扰视线。 |
| 底导 / 分段 | `1.00`（**仅图标盒** 0.94） | 整 tab 缩放会带动文字与选中指示条，产生"标签在跳"；只缩图标盒，文字保持像素对齐。 |
| chip | `1.00` | 沿用既有决策（`globals.css:512` 注释：4 列网格缩放会串味）。 |
| 开关 | `1.00` | 开关的反馈由**旋钮位移**承担（`--dur-base` 200ms），再叠加缩放会与位移抢注意力。 |
| 地图标记 | `1.00` | 见 §5。 |

**抬起回弹**：`180ms`，`cubic-bezier(0.2, 0, 0, 1)`（= 既有 `--ease-standard` / M3 standard）。
**不采用过冲**。理由：① 项目自己的注释（`globals.css:197`）已禁弹跳，现状用 1.9 过冲属自相矛盾，二者必改其一；② YouTube / M3 标准曲线均无过冲（过冲属 M3 *expressive* 家族，需要显式选择）；③ 本产品核心场景是**边走边看**，手持晃动叠加过冲会被读成"界面没跟上手指"；④ 3% 的位移配上过冲，峰值会短暂超过 100%（约 1.013），在 11px 小元素上反而像抖动。

> 若团队否决"去过冲"，则必须同步把 `globals.css:197` 的注释改写，否则下一个人会再把它改回来 —— 这是**文档与代码必须同源**的问题，不是口味问题。

**下限保护（关键）**：`transform` 会同步缩放命中区。44px 元素缩到 0.97 = 42.7px，瞬时低于 WCAG 2.5.5 的 44px。处理方式不是放弃形变，而是明确约束：**WCAG 2.5.5 约束的是静止态目标尺寸**；按压态只在手指已按下的期间存在，不参与可达性判定。工程上必须保证：**静止态命中区与改动前逐像素一致**（判据 A8）。

### 3.2 状态层（state layer）

| 档 | Token | 值 | 依据 |
|---|---|---|---|
| 主按钮（实底） | `--press-on-color` = `accent-on` | **0.12** | M3 state layer 按压档常量 **12%**（`_md-sys-state.scss` 可逐行核对）。实底按钮叠"前景色"是 M3 的 on-color 规则。 |
| 次按钮 / 文字按钮 | `--press-on-color` = `fg` | **0.12** | 同上；文字按钮没有实底，叠 `fg` 才能同时压暗底与保持字色不变。 |
| 卡片 | 涟漪（`--press-on-color` = `fg`） | **0.12** | 正常走涟漪（面积随时间展开，观感不靠全卡压暗）；reduced-motion / 键盘触发时退化为整卡状态层，**同样 0.12** —— 不另设 6%（见 §3.2.1）。 |
| 列表行 | `--press-row-bg` | `var(--surface-2)` | **沿用既有做法**（不新增叠层）。实测 ΔL\* = 6.9，高于 JND（约 1–2），强光下可辨。统一三套不一致（F8）到这一个值。 |
| 底导 / 分段 | `--press-on-color` = `fg` | **0.12** | 只作用于图标盒；小面积上 0.12 仍不显脏（实测 ΔL\* 9.8）。 |
| chip | `--press-on-color` = `fg`；`chip--on` 用 `accent-on` | **0.12**（两态同一常量） | 沿用既有"不缩放、改色"的决策，只把换色统一为状态层（既有换色是 `surface-dim → primary-container`，色相跨度太大，在 chip 网格里像"换了一个控件"）。 |
| 开关 | `--press-on-color` = `fg` | **0.12** | 作用于整条开关（含 label 与轨道），用 `::before`（`::after` 已被命中区占用，F12）。 |
| 地图标记 | 无填充层，**只有环** | 见 §5 | 填充层会让 11px 的站点"变成另一个颜色的点"，与站型语义（巴士圆/轻轨方/线路色）冲突。 |

**渲染位置与层叠（必须写清，否则会踩坑）**：
- 状态层用 `::after`：`position:absolute; inset:0; border-radius:inherit; background:var(--press-on-color); opacity:0; pointer-events:none`；按下时 `opacity: var(--press-op-pressed)`。**不透明度只出现在这一处**。
- **它叠在内容之上**（伪元素是最后一个子盒）。这不是疏忽，而是取舍：叠在内容之下需要给每个元素重建层叠上下文（`isolation` + 内容 `z-index`），代价远大于收益。实测 0.12 不破坏可读性：`--fg` 文字 18.05:1 → **14.04:1**；主按钮白字 8.38:1 → **6.21:1**（均 ≥ 4.5，见 §3.2.1 实测表）。**唯一的例外**：将来卡片内出现图片时，状态层必须改为图片下方，否则会给人像"蒙灰"。
- 目标若为 `position: static`，加 `position: relative` 前必须审计其绝对定位子元素；若有，改用等效的 `box-shadow: inset 0 0 0 9999px var(--press-on-color)` + 元素 `opacity` 不变（0.12 时两者视觉不可分辨，且同样不影响命中）。

**深色模式**：状态层用 `--fg` 派生，深色下 `--fg` 变浅 ⇒ 自动变成"提亮"，无需覆写。实测（0.12）：深色 `fg` on `surface` 12.92:1 → 按压 **9.37:1**（ΔL\* 11.3）；深色主按钮 `on-accent` on `accent` 7.50:1 → 按压 **6.18:1**。全部 ≥ 4.5。

### 3.2.1 唯一不透明度常量（结构性纪律）

**全站只有一个按下不透明度数字：`--press-op-pressed: 0.12`。** 任何第二处独立的 opacity 数字都视为缺陷。

技术实现上让这件事**不可违反**：状态层不写成 `color-mix(… 12% …)`，而是

```css
background: var(--press-on-color);          /* 命名色，无数字 */
opacity: var(--press-op-pressed);           /* 全站唯一的数字出口 */
```

这样"不透明度"在 CSS 里只出现一次（`--press-op-pressed` 的定义行），QA 可以直接断言 `getComputedStyle(el, '::after').opacity === '0.12'`。

**为什么放弃我上一版的三档阶梯（6% / 8% / 10%）**：三档各有道理（按"墨量守恒"大面积降档），但它制造了**三个可独立调参的数字** —— 与本次 U1 步行线「两套参数只改一半」是同型缺陷。你要求"0.12 有可核对来源、0.10 是估算"，这个判据同样适用于 6% 与 8%：它们都是我的估算。**可核对来源 > 估算**这一条应当全站一致，不能只在主按钮上遵守。

**面积问题的替代解法（不再用降 opacity 解决）**：

| 档 | 大面积怎么处理 | 为什么这样更好 |
|---|---|---|
| 卡片 | 走**涟漪**：面积随时间展开，任一时刻只覆盖局部，观感上不会"整卡蒙灰" | 用时间换面积，不靠削弱墨量 |
| 卡片（reduced-motion） | 整卡 0.12 状态层 | 只在用户系统设置了减少动态时出现，且是瞬时切换（`transition-duration: 0.01ms`），不产生"渐变变脏"的观感 |
| 列表行 | `--press-row-bg`（命名色 token，**不是** opacity 数字） | 行本来就是"底色交换"语义，不需要叠层；也避免与底色双重压暗 |

**0.12 实测（`.verify/_u11-op12.js`）**：

| 场景 | 叠加后背景 | 文字对比度 | ΔL\* |
|---|---|---|---|
| 浅色 · 正文 on 状态层 | `#e7e8e9` | **14.04:1**（原 18.05） | 9.8 |
| 浅色 · 主按钮白字 on 按下态 | `#36629c` | **6.21:1**（原 8.38） | 8.1 |
| 深色 · 正文 on 状态层 | `#303238` | **9.37:1**（原 12.92） | 11.3 |
| 深色 · 主按钮 on 按下态 | `#95b5e9` | **6.18:1**（原 7.50） | 6.6 |
| 参照 · 0.10（原方案） | — | 14.71 / 6.48 / 9.94 / 6.39 | 8.1 / 6.9 / 9.5 / 5.5 |

> 0.12 在所有组合上仍 ≥ 4.5:1，且反馈更明确（ΔL\* 提升 1–2 档）。结论：**采纳 0.12，无需下调**。

### 3.3 时延

| 档 | 按下（in） | 保持 | 松开（out） | 依据 |
|---|---|---|---|---|
| 主 / 次按钮 | 90ms | 至 pointerup | 180ms | in：M3 short2 = 100ms，取 90ms 留一帧余量；且这是项目已在线上验证过的值（`--dur-press`）。out：必须 ≤ 200ms（本轮硬约束）；M3 short4 = 200ms，取 180ms 留 20ms 给帧调度。 |
| 卡片 | 90ms（涟漪 120ms） | 至 pointerup | 180ms（涟漪 200ms） | 涟漪扩散略慢于形变，才有"铺开"的空间感；200ms 是上限值本身。 |
| 列表行 | **60ms** | 至 pointerup | **120ms** | 行是高频连续点击（选站/选收藏）。90ms 会让上一行的余晖与下一行的起始重叠，读成"列表在闪"。60ms = 3.6 帧，仍平滑。 |
| 底导 / 分段 | 90ms | 至 pointerup | 150ms | 切 tab 会触发路由/内容变化，150ms 让反馈与内容切换**部分重叠**，避免"先灭后换"的空档。 |
| chip / 开关 | 90ms | 至 pointerup | 150ms | 与底导同档；开关的弧线动画 200ms 独立运行，不叠加。 |
| 地图标记 | **16ms（一帧）** | 至 pointerup | 90ms | 见 §5.2：需要一帧消歧窗口过滤"按下即拖动"，但**不能用 80ms**——多数轻点持续时间只有 60–90ms，80ms 延迟会让快速轻点**完全没有反馈**。 |

**取消（手指滑出 / 手势冲突）**：
| 情形 | 处理 | 理由 |
|---|---|---|
| pointerleave / pointercancel | 走 out 曲线回退（180/120/150/90ms 按档） | 与正常松开一致，不额外加速；突然消失会被读成"闪断" |
| 手指滑出后**又滑回** | 重新 arm，再次显示 | 与原生按钮一致（M3 同样行为） |
| 地图拖拽位移 > 6px | **立即**移除 pressed，out 90ms | 拖拽中的残留 press 会被读成"地图卡了" |
| 长列表滚动 | 立即移除所有 pressed，且滚动期间不再 arm | 见 A5 |
| 元素被卸载（列表刷新） | 无需处理，属性随节点消失 | —— |

**绝对上限自查**：本规范最长动画 = 涟漪 200ms = 上限值，其余 ≤180ms。**现状 `--dur-release: 240ms` 超限，必须改为 180ms**（见 §8 变更表）。

## 5. 地图元素专章（T8）

### 5.1 只加环，不缩放、不涟漪 —— 三条硬理由

1. **缩放会改变命中区**。站点 11px / 13px，`transform: scale()` 直接缩放命中的几何。本轮硬约束明写"不得改变既有可点击区域的命中范围"。
2. **缩放会让标记偏离真实坐标**。地图标记的位置**本身就是信息**（"站在这里"）。按下时标记尺寸变化，视觉重心不变但边缘移动，在 11px 尺度上会被读成"点动了一下"——地图上的 1px 位移等于几十米误差的心理暗示。
3. **涟漪会漫出图形并压住线路**。11px 的圆点上放涟漪，半径必然 >20px，会盖住旁边的线路色与相邻站点；且站点层级只有 90/95，涟漪层要么被线路压住（看不见）要么必须提 z（破坏层级表）。

**环的构造（用 box-shadow，不动布局、不动命中、不动 z）**：

```css
/* 默认无环；按下时白色隔离带 + 深色环 */
.nav-map__station[data-pressed="true"] {
  box-shadow:
    0 0 0 2px var(--press-ring-gap-color),  /* #fff：与标记自带白边同族，形成隔离带 */
    0 0 0 4px var(--press-ring-map);        /* 深色环：在浅色瓦片上 19:1 */
}
```

- 环宽 2px @ 11px 标记 = 直径 18% 的外扩，与 `.nav-map__station--lrt` 的 13px 方点同量级；4px 总外径 = +8px，仍远小于相邻站点常见间距（>20px），不会互相咬合。
- `box-shadow` **不参与布局、不参与命中测试**，因此"命中范围不变"这条被结构性保证，而不是靠自觉。
- 颜色：`--press-ring-map: #0c0f14` **固定值，不随主题**（底图恒为浅色瓦片）。这与既有 `--map-walk-*` 的显式例外同源（`globals.css:7714-7719` 注释）。`--press-ring-gap-color: #fff` 用 `#fff` 属规则允许的例外。

### 5.2 拖拽冲突：一帧消歧 + 位移阈值（不用 `:active`）

**为什么不能用 `:active`**：`:active` 在 pointerdown 的**同一帧**就生效，且不感知移动。用户从 pin 上开始拖地图，`:active` 会让 pin 全程高亮到拖拽结束——正是负责人担心的那个缺陷。

**采用的方案**：

| 步骤 | 行为 |
|---|---|
| `pointerdown` on marker | 记录起点，**不立即**置 pressed |
| 下一帧（`--press-map-arm: 16ms`） | 若仍按下且累计位移 ≤ `--press-move-cancel: 6px` → 置 `data-pressed="true"` |
| `pointermove` 累计位移 > 6px | 立即移除 pressed（out 90ms），本次手势不再 arm |
| `pointerup` / `pointercancel` | 移除 pressed |

**为什么是 16ms 而不是 80ms**：轻点的典型持续时长是 60–90ms。若等 80ms 才显示，**大部分正常点击会完全没有反馈**（手指抬起时反馈才刚要出现）。16ms（一帧）足够过滤真实拖动——手指拖动在 60Hz 下第一帧就会产生约 3–5px 位移，配合 6px 阈值可在显示前拦下绝大多数拖动。

**残留容忍度（写进验收判据，不藏着）**：极慢起步的拖动（第一帧位移 <6px）会有 1 帧闪烁。允许 10 次拖动试验中 `data-pressed` 累计 ≤2 帧（约 33ms）。若要严格 0 帧，必须把 arm 延到 80ms 并接受"轻点无反馈"——两者不可兼得，**推荐前者**。

### 5.3 层级（明确"不改"）

**按压反馈一律不修改任何 `z-index`。** 唯一涉及层级的视觉是环，而环是 `box-shadow`（随元素自身图层绘制）。因此：

```
ghost 68 < done 69 < ahead 70 < 彩段 72 < now 73 < 站点 90/95 < pin 110/120 < 蓝点 128 < 车辆 130
```

- 被按下的站点仍在其 90/95 层：**经过的车辆（130）依然压住它**，语义正确（"车在这一站上面"）。
- 被按下的车辆仍是 130。
- **用户蓝点（128）不加按压反馈**：它不可点（纯定位），给了反馈就是假承诺。

## 6. 哪些元素不加按压反馈（以及为什么）

| 类别 | 例子 | 理由 |
|---|---|---|
| 纯展示文本 / 数值 | `.rc-tier` 档位标签、`.rc-total`、`.rc-hint`、`.rc-foot`、`.nav-actions__staterow` | 反馈是"点击已被受理"的承诺。不可点元素给反馈 = 假承诺，用户会反复点。 |
| 不可点的进度元素 | `.navstrip__row`（站点行）、`.navstrip__seg`、`.navstrip__badge` | 导航中站点行是**只读进度条**，点它没有任何动作。 |
| 地图底图 / 折线 / 多边形 | `Polyline`、域外遮罩 | 点击穿透给地图（拖拽/缩放），不是控件。 |
| 禁用态 | `button:disabled`、`.btn:disabled`、`[aria-disabled="true"]` | 既有规则已改为"换色不降透明"（`globals.css:520-537`）；再叠 press 会让人以为"再按一下就能用"。 |
| 加载中且不可重复提交的动作 | 提交中的主按钮（`is-loading`） | 已有 spinner 作为"已受理"回执；再给 press 会鼓励连点。 |
| 拖拽把手 | `.step-sheet__handle`、`.route-sheet__grabber`（拖动不是点击） | 按下是为了拖，不是为了触发；press 会与拖拽位移混淆。 |
| 用户蓝点 | z 128 | 不可点。 |
| 骨架屏 | `.rc-sk`、`.rc-walkpreview__sk` | 内容尚未存在，点击目标未就绪。 |

## 7. 无障碍与降级

### 7.1 `prefers-reduced-motion: reduce`

| 通道 | 处理 | 结果 |
|---|---|---|
| 形变 | `transform: none`（既有规则已做，`globals.css:552-554`） | 无位移 |
| 涟漪 | `display: none`（不渲染粒子/圆） | 无扩散 |
| 状态层 | **保留，且切换为瞬时**（既有全局 `transition-duration: 0.01ms` 已实现） | 按下即变色，**最小可见反馈仍在** |

**这一条是硬要求**：不能"关掉动效 = 什么都不发生"。按下必须有确认感，否则用户会怀疑没点到而重复点击（对"开始导航"这类按钮会造成重复请求风险）。

实现约束：涟漪层不要用 `animation-iteration-count: 1` 之类的"跑完就停"来降级（0.01ms 会让它瞬间闪一下），必须显式 `display: none`。

### 7.2 不依赖颜色单独传达

三通道分工：**明度（状态层）+ 形状/尺寸（形变）+ 轮廓（地图环）**。任取其一都能被感知：
- 灰度下：状态层是明度差（ΔL\* 6.9–9.5），不依赖色相；
- 色盲下：同上；
- 关动效：状态层仍在；
- 关透明（若将来支持 `prefers-reduced-transparency`）：形变 + 环仍在。

### 7.4 涟漪能力的降级（`mask` 不受支持时）

**结论：最坏情况退化为「无涟漪」，不得退化为「无反馈」。**

| 层 | 若 `mask` / `-webkit-mask` 均不被支持 | 结果 |
|---|---|---|
| 涟漪（T3 可选通道） | `mask-size` 不生效 ⇒ 圆形扩散画不出来 | **涟漪不可见**（仅此一项缺失） |
| 状态层（必备通道） | 走普通 `background` + `opacity`，与 mask 无关 | **正常生效**（`data-pressed` 出现、`opacity: 0.12`） |
| 形变（T1/T2 可选通道） | 走 `transform`，与 mask 无关 | **正常生效** |
| 地图环（T8） | 走 `box-shadow`，与 mask 无关 | **正常生效** |

**为什么这个降级方向是安全的**：状态层是"必需通道"，它不依赖 mask；涟漪只是"锦上添花"的空间因果。因此 mask 失效时用户仍然知道"按到了"，只是少了一个装饰性扩散 —— 符合「反馈链条必须有保底通道」的原则。

**兼容基线（team-lead 裁定，纳入）**：`-webkit-mask` 自 iOS 14 / Android Chrome 90 起可用，覆盖本项目 PWA 基线。实现必须**双前缀并存 + 无前缀兜底**（`-webkit-mask-*` + `mask-*` 各写一份），不得只写前缀版。

**对应判据**：A18（禁 mask 后状态层仍在）、A19（自裁不得改父级 overflow）。

### 7.3 触觉（`navigator.vibrate`）

**建议：不做通用触觉。默认关，且本批不提供开关。—— 这不是新取舍，本项目已有既定纪律。**

代码里的现状（已核实，注意文件位置与口头描述有出入）：

| 位置 | 事实 | 含义 |
|---|---|---|
| `TimerWizard.tsx:90-93` | 注释原文「关键打点（出发/上车/下车/到达）触发 10ms 短振感；**非每个点击都振**」 | **这是本项目对触觉的成文口径**：只给关键打点，不给普通点击 |
| `useRideTracking.ts:761-770` | `buzz(pattern)` 封装，供到站/提醒使用 | 震动通道已归"提醒"所有 |
| `useWalkFollow.ts:23` | 注释明确「本 hook **不调用** `navigator.vibrate`，也不要后续"顺手加一个"」 | 已有一处明确的"禁止顺手加"先例 |
| `WalkTurnBanner.tsx:20` | 注释明确「偏航**不加震动**、不加提示音…也不得以后加」 | 第二处 |
| `grep vibrate src/` | 仅 `useRideTracking` 与 `TimerWizard` 两处 | 通道清晰，无第三处 |

理由（按权重）：
1. **会有两处明确的"禁止"被推翻**。上面两个 hook 的注释是前人踩过之后写下的，加通用触觉等于把它们作废；而它们禁止的理由（偏航提示不该抢注意力）与"普通按钮不该抢注意力"完全同构。
2. **会稀释唯一的安全信号**。震动已被「到站提醒」独占（设计文档 §2.4「横幅 + 震动、禁止声音」）。每次点按钮都震，用户在车上就无法靠触觉区分"到站了"和"我点了个按钮"——这是安全问题。
3. **平台不生效且不做兜底**。iOS Safari 不支持 Vibration API（**待真机验证**：架构师用 `'vibrate' in navigator` 一条断言即可结掉）。若为 false，则 iOS 用户天然无触觉 —— 按要求**不写兜底**（不做"模拟震动"的视觉替代，那会变成另一种噪声）。
4. **不同步**：Android 马达启动延迟约 10–50ms，与 90ms 的视觉反馈叠加后会被读成"两下"，反而削弱因果感。
5. **不可断言**：震动无法被 QA 自动化验证，属于"做了也验收不了"的投入。

若产品坚持，唯一允许的位置：**「开始导航」主按钮，每会话最多 1 次，默认关、设置项开启**；且必须落在到站提醒的静默窗口（`±5s`）之外。

## 9. 可机器验证的验收判据

> 契约：**被按下的元素**写 `data-pressed="true"`，松开/取消时**移除该属性**（不写 `false`）。全站唯一写入口，禁止各组件各写一套（与 `observe-hooks.ts` 的单点写入纪律同源）。
> 只读 DOM 属性不足以证明视觉生效，因此每条都配一个"计算样式"断言。

| # | 判据 | 怎么测 | 通过条件 |
|---|---|---|---|
| **A1** | 按下后 X ms 内出现按下态 | Playwright `mousedown`/`touchstart` + `MutationObserver` 记录 `data-pressed` 出现时刻（`performance.now()` 差值） | T1–T7 **≤16ms**；T8 地图 **≤32ms**（一帧 arm + 一帧写属性） |
| **A2** | 松开/取消后清除 | `mouseup` / `pointercancel` / `pointerleave` 后轮询 | **≤16ms** 内属性消失；地图 ≤16ms；且 `pointerleave` 后再 `pointerenter` 能重新置位 |
| **A3** | 形变值与档位一致 | `getComputedStyle(el).transform` | T1/T2 = `matrix(0.97, 0, 0, 0.97, 0, 0)`；T2 图标键 = `0.94`；**T3–T8 = `none`** |
| **A4** | reduced-motion 下仍有最小反馈 | `emulateMedia({reducedMotion:'reduce'})` → 按下 | `data-pressed="true"` 仍出现；`transform === 'none'`；涟漪节点 `display === 'none'`；`::after` 的 `opacity === '0.12'`（T3 与其余档同值） |
| **A5** | 长列表滚动期间无按压态 | 在 `.ssheet__list` / `.route-sheet__scroll` 上连续 30 次滑动，每 16ms 采样 | 滚动位移非零期间，`[data-pressed="true"]` 计数恒为 **0**；滚动停止后 100ms 内仍为 0 |
| **A6** | 地图拖拽期间不出现按压态 | 从 pin 中心按下后拖 120px（10 次，含 2 次慢起步） | `data-pressed` 累计存在时间 **≤33ms（2 帧）**；`dragend` 后 16ms 内为 0 |
| **A7** | 层级不被按压改变 | 按下前后读 `getComputedStyle(el).zIndex`；地图读 `marker.getZIndex()` | **逐元素完全相等**；且全站按下时不存在任何新增的 `z-index` 声明 |
| **A8** | 静止态命中区不变 | 元素包围盒按 10px 网格采样 `document.elementFromPoint`，比较改动前后命中的元素集合 | 集合**完全相同**（允许新增元素仅限既有 expander 伪元素） |
| **A9** | 列表行不叠层（不双重压暗） | T4 按下时读 `backgroundColor` 与 `::after` 的 `opacity` | `backgroundColor` = `--press-row-bg` 解析值；`::after` `opacity === '0'` |
| **A10** | 涟漪不越界 | 卡片按下时截图，与静止态做像素差；统计宿主 `border-box` **之外**的变化像素 | 宿主外变化像素 **= 0**（容差 2/255 抗锯齿） |
| **A11** | 按下态文字对比度 | 合成按下后背景，计算文字对比度 | ≥ **4.5:1**（0.12 实测：浅色主按钮 6.21、深色主按钮 6.18、浅色正文 14.04、深色正文 9.37） |
| **A12** | 所有按压动画 ≤200ms | 遍历按下元素的 `transitionDuration` / `animationDuration`，取最大值 | **max ≤ 200ms**（现状 240ms 会被这条判红） |
| **A13** | 无 emoji / 无硬编码色 / 不破坏既有禁用样式 | `grep` 新增 CSS 段；`button:disabled` 的 `opacity` 仍为 `1` | 新增段 `#hex` 仅允许 `--press-ring-map` 与 `--press-ring-gap-color` 两行定义；禁用规则未被覆写 |
| **A15** | 全站只有一个按下不透明度数字 | `grep -rnE 'opacity://s*0?//.[0-9]+' src/app/globals.css` 后过滤按压相关选择器；并断言 `getComputedStyle(el,'::after').opacity === '0.12'` | 按压相关规则中 opacity 数字**只有 `var(--press-op-pressed)`**；`::after` 计算值为 `0.12` |
| **A16** | 双曲线仍成立（按下快、抬起慢） | 读按下与松开两个时刻的 `transitionDuration` | 按下 `90ms`（行 `60ms`）；松开 `180ms`（行 `120ms`）；**两者不相等且抬起更长** |
| **A17** | 涟漪起点 = 真实触点（非元素中心） | 在卡片**左上角**按下：① 读 `getComputedStyle(card).getPropertyValue('--press-x' / '--press-y')`；② 可选像素复核涟漪圆心 | ① 变量值与触点局部坐标偏差 **≤2px**（指针事件）；键盘触发时允许回落 `50%`（无触点）② 圆心距左上角 ≤24px，且距元素中心 ≥ 卡宽×0.3 |
| **A18** | mask 不受支持时涟漪退化、但反馈链不塌 | 启动参数禁用 mask（`--blink-settings=...` 不可行时用 CDP 注入 `CSS.supports` 桩，或直接在 DevTools 覆盖 `.press-ripple::after{mask-image:none;-webkit-mask-image:none}`）；然后按下卡片 | `data-pressed="true"` 仍出现；`::after` 的 `opacity === '0.12'`（状态层仍在）；**若该元素有形变档，`transform` 仍生效**；页面无报错、无布局变化。即：最坏退化为「无涟漪」，不得退化为「无反馈」 |
| **A19** | 涟漪自裁不得给父级新增 `overflow:hidden` | 改动前后对 `.rc` / `.rv-card` / `.press-card` 的**父元素**读 `getComputedStyle(parent).overflow` / `overflowX` / `overflowY` | 三者**与改前逐字段相等**；且新增 CSS 段中不出现 `overflow: hidden`（grep 断言）。理由：父级裁切会连 `focus-visible` 的 `outline`/`box-shadow` 与角标一起裁掉 |

**A6 拆成两条（便于 QA 逐条登记）**

| # | 判据 | 通过条件 |
|---|---|---|
| **A6a** | 地图**拖拽过程中**不得出现 press 态 | 从 pin 按下 → 拖 120px（10 次，含 2 次慢起步）：`data-pressed` 累计存在时间 **≤33ms（2 帧）**；拖动期间目标 marker 的 `data-pressed` 不出现（除上述 ≤2 帧） |
| **A6b** | 同一手势结束后必须干净 | `pointerup` / `dragend` 后 **≤16ms** 内全站 `[data-pressed]` 计数为 0；且下一次轻点能正常出现 press |

**辅助断言（不进 CI，发版前跑一次）**：A14 视觉基线——取 T1/T3/T4/T8 各一张「静止 / 按下」截图，人工确认三通道中至少两个可见。

**为什么 A12 是这一批的关键**：它是唯一能把"文档写了 ≤200ms、代码还留 240ms"这种分叉判死的判据，且不依赖任何主观判断。
**为什么 A15 与 A17 同样该进 CI**：A15 锁死"两套参数只改一半"的同型复发；A17 锁死"从元素中心扩散"这个 Material 早期做法的回潮（YouTube 现行是从触点起）。

## 10. 与 YouTube / M3 的对应与刻意分歧

| YouTube / Google 的做法 | 本规范 | 是否一致 | 理由 |
|---|---|---|---|
| 触点涟漪（ripple），从按下位置扩散 | T3 卡片采用，直径 ≥2×对角线 | 一致 | 卡片是"大面积可点区域"，涟漪提供空间因果 |
| 涟漪铺满所有可点元素 | 只给 T3 | **分歧** | 48px 按钮上涟漪 90ms 就撑满，与状态层不可区分；长列表每行涟漪会满屏闪 |
| M3 state layer 按压 0.12 | **全站唯一常量 0.12**（层/涟漪/键盘兜底同值） | 一致 | 见 §3.2.1：可核对来源优先于估算，且杜绝"两套参数只改一半" |
| 无过冲（standard / emphasized 曲线） | 去掉既有 1.9 过冲 | 一致 | 见 §3.1 |
| 涟漪约 300ms | 120ms 扩散 / 200ms 收尾 | **分歧** | 本轮硬约束 ≤200ms |
| Google Maps 地点卡：整卡状态层，不缩放 | T3 一致 | 一致 | 大面积缩放会读成"内容在动" |
| Google Maps 图钉：选中光环（halo），不涟漪 | T8 用环 | 一致 | 小目标不能涟漪；环不动命中 |
| 触觉反馈（部分 Pixel 机型） | 不做 | **分歧** | 会稀释到站震动的唯一性（见 §7.3） |

## 11. 交接给前端的硬约束

1. **唯一写入口**：`data-pressed` 由一个统一控制器写（放在 session/根层，或与 `observe-hooks.ts` 同级的模块），**禁止每个组件自己 `setAttribute`**。理由：两份状态必然漂移，且 QA 无法断言。
2. **状态层不得改 `z-index`**，不得新增 `position: absolute` 的兄弟节点（只用宿主自身的伪元素）。目标为 static 且含绝对定位子元素时，改用 `inset` 硬投影。
3. **涟漪只在 T3**；且涟漪与整块状态层**互斥**，不得同时开启。
4. **地图标记不得用 `:active`** —— 必须走 §5.2 的一帧 arm + 6px 取消。
5. **既有 `-webkit-tap-highlight-color: transparent` 不得删除**（`globals.css:466`）。删了 iOS 会出现系统蓝框，比没有反馈更糟。
6. **不改命中区**：静止态逐像素一致（A8）；所有新伪元素 `pointer-events: none`。
7. **`--dur-release` 必须从 240ms 改到 180ms**；`--spring-release` 若保留过冲，必须同步改写 `globals.css:197` 的注释（二者只能改一个方向，不能继续自相矛盾）。

## 12. 「无矛盾冲突」判定清单（哪些可以按 YouTube / M3 标准升级）

判据不是"好不好看"，而是**存在哪种冲突**。冲突源只有五类：**容器裁切（overflow/radius）· 层叠（z-index）· 手势（拖动/滚动）· 面积与命中区 · 与既有 90ms 节奏/语义冲突**。

| 类 | 元素 | 判定 | 冲突源 | 允许做的升级 | 不得做的 |
|---|---|---|---|---|---|
| T1 主按钮 | `.btn--primary`、`.btn--tonal` | **可升级** | 无（无裁切、无手势、48px） | 状态层 0.12 + `scale .97` + 双曲线 90/180 + **硬投影 `2px→1px`** | 涟漪（48px 上 90ms 撑满，等于纯成本） |
| T2 次按钮 | `.btn--text`、`.btn--outline`、`.btn--icon`、`.nav-brand` | **可升级** | 无；`.btn--icon` 圆形，同比例感知更强 | 同上；icon 用 `scale .94` | 涟漪；改命中区 |
| T3 卡片 | `.rc`、`.press-card`、`.rv-card`、收藏卡 | **可升级（涟漪）** | **容器裁切**：`.rc` 有 `overflow:hidden`（`globals.css:1241`），`.rv-card` 无 ⇒ 涟漪必须**自裁**（`border-radius:inherit` 的背景/mask），不得依赖给父级加 `overflow:hidden`（会裁掉 focus ring 与角标） | 涟漪（触点起、0.12、圆形自裁）+ 双曲线 90/180（涟漪 120/200） | `scale`（350px × 4% = 14px 内容位移 + 文字重栅格化发虚） |
| T4 列表行 | `.nav-sbox__row`、`.ssheet__item`、`.rpanel__row`、`.fav-flat__main`、`.line-result` | **保持现状（只做统一）** | **长列表性能 + 滚动手势 + 连点节奏**：涟漪在 30 行列表滚动时会满屏闪；行内缩放会让相邻行互相干扰 | 把三套不一致统一为 `--press-row-bg`；时长降到 60/120 | 涟漪；`scale`；边框/阴影变化（会在长列表里产生"脉动感"） |
| T5 底导/分段 | `.bottom-nav__tab`、`.pref-switch__opt` | **可升级（限定图标盒）** | **容器裁切风险低，但与既有 90ms 节奏冲突**：整 tab 缩放会带动文字与 `is-active` 指示条，读成"标签在跳" | 状态层 0.12 + **只缩图标盒** `.94` | 整 tab `scale`；涟漪（`.bottom-nav` 无 overflow，会漫到底部安全区） |
| T6 chip/标签 | `.chip`、`.chip--on` | **可升级（仅状态层）** | **网格**：4 列 chip 的 `scale` 会让相邻格产生"串味"；且既有已明确"不缩放"（`:512` 注释） | 用 0.12 状态层**替换**既有的大跨度换色（`surface-dim → primary-container` 色相跨太远，像"换了个控件"） | `scale`；涟漪 |
| T7 开关/勾选 | `.lrt-switch`（`role="switch"`）、checkbox | **可升级（用 `::before`）** | **伪元素被占**：`::after` 已用于命中区扩展（`globals.css:7263-7268`）；旋钮有独立 200ms 位移 | 状态层 0.12 走 `::before` | 改 `::after`；给旋钮再加缩放（会与位移抢注意力） |
| T8 地图 pin | `.nav-map__station`（z90/95）、车辆（z130）、pin（z110/120） | **不得升级为形变/涟漪（只允许环）** | **地图手势 + 命中区 + 锚点偏移 + 层叠**四重冲突：`scale` 改命中区且让标记偏离真实坐标；涟漪漫出 11px 图形、要么被线路压住要么破坏 z 表 | 外扩细描边环（`box-shadow`，不动布局/命中/z） | `scale`；涟漪；任何 z 改动 |
| 拖拽面 | `.route-sheet__peek` | **可升级但必须走手势消歧** | **手势**：`touch-action:none` 且整块是拖拽把手；用 `:active` 会在整个拖动过程常亮 | 状态层 0.12 + 一帧 arm + 6px 取消（与地图同构） | `scale`（拖动时元素跟着缩会像"面板在抖"）；涟漪 |
| 原生披露行 | `.help-faq__q`（`<summary>`） | **可升级（仅状态层）** | 无裁切、无手势；但**非按钮**，`button` 基元选择器不覆盖它（所以现在完全没反馈） | 状态层 0.12，`border-radius: chip` | `scale`（整行宽度，缩放会与下方内容错位） |

**四条推论（记在 Spec 里，避免以后反复讨论）**

1. **"可升级"不等于"全上三通道"**：全表只有 T3 拿到涟漪；只有短边 ≤56px 的拿到形变；**状态层是所有档的公共底座**。
2. **与既有 90ms 节奏冲突时，节奏优先**：例如底导、chip 的 `in` 保持 90ms（不因为"要更 YouTube"而改 60ms），因为跨页面一致性比单个元素的灵敏度更重要。
3. **不得升级的四类，理由都不是"麻烦"，而是会违反本轮硬约束**（命中区、z 层、手势、≤200ms）。
4. **拖拽面必须与地图同构**（一帧 arm + 6px 取消）。若实现成 `:active`，会复现"拖地图时 pin 一直高亮"的同款缺陷。

## 13. 「升级」到底改了哪个属性（diff 级）

> 这一节回答"我们到底做了什么和以前不一样"，全部是属性级可核对差异，不含形容词。

| # | 属性 | 现状 | 升级后 | 性质 |
|---|---|---|---|---|
| D1 | 按压叠加方式 | `filter: var(--state-active)` = `brightness(0.9)` | `::after` 叠层，`opacity: var(--press-op-pressed)` | **实质升级**：`filter` 会连同**子元素**一起压暗（车牌黑底黄字、线路彩色标签、图片都被压暗失真）；叠层只压底层，子元素保持原色。这也是 M3 / YouTube 的做法 |
| D2 | 叠加强度 | 亮度 −10%（= 约 0.10 墨量） | 0.12（M3 常量，可核对） | 数值统一 + 有来源 |
| D3 | 抬起时长 | `--dur-release: 240ms` | `--press-out: 180ms` | **硬约束修复**（≤200ms） |
| D4 | 抬起曲线 | `cubic-bezier(0.22, 1.9, 0.36, 1)`（过冲约 1.013） | `cubic-bezier(0.2, 0, 0, 1)`（无过冲） | **修自相矛盾**（`:197` 注释已禁弹跳） |
| D5 | 卡片形变 | `scale(0.96)` | **无**（`--press-scale-none: 1`） | 去内容位移与文字重栅格化 |
| D6 | 卡片反馈 | 变底色 `--surface-dim` | 涟漪（触点起，0.12，自裁圆角） | **新增通道**，空间因果 |
| D7 | 列表行 | 三套不一（`brightness(0.9)` / `--surface-2`） | 统一 `--press-row-bg`；60/120 | 统一 + 高频优化 |
| D8 | chip | 换色 `surface-dim → primary-container` | 0.12 状态层（色相不变） | 语义收敛（不再像"换了个控件"） |
| D9 | 地图标记 | **零反馈** | 外扩细描边环（2px 隔离 + 2px 环） | **新增通道**，不动命中/z |
| D10 | 折叠键 / 品牌牌 / 行内链接 / peek / FAQ 行 | **零反馈**（5 处缺口） | 状态层（+ peek 走手势消歧；链接类按 `--icon` 变体决定是否 0.94） | **补全** |
| D11 | 可观测性 | 只有 `:active`，QA 无法断言 | `data-pressed="true"` 单点写入 | **可验收**（A1–A17） |
| D12 | 不透明度数字 | 散落（`brightness(0.9)`、各组件 op） | 全站唯一 `--press-op-pressed: 0.12` | **结构性防复发** |

### 14.3 卡片涟漪（触点起、自裁）

```css
/* 涟漪 = 宿主自己的 ::after，用 mask 做从 0 到 D 的圆形扩散。
   为什么用 mask 而不是子元素圆：不能新增 DOM；且 mask 天然被 border-radius 裁切。
   注意：溅射半径 D 与触点 x/y 由统一控制器在 pointerdown 时写入（见 14.5）。 */
.press-ripple::after {
  content: "";
  position: absolute;
  inset: 0;
  border-radius: inherit;
  background: var(--press-on-color);
  opacity: 0;
  pointer-events: none;
  -webkit-mask-image: radial-gradient(circle at center, #000 99%, transparent 100%);
          mask-image: radial-gradient(circle at center, #000 99%, transparent 100%);
  -webkit-mask-repeat: no-repeat;  mask-repeat: no-repeat;
  -webkit-mask-position: var(--press-x, 50%) var(--press-y, 50%);
          mask-position: var(--press-x, 50%) var(--press-y, 50%);
  -webkit-mask-size: 0 0;          mask-size: 0 0;
  transition: -webkit-mask-size var(--press-ripple-in) var(--press-ease-out),
              mask-size var(--press-ripple-in) var(--press-ease-out),
              opacity var(--press-ripple-out) var(--press-ease-out);
}
.press-ripple[data-pressed="true"]::after {
  opacity: var(--press-op-pressed);
  -webkit-mask-size: var(--press-d) var(--press-d);
          mask-size: var(--press-d) var(--press-d);
}
/* 键盘触发（无触点）⇒ 允许从中心扩散 */
.press-ripple[data-pressed-via="key"]::after { --press-x: 50%; --press-y: 50%; }
```

> 性能备注：`mask-size` 属绘制层动画，只在**单卡 120ms** 内发生，不在长列表触发（T4 无涟漪）。若架构师在真机测得掉帧，可对 `.rc`（已有 `overflow:hidden`）改用"子盒圆 + `transform: scale()`"的合成层方案，视觉等价 —— 但**起点仍是触点**（A17 不放松，它是判据不是实现细节）。
>
> **落地前置（team-lead 要求）**：实现前先用临时 HTML 或注入一段 `style` 做一次最小可跑验证，确认双前缀下**不漫出、不闪、无掉帧**；通过才落实现，不通过则退到上面的合成层替代方案（`.rc` 先行，`.rv-card` 仍走 mask + A18 降级）。
>
> **mask 不受支持时的行为**：涟漪不显示，状态层与形变仍生效（详见 §7.4，判据 A18）。**不得**为了"让涟漪一定可见"而给父级加 `overflow:hidden`（会裁掉 focus ring，判据 A19）。

### 14.4 五处缺口元素 → 4 类规则

> 结论：**按类归成 4 类**（链接类合并两元素），因为反馈策略相同，差异只在"是否缩放"。

```css
/* ── 类 A：链接类（.link-hit / .rc-report__link）──
   共同点：命中区已由既有规则处理（.link-hit 用 -12px margin 撑到 44px），
           绝不能因为按下态再改命中区；都不做涟漪。 */
.link-hit,
.rc-report__link { position: relative; }      /* 若已是 static 才需要 */
.link-hit::after,
.rc-report__link::after {
  content: ""; position: absolute; inset: 0;
  border-radius: var(--radius-chip);           /* 这两个元素自身无 radius，显式给 */
  background: var(--press-on-color);
  opacity: 0; pointer-events: none;
  transition: opacity var(--press-in) var(--press-ease-in);
}
.link-hit[data-pressed="true"]::after,
.rc-report__link[data-pressed="true"]::after { opacity: var(--press-op-pressed); }
/* 变体：32×32 图标链可缩，行内文字链不缩（避免整段文字位移） */
.rc-report__link[data-pressed="true"] { transform: scale(var(--press-scale-icon)); }

/* ── 类 B：品牌牌（.nav-brand）── 已有边框与 6px 圆角，只叠层 + 可用按钮档缩放 */
.nav-brand[data-pressed="true"]::after { opacity: var(--press-op-pressed); }
.nav-brand[data-pressed="true"] { transform: scale(var(--press-scale-btn)); }

/* ── 类 C：拖拽摘要面（.route-sheet__peek）── 必须与地图同构：
   一帧 arm + 6px 取消；不得用 :active（会在整个拖动过程常亮）。
   本身是整块面板顶部，不做 scale。 */
.route-sheet__peek[data-pressed="true"]::after { opacity: var(--press-op-pressed); }

/* ── 类 D：原生披露行（.help-faq__q 是 <summary>）──
   button 基元选择器覆盖不到它，所以目前完全没反馈。整行宽度，不缩放。 */
.help-faq__q { position: relative; border-radius: var(--radius-chip); }
.help-faq__q[data-pressed="true"]::after { opacity: var(--press-op-pressed); }
```

**为什么这 5 处之前全没有反馈（机制，不是疏漏）**：

| 元素 | 为什么漏 |
|---|---|
| `.nav-brand` | 它是 `<Link class="nav-brand">`（`<a>`），而按压基元选择器是 `button, .btn, .btn--undo`（`globals.css:465-467`）—— `a.nav-brand` 不匹配 |
| `.link-hit` | 同上：`<Link>` 渲染成 `<a>`，无 `.btn` 类 |
| `.rc-report__link` | 同上 |
| `.help-faq__q` | 是 `<summary>`，既非 button 也非 `.btn` |
| `.route-sheet__peek` | 是 `<div>`（拖拽面），从未挂按压规则 |

⇒ **根因是一句话：按压基元挂在"类 + button 元素"上，凡是 `<a>` / `<summary>` / `<div>` 的可点元素都会漏。** 这也是为什么不建议继续往 `button, .btn` 后面追加选择器（会越加越长），而应改为「统一控制器 + `data-pressed`」：**写属性的一端不关心元素类型**。

### 14.5 统一控制器（伪代码，唯一的 `data-pressed` 写入者）

```ts
// 全站唯一：禁止任何组件自己 setAttribute('data-pressed', ...)
const ARM = 16, MOVE_CANCEL = 6;

function onPointerDown(e: PointerEvent) {
  const el = (e.target as Element).closest<HTMLElement>('[data-pressable]');
  if (!el || el.matches(':disabled, [aria-disabled="true"]')) return;
  const rect = el.getBoundingClientRect();
  // 触点 → 元素局部坐标（涟漪起点；键盘事件无触点时回落 50%）
  el.style.setProperty('--press-x', `${((e.clientX - rect.left) / rect.width) * 100}%`);
  el.style.setProperty('--press-y', `${((e.clientY - rect.top) / rect.height) * 100}%`);
  const d = Math.hypot(rect.width, rect.height) * 2;   // ≥2× 对角线
  el.style.setProperty('--press-d', `${d}px`);

  const needsArm = el.dataset.pressGesture === 'map' || el.dataset.pressGesture === 'drag';
  if (!needsArm) { el.dataset.pressed = 'true'; return; }   // 普通按钮：当帧即显

  const sx = e.clientX, sy = e.clientY;
  const t = setTimeout(() => { el.dataset.pressed = 'true'; }, ARM);   // 一帧消歧
  const move = (ev: PointerEvent) => {
    if (Math.hypot(ev.clientX - sx, ev.clientY - sy) > MOVE_CANCEL) {
      clearTimeout(t); delete el.dataset.pressed;        // 拖动 ⇒ 取消
      cleanup();
    }
  };
  const cleanup = () => { /* removeEventListener... */ };
  window.addEventListener('pointermove', move, { passive: true });
  window.addEventListener('pointerup', cleanup, { once: true });
  window.addEventListener('pointercancel', cleanup, { once: true });
}

// 滚动期间：全局捕获 scroll，立即清空所有 pressed，并在滚动停止后 100ms 内不 arm
```

### 14.6 与既有 `:active` 的关系（迁移策略）
