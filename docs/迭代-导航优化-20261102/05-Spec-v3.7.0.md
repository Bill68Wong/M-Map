## 1. 本期目标（一句话）

在不改变任何路线结果的前提下把搜索与导航链路的等待时间压到热态 2 秒内，并让导航在中途断网、切后台、上车后才开始这三种真实场景下都不失效。

## 3. 缓存红线（负责人硬约束 · 违反视为阻断缺陷）

> 背景：负责人反馈过「从收藏页进入导航拿到旧数据、刷新才生效」。
> 红线条款**由架构师论证后定论**（负责人要求不得由项目总监直接拍板），完整版见
> `06-缓存策略与新鲜度保障.md` §6（RL1~RL9，每条含「判据（怎么机验）+ 违反后果」）。
> 本节只保留结论摘要与三条最关键的机制。

### 3.1 根因结论（推翻「缓存导致」的直觉）

判据来自负责人的原话「**刷新才生效**」：
- 若是数据源缓存（CDN / `transit_cache` / `force-cache`），**浏览器刷新救不了**（旧副本仍在）⇒ 与描述矛盾；
- 若是组件状态复用，整页刷新 = 重新挂载 = 状态清空 ⇒ **立刻生效** ⇒ 与描述吻合。

⇒ **根因是「组件状态复用 + 请求去重」，不是数据源缓存**。具体位置：`src/components/nav/useRecommend.ts:143-147` 的
`loadedQueryRef.current === fullQuery` 跳过判断**不含任何时间因素** ⇒ 20 分钟后点同一 OD 一个请求都不发。
该缺陷**当前仍在线上**，本期必须修（已派前端）。

### 3.2 九条红线（RL1~RL9 摘要）

| 编号 | 红线 | 判据要点 |
|------|------|----------|
| RL1 | 缓存条目不得含**本项目自己计算的**实时值（车辆位置、到站剩余、等待时长）；`transit_cache` 存的高德原始方案为**显式豁免**（受 RL4 约束） | 缓存条目字段清单 + `assertNoLiveFields` |
| RL2 | 静态缓存键**由数据形状自动派生**（列集合指纹），不靠人手 +1 版本号 | 键名含派生指纹 |
| RL3 | 服务端必须校验 `issuedAt`：缓存条目写入时刻早于用户发起时刻 ⇒ 不命中 | `fetched_at >= to_timestamp(issuedAt)` |
| RL4 | `transit_cache` 保持 60s，**不上调**；要提速走 `issuedAt`，不走延长 TTL | 源码常量 |
| RL5 | 浏览器强缓存仅限纯几何/站点清单；实时接口一律 `no-store` | grep 每个 `force-cache` 的 URL |
| RL6 | 去重缓存必须回报 `cachedAgoMs`（不得「只刷时间基准」冒充新鲜） | 响应含陈旧度字段 |
| RL7 | 静态与实时在类型层隔离（`NavStaticOnly` / `NavLiveOnly`），越界**抛错不 warn** | 类型检查 + 运行时断言 |
| RL8 | 缓存状态观测必须在**同一实例**内读取，不得跨实例推断 | `/api/health?warm=1` |
| RL9 | 静态缓存体积必须有**预警**（不是只在超限后跳过） | `sizeBytes > 1.8MB` 即告警 |

### 3.3 三层机制（缺一层就漏一类问题）

| 层 | 落点 | 管住什么 |
|----|------|----------|
| 类型层 | 新增 `src/lib/nav/freshness.ts`（`IssuedAt` 品牌类型 + `assertNoLiveFields`） | 防止把实时字段塞进可缓存结构 |
| 服务端 | `TransitCacheIo.get(odKey, ttlSec, issuedAt?)` + `/api/nav?issuedAt=` | 防止复用「比本次请求更旧」的缓存条目 |
| 客户端 | `loadedAtRef { q, at }` + 5s 复用窗口 | 防止「压根不发请求」 |

⚠️ 硬约束：`issuedAt` **不得进入** `fullQuery`（它是 `mergeCardsStable` 的守卫键）—— 掺时间会让 merge 永不命中、列表每次整体替换（= 2026-10-29 `3b7096f` 修过的阻断缺陷）。

**已有缓存的合规结论（本期只补 RL5 缺口，其余不改）**：

| 缓存 | 内容 | 判定 |
|------|------|------|
| `getStaticRows`（Data Cache） | 站序 / 段统计 / 步行 / 换乘 / 轻轨时刻表 | 合规。~~3.07MB 超 2MB 从未写入~~ **该前提已过期**：v3.6.1 数组编码后入缓存体积 **1.20MB < 2MB**，缓存正常工作，**本期不拆包**，只加 RL9 体积预警 |
| `transit_cache` | 高德路径规划原始方案 | 合规（RL1 豁免 + RL4 保持 60s） |
| `__navCaches`（进程内） | 站码映射 / 站点地理 | 合规（纯静态，60s） |
| `progress.ts` 几何缓存 | 线路 shape / 里程 | **需加版本段或压 TTL**——S3 匹配算法以里程为唯一标尺，旧几何会稳定锁错车 |
| `force-cache` × 6 处 | 站点清单 / 线路几何 / 路线总览锚点 | **3 处现存违规**（`route-shapes`×2、`route-lines`×1，URL 无版本号）；本期改为去掉浏览器强缓存、由服务端 `max-age` 单层管理 |

## 4. 明确不做（Out-of-Scope · 锁定）

| 不做的项 | 原因 | 何时再考虑 |
|----------|------|------------|
| Service Worker 离线壳 | 负责人选择「只修现有问题」；引入后每次发版都要处理旧壳替换 | 若真机验证发现「断网刷新白屏」是高频痛点 |
| 渐进式估算结果（先估算后替换） | 负责人要求「一次给对」，不接受数字跳变 | 不再考虑 |
| 低置信时的「核对入口」/ 候选列表 | 负责人明确先不给入口；澳门隧道少，靠算法解决 | 若真机实测出现「锁错车且无法自救」再评估 |
| Vercel 升级 Pro | Hobby 可改单区域，无需付费 | 若需要多区域部署 |
| 上调 `transit_cache` TTL | 会让路线方案本身变旧（R4） | 不做 |
| 多策略补查改流式返回（先 3 张后 5 张） | 会让列表跳变，违背「一次给对」 | 埋点上线后再评估 |

## 5. 技术约束（锁定）

| 项 | 值 | 依据 |
|----|----|------|
| 函数执行区域 | `hkg1`（`vercel.json: "regions"`） | 官方文档 Hobby = 单区域但可改；`X-Vercel-Id: hkg1::iad1::` 实测跨洋 |
| 迁区前置验证 | 先在 Preview 部署跑 `.verify/perf/measure-gaps.mjs`，确认 Supabase pooler 不拒新来源 | ADR C1 |
| 静态数据 payload | **1.20MB（已合规，不拆包）**，`> 1.8MB` 触发预警 | 架构师实测：v3.6.1 数组编码压掉 68%；最大表占 76%，约 3.8 万行触顶 |
| 车辆 stale 阈值 | 30s（约束：> 2×POLL_MS 即 24s，且 ≤ 90s） | 测试 AC 阈值约束 |
| 定位看门狗阈值 | 20s 无回调即重订阅 | 架构师 D 系列缺陷 |
| 匹配算法候选集 | 该线路该方向**全部在途车**（不是上车站到站车） | 需求 3 根因 |
| 环线防护 | 复用 `monotonicCut` 单调游标，禁止跨圈重复计数 | 111 方向中 55 个为环线（49.5%） |
| 速度门 | 不得用于区分「冲刺赶车」与「乘车」：档 1 = 12.96 km/h 落在 R2 速度带 (8,80] 内 | 架构师实测 |
| 观测钩子 | `body[data-geo]` / `body[data-veh]` / `body[data-veh-age]` / `body[data-user-fix]="ts,acc"`（不写经纬度）/ `data-result-stage` / `data-card-pending` / `data-board-match` | 测试 §3.4 + 产品附 A；**禁止合成 `data-net`** |
| 硬性语义 | 定位不可用 ≠ 导航不可用：单轴失效不得整页降级，站序/剩余时间/下车提醒照常 | 测试 AC2.7 |

## 8. 验收标准（锁定 · 以测试文档为准 + 本期新增）

以 `03-测试-基线测量与场景复现.md` 的 **24 条 EARS** 为基础，另加本期四条：

| 编号 | 验收标准 |
|------|----------|
| AC5.1 | While 同一 OD 间隔 ≥2 分钟从**收藏页**发起导航，系统**必须**重新计算实时段（`stats.liveMs > 0`），且返回的车辆时刻不早于本次进入时刻 |
| AC5.2 | While 任何静态缓存命中，响应中**不得**出现车辆位置、到站剩余秒数、等待时长三类字段（RL1 机验） |
| AC5.3 | When 访问 `/api/health?warm=1`，`cache.staticRows.status` **必须**为 `ok`，且 `sizeBytes` 落在 `[0.8MB, 2MB)`（下界防「读到 0 也当通过」；多实例下必须同请求内 `await loadStatics()` 才能读到真实值） |
| AC5.4 | When 从首页/收藏/深链三条入口分别发起同一 OD，三者的 `stats.transitFromCache` 与车辆帧时间戳**必须**各自独立，不得互相复用 |
| AC5.5 | If 客户端传入 `issuedAt` 且缓存条目写入时刻早于它，服务端**必须**视为未命中并重新请求上游（RL3） |
| AC5.6 | When 同一 OD 在 5 秒内重复触发，系统**必须**不重复请求；超过 5 秒**必须**重新请求（RL —— 修 `useRecommend` 无时效跳过） |
| AC5.7 | When 线路几何发生变更（shape 行数/更新时间变化），`progress.ts` 的里程缓存键**必须**随之变化，不得继续返回旧几何（S3 正确性前置） |

## 9. 端到端验证步骤

```bash
# 1) 类型与静态检查
npx tsc --noEmit
npm run lint

# 2) 构建（本地 PowerShell 通道，勿用 Bash 沙箱）
CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=999999 npm run build

# 3) 基线对比（对 Preview 域名，勿并发打生产）
PERF_BASE=https://<preview-host> node .verify/perf/measure-nav.mjs
# 断言：热态 P50 ≤ 2000ms；冷态 P50 ≤ 5000ms；outsideMs ≤ 120ms（迁区生效）

# 4) 缓存红线
node .verify/perf/check-cache-redlines.mjs
# 断言：R1~R5 全部 pass

# 5) 稳定性场景（自动化部分）
node .verify/perf/scenarios-nav.mjs
# 断言：切后台 2min 回前台后 2s 内发出一次车辆请求；断网时 data-veh=stale 且蓝点不消失

# 6) 匹配算法单测
npx tsx .verify/test-match-vehicle.ts
# 断言：环线不跨圈、平行线路不误锁、冲刺场景不误判乘车
```

## 10. 风险与回滚

| 风险 | 触发条件 | 回滚动作 |
|------|----------|----------|
| 迁 hkg1 后 Supabase pooler 拒连 | 全站 5xx | `vercel.json` 删 `regions` 重新部署（配置级回滚，秒级） |
| 静态拆包后数据不一致 | 站序错乱 / 换乘缺失 | 保留旧 `getStaticRows` 键，回退到单条读取 |
| 匹配算法误锁 | 真机出现「锁错车」 | `AUTO_BOARDING_ENABLED` 已有总开关；新增 `MATCH_VEHICLE_ENABLED` 独立开关，默认关，真机验证后开 |
| detail-body 改按需后折叠栏空白 | 前端未同步 | 服务端保留 `fold` 缺省返回空数组，前端降级为不显示折叠栏 |
