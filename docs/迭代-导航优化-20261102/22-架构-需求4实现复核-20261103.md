## 2. 偏差（需裁定，非阻断）

### D1 · 第 2 条「站序一致性」用的不是 V4 那套算法

| | 规格（19 号 §4.2 `pickPair`） | 实现（`pickTripPair`） |
|---|---|---|
| 判据来源 | `mids`：**中间站坐标**（`useRouteOverview` 从 `strips[i].stops` 映射传入） | `stations`：**全线站码链**（`/api/route-shapes` 下发） |
| 判定方式 | `violations` = 中间站最近投影**不落在弧内**的次数，**取违反数最小** | `expected = avgHopM × seqDiff`，**要求弧长落在 `[0.4, 2.5] × expected`** |
| 数据结构 | `OverviewLegInput.stops?: {code,lng,lat}[]`（**未实现，该字段不存在**） | 新增 `RouteStopSeq`（已在 API 侧落地） |

方向是对的（**确实用的是站码链 `s.code` + `seq`，不是几何距离** —— 这条你没踩坑），但**这是两套不同算法**。后果：

- V4 的实测成绩（修正 987 / 持平 8532 / 过短 0 / 过长 0）**是 `mids + violations` 那套测出来的，不能直接外推到这个实现**；
- 我这边的 93 段抽样是「变短 87 / 持平 6 / 变长 0」——**方向一致、无恶化迹象**，但样本量与 OD 构造方式都远不及 V4 的 9531 条，不足以下"等价"的结论。

**需要实现方裁定二选一**：
1. **改回规格**（补 `mids`/`violations`）——等于重写 `pickTripPair`，但能直接吃 V4 的对拍成绩；
2. **保留现实现 + 重跑 9531 对拍**，用同一套样本重新出「修正/持平/过短/过长」四个数，达标（过短 0 / 过长 0）即可结案。

我倾向 **2**（现实现的判据更简单、少一次 `/api/stations` 依赖、少一个入参字段），但**必须用同一批样本重新对拍**才能声称"未退化"。

### D2 · `forward` tiebreak 的输入被换（低风险）

`route-overview.ts:435`：

```ts
- const forward = nb.idx <= na.idx;        // 原
+ const forward = pair.iBoard <= pair.iAlight;   // 现
```

这行的作用只是**并列时的加分项**（`|score - bestScore| <= 1e-6` 才生效），不改 `score` 本身 —— 所以「外层按 `dBoard+dAlight` 选向」这条**守住了**。但严格说"外层一字未改"不成立：`leg.dir` 在并列情形下可能因 `repicked` 而翻转，而 `leg.dir` 会拼进 `/api/route-vehicles?dir=`（`useRideTracking:706`）。

- 缺 `stations` 时：`pair.iBoard === nb.idx` ⇒ **完全等价，零风险**；
- `stations` 接通后：仅在 `|Δscore| < 1e-6` 的并列时可能翻转，概率极低。
- 建议：改回 `nb.idx <= na.idx`，让"外层一字未改"这句话**字面也成立**（一行改动，零收益但消除歧义）。

## 5. 补充核查（后端提醒「两套投影逻辑并存」后追加，2026-11-03）

### 5.2 但不能拿它当渲染锚点：与当前 shape/站点坐标存在最大 ~97m 失配

`.verify/_q4-mileage3.mts`（mileage → 最近顶点 → 量该顶点到站点坐标的距离）：


C653 在 mileage 上落到 i=537，而几何最近顶点是 i=539（距 25.9m）—— 两者差 2 个顶点、约 80m 里程。说明 **mileage 表与当前 `route_shapes` 或 `stations` 坐标不同版本**（表有 `updated_at`，但显然与 shape 重抓不同步）。

⇒ **结论：`route_station_mileage` 可用于「车辆位置投影 / 行程进度」（`progress.ts` 的用途，容差宽松），不可用于「彩段锚点」（渲染，容差像素级）。** 我要把它从需求 4 的候选方案里排除，避免实现方被"表里已有数据"误导去改。

### 7.0 方法论（本轮实证，建议团队级留存）

| # | 谁 | 犯的错 | 形态 |
|---|---|---|---|
| 1 | 架构（本报告作者） | 17 号第一版断言「既有对拍脚本能保护 `buildStrips`」—— 没核 `scripts/` 与 `.verify/` 的实际覆盖范围 | 范围划错 |
