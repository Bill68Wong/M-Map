# 产品验收标准 · 开屏播放条件与边界（2026-11-02 · v2 定稿）

> 角色：产品经理 · 本文替代原「06-产品-开屏触发机制-验收标准.md」（版本门方案全部作废，旧文件名不再使用）。
> 依据：负责人裁决（2026-11-02）——**每次进入应用都播**；视觉与实现细节见 05-设计-开屏与加载动画-规格.md；观测钩子见 02 附录 A5。
> 一句话：**开屏是"覆盖在正在加载的地图之上的一次性过场"，不是一个需要被调度的品牌仪式。**

---

## 0. 决策变更记录（为什么推翻版本门）

负责人原话：「每次进入应用都有开屏动画，怎么又改回来了，让专家团改回去」。他最初的需求原文是「趁着首页地图还在加载的时候就利用开屏动画优化用户体验」——**目的是优化等待，不是品牌仪式**。

前一版把它做成"首装 + 大版本更新播一次"，是评审方（含本文作者）用"高频工具会腻"的判断覆盖了原始需求。判断本身没错（数据仍在：一天 4 次 × 1.5 秒 ≈ 每月 3 分钟），但**它服务的是另一个目标**。以负责人裁决为准，版本门、cookie 记账、major 判定全部作废。

代价与止损：既然每次都播，动画就**不能有任何附加等待**，且必须在 1 秒内让位给内容——这两条从"建议"升为硬验收（见 P5、P6）。

## 1. 播放条件（唯一规则 + 一条补充）

| 场景 | 播不播 | 说明 |
|---|---|---|
| 新标签打开页面 | 播 | 含从外部链接、收藏、分享链接进入 |
| **深链到内页（`/favorites`、`/help`、`/line/<code>`、`/card`）** | **播** | 见下方「深链为什么也播」——这是挂根 layout 的必然结果，已接受 |
| 刷新（含下拉刷新、硬刷新） | 播 | 连续快速刷新也每次都播（不做防抖，不做冷却） |
| 已安装 PWA 冷启动 | 播 | 与 Android 系统开屏衔接（见 §3） |
| 关闭标签后重新打开 | 播 | 与"新标签"同 |
| **暖启动：bfcache 还原（前进/后退）** | **不播** | 页面未重载，浏览器还原快照 |
| **暖启动：切到其他 App / 其他标签再切回** | **不播** | 同一会话，页面未重载 |
| **应用内客户端路由（底导切页 `/favorites` `/help` 互跳、从收藏点组合回首页 `/`）** | **不播** | 用户没有离开应用，页面未重载（见下方裁定） |

**「深链到内页为什么也播」（2026-11-02 终裁，代价诚实记入）**：

挂载点定在根 `layout.tsx` ⇒ **任何整页加载都会渲染 layout ⇒ 必然播**。深链到 `/help`、`/line/MT1` 这类无地图页时，动画其实**没有等待可遮**，播 960ms 属于纯拖延——这与本文件驳回"客户端路由播"的理由（"没有遮丑价值，只有拖延价值"）**在逻辑上是同一条**。

仍然接受，理由有两条，都不是"技术上做不到"，而是权衡：

1. **备选方案（按路由条件渲染 / 白名单）的代价更大**：它要求开屏组件知道"当前路由是否有地图"，这是一份会随路由新增而腐化的清单；且它把"开屏在哪出现"变回不可预测——正是本轮反复推翻的那类规则。**简单规则优于聪明规则。**
2. **深链进入无地图页是低频路径**（个人项目，主入口是首页；深链主要来自分享，而分享出去的多是路线结果页），且动画可点击跳过。**每天 4~6 次的主路径（首页冷启动）才是体验主战场**，那里动画有真实等待可遮。

**同时记录代价**：`/help`、`/about` 整页加载也会多看约 1 秒。**不加路由白名单**——加白名单等于把门加回来，且让"哪些页有开屏"不可预测。若将来深链占比显著上升，再议（届时优先做"缩短动画"，不是加白名单）。

**「应用内客户端路由不播」的裁定（2026-11-02 补，解决 06 内部口径冲突）**：

「每次进入应用」= **从外部进入**（冷启动、刷新、深链、重新打开标签），**不含应用内部的页面切换**。三条理由：

1. **没有遮丑价值，只有拖延价值**。内页切换时首屏数据通常已在内存或缓存里，地图往往秒开——此时播 960ms 动画是纯粹推迟用户到达目标页，与"优化等待"的初衷相反。
2. **这才是真正会腻的场景**。用户在一次使用中可能来回切底导 4~6 次（查收藏 → 回首页 → 再查），频率远高于冷启动。冷启动播动画是"仪式感"，内页切换播动画是"每次点底导都被拦住"。
3. **它与 §1 的表述本来一致**：客户端路由不产生页面加载，所以"每次页面加载都播"自然推出"客户端路由不播"。此前的冲突来自把挂载位置（`page.tsx`）当成了规则。

**衍生边界（重要，与加载态分工）**：从收藏点一个组合「回放」回首页时，会触发真实的路线规划请求——这时需要遮的是**请求等待**，由**加载态**（小尺寸循环 + 分步文案）承担，**不是开屏动画**。两者职责不重叠：**开屏遮应用启动，加载态遮请求等待。**

**实现手段（2026-11-02 二次修正：**挂根 layout，物理删除已播标记**）**：

第一版说"禁止用标记"，错（媒介生命周期才是判据）；第二版说"用模块级内存标记"，方向对但**不够**——标记只解决了"同一 document 内不重复"，没解决"哪些路由根本播不到"。核对代码后确认的真缺陷：

> `BrandSplash` 当时只挂在 `src/app/page.tsx` ⇒ **从外链/分享链接打开 `/favorites`、`/line/xxx`、`/help` 整页加载时不播**，直接违反 §1「新标签打开页面（含外部链接、分享链接）⇒ 播」。

因此实现改为：**挂根 `layout.tsx` + 物理删除 `sessionPlayed` 标记**。

- **为什么挂 layout 就能满足"客户端路由不播"**：Next.js App Router 的 layout 在客户端路由切换时**不重新挂载**，组件实例与 state 保持 ⇒ 只有整页加载才渲染一次、播一次。这是比"标记压制"更强的手段——**它从结构上就不存在第二次挂载**。
- **为什么删标记**：标记是为"page 级挂载 + 客户端路由重挂"准备的补丁，挂 layout 后不再需要；且该标记是 `next dev` 下开屏层永不移除、吞掉全站点击的根因（StrictMode 双调用时，第二遍 effect 走 `if (sessionPlayed) return` 提前返回，跳过了监听与兜底重建，第一遍的覆盖层留在 DOM）。物理删除是根治。
- **副产品**：删标记后代码里**不留任何可用的已播钩子**，将来想加回去必须新写一段代码（而非改一个布尔值）——这正是 P10 防回潮想要的效果。

**代价（必须记入，不加白名单）**：挂 layout 后，`/help`、`/about` 这类无地图页深链进入**也会播 960ms**（详见上方「深链为什么也播」）。

**仍然禁止的媒介**（防回潮）：cookie / localStorage / sessionStorage。三者会跨加载/跨会话留存，构成真正的频次控制，撞 P10。

**为什么暖启动不播（评审判断，已采纳）**：这不是产品克制，是三条同向的理由——① 页面没有重载，动画层早已从 DOM 移除，重播必须人为重挂节点并强制重启动画，属于"为了播而播"；② 用户切回时注意力在"接着看刚才的内容"，重播会打断恢复位置（Apple 明确要求恢复上次状态）；③ 平台自身同构：Android 热启动从不显示系统开屏。因此"每次进入应用"在实现语义上等于**每次页面加载**，两者不矛盾。

**明确的取舍**：每次加载都播 ⇒ 用户在一次通勤里反复打开可能反复看到。接受，不做频次控制；止损方式是"短 + 可跳过 + 不阻塞"，而不是"少播"。

## 2. 验收标准（产品级，可直接转 EARS 机验）

> 前置：本组用例**不需要任何 cookie / localStorage 预置**（无版本门）。断言只依赖 `body[data-splash-state]` 与 `[data-splash-root]`。

> **两条断言写法原则（2026-11-02 定，来自本轮实战）**
> 1. **断行为，不断状态值。** P1c 从「断 `blocked`」改为「断 `playing` 全程出现次数 === 1」就是范例：`blocked` 只能证明"到了但没播"，出现次数直接证明"没再播"。状态值会随实现方案变化（本文件枚举从 4→5→4 翻了三轮），**行为不会**。
> 2. **只写「断言判据所需」的数值，不抄「仅供说明」的数值。**（2026-11-02 修正：原稿写成"零实现数值"，过于绝对，与本文实做矛盾——P4/P4a 必须给出 `≤200ms`、`0–100ms`、钉 `600ms` delay 这类值，否则断言写不出来、缺陷也定位不了。）
>    · **必须写**：断言要比较的阈值（`≤200ms`、`≤120ms`）、采样窗口（`0–100ms`）、缺陷定位所需的最小坐标/时长（钉 delay `600ms`、光点起点 `(12,48)`）。
>    · **不要写**：完整时刻表、各段 delay/duration 的枚举、脉冲相位这类**会随视觉迭代变**且断言不依赖其逐项比较的细节——要核请引用 05 规格 §4。
>    · **判据（一步可验）**：**"删掉这个数值，断言还能不能写出来？"** 能写 ⇒ 属"仅供说明"，删；不能写 ⇒ 属"判据所需"，留。
>    · 反面实证：本轮发生过 `416ms→310ms` 的数值更正，架构师 08 抄了完整时刻表，需改四处；本文因未抄时刻表，零返工。

| # | Given / When / Then | 断言手段 |
|---|---|---|
| P1 | When 页面加载（新标签 / 刷新 / 深链 / PWA 冷启动任一）→ Then 动画播放，`data-splash-state` 经 `playing` 到终态 `done`（或用户跳过为 `skipped`） | 钩子 + 各加载方式各跑一次 |
| P1b | When 连续刷新 3 次 → Then **每次都播**（3 次均出现 `playing`），无冷却、无防抖 | 钩子 + 连续 reload |
| P1c | When 应用内客户端路由（`/favorites` → 底导回 `/`、`/help` ↔ `/`、从收藏点组合回放回 `/`）→ Then **`[data-splash-root]` 不出现**，且 **`playing` 全程只出现一次**（不新增 `playing` 写入）。**不断某个特定终值**——挂 layout 后组件不重挂，宿主实例的 `state` 保持整页加载时的终态（`done`/`skipped`）；断"写入次数"比断"值叫什么"更稳，也不会因将来改终值而误红 | MutationObserver 记录 `state` 写入序列 + 容器存在性 + 两条路由各跑一次 |
| P1d | **回归守卫（不是待修功能）**。When 从外链/分享链接/直接输入 URL 打开非首页路由（`/favorites`、`/help`、`/line/<code>`）→ Then **同样播放**（`playing` 出现）。**当前应绿**（挂载点已在 `layout.tsx`，任何整页加载都渲染 layout）。它红只有一种可能：**有人把挂载点挪回 `page.tsx`**——那时深链内页会完全不播，而这是本方案唯一的结构性特征，必须被钉住。**为什么这条"现在绿"仍必须留**：回退到 page 方案的代价不是"恢复 1 行标记"，而是**必须有 3 条纪律同时成立**（置位时机只能在 `markDone`/`skip`、early-return 判据必须用 DOM 事实而非标记、cleanup 必须可重入），漏任一条就静默复发 dev StrictMode 遮挡缺陷。P1d 钉的是这笔**持续正确性负担**，不是代码行数 | 钩子 + 三条路由各整页加载一次 |
| P2 | When 暖启动（bfcache 还原 / 后台切回同一会话）→ Then **`[data-splash-root]` 不出现、动画不重播**；首屏内容与滚动位置保持原状 | MutationObserver + 钩子 + 前进/后退与切后台两条路径 |
| P3 | When 播放中点击任意处 → Then ≤120ms 淡出并**移除**容器，`data-splash-state === "skipped"` 且 `querySelector('[data-splash-root]') === null`，首屏立即可交互。计时基准 = click 事件时间戳，终点 = MutationObserver 记录的容器移除时间；断言 ≤120ms，**失败时输出实际毫秒数** | 双条件断言（A5 规则）+ 计时证据 |
| P4 | When `prefers-reduced-motion` 开启（`page.emulateMedia({ reducedMotion: "reduce" })`）→ Then 直接渲染静止末帧、无位移动画，`data-splash-state === "reduced"`，容器**约 100ms 内移除**（`globals.css:8749` 的 reduced 块把 overlay exit 改为 `100ms linear`、`delay 0ms`；正常态是 860ms）。**断言写「≤200ms 已移除」，不要锁 860ms**——锁 860ms 会红，且那个改动本身是好的（无障碍用户少等 760ms）。另须断「末帧完整性」（见 P4a） | 钩子 + 模拟媒体特性 + 移除时刻 ≤200ms |
| **P4a** | When `prefers-reduced-motion` 开启 → Then **末帧是完整 logo**：钉已到位（`transform` 含 `matrix(1,...)` 而非 `matrix(0,...)`）、路线描边已走完（`stroke-dashoffset ≈ 0`）、涟漪与亮点 `opacity ≈ 0`、**光点 `opacity ≈ 0`**（`animation: none` 会让光点停在路径起点 (12,48) 可见，实现专门用 `opacity: 0 !important` 兜住）。**采样窗口 = 0–100ms（容器约 100ms 即移除）**；在 700ms 采样会取不到元素而假红。**背景**：全局 reduced-motion 杀开关（`globals.css:541`）只清 `animation-duration`、**不清 `animation-delay`** ⇒ 若不修，开屏钉的 600ms delay 会让 reduced 用户先看到**缺钉子的 logo**，600ms 后钉子凭空弹出。修复已落地（`globals.css:8749` 整段禁用 mark 内动画 + 三元素 `opacity: 0 !important`） | 计算样式断言（`transform` / `stroke-dashoffset` / `opacity` 终值）在容器移除前采样 |
| P5 | 全程：**动画不得推迟首屏内容渲染**。动画层存在期间，首屏（地图容器 + 底部面板结构）必须已在 DOM 中渲染完毕；禁止"等动画播完才挂载首屏" | 钩子 + DOM 时序（容器存在时首屏节点已存在） |
| P6 | When 动画结束或跳过（`done` / `skipped`）→ Then ≤100ms 内首屏可交互（点击命中测试通过），且**动画层不得残留** | 钩子 + 命中测试 + 容器移除断言 |
| P7 | **适用范围：仅落到首页 `/`（有地图容器）**。When 首屏内容就绪时间 > 动画时长（慢网）→ Then 动画结束后该位置**有可感知的加载反馈，不得空白/静止**，且**只有一种主导视觉**。当前证据 = `[data-loader-root]`（48px 小 M 循环，`.nav-map__cover` 内）+ 文案「地图加载中…」；骨架块已移除，不会两套并存。**地图仍可操作**。**注意**：`.nav-map__cover` 从 `phase === "loading"` 即存在，开屏淡出只是把它暴露出来——**从无空窗**（§4）。深链进 `/help`、`/about`、`/favorites`、`/card` 无地图容器、无 cover 可暴露，**本条不适用** | 慢网模拟 + `[data-loader-root]` + `[data-loader-slot="map-cover"]` + 文案（限首页） |
| P7a | **适用范围：仅落到首页 `/`**（淡出期下方需有 loading 层才谈得上双影）。When 开屏淡出（860–960ms）→ Then **不得出现可辨识的双影**（可截图核验：880ms / 920ms 两帧）。**不断"位置同心"**——加载态在地图容器内居中（§4.1），与屏幕中心不同心是设计意图 | 双帧截图比对（限首页） |
| P8 | 全程：`data-splash-state` 取值为 **4 值之一**：`playing / skipped / done / reduced`，优先级链 `skipped > done > reduced > playing`（仅约束同一挂载实例内的终态竞争）。**不含 `blocked`**：挂载点在根 `layout.tsx` ⇒ 客户端路由不重挂、bfcache 还原时容器已移除（组件 `gone` 状态随快照恢复，不重播）⇒ **没有任何场景需要写"已播但未播"这个值**。留一个永不出现的值，等于给 QA 一条永远绿的假断言 | A5 互斥规则 |
| P9 | 全程：动画层存在时全页唯一实例（`querySelectorAll('[data-splash-root]').length <= 1`）。**历史提示**：曾出现 `layout.tsx:88` 与 `page.tsx:80` 双份挂载 ⇒ SSR 输出 2 个容器 ⇒ 本条必然红；已删除 `page.tsx` 那份，当前全仓仅 `layout.tsx:88` 一处。本条现在的作用就是**防止再出现双挂载** | DOM 计数 |
| P10 | **负向断言（防回潮）**：页面加载完成后，**cookie / localStorage / sessionStorage 三者**均不得新增任何"开屏 / splash"相关键；加载前后三者快照应无可归因于开屏的变化。**sessionStorage 是重点**——它只在同一 tab 内跨刷新保留，正是"看起来像内存标记、实际会拦掉第二次刷新"的隐蔽媒介 | `context.cookies()` + localStorage / sessionStorage 快照 diff |

## 3. 边界与不做的事

- **不做版本门**：不写 cookie、不写 localStorage、不写 sessionStorage、不做 major/minor 判定、不做"是否再看一次"开关。P10 就是这条的守门断言。
- **不做频次控制**：不加冷却、不加"本次会话已播"标记、不因连续刷新而跳过。实现上靠**挂载位置**（根 layout 在客户端路由不重挂）从结构上保证"一次加载只播一次"，不靠任何标记压制。
  · 澄清（2026-11-02 三次修订）：本条禁止的是**任何形式的已播标记**——无论内存变量、sessionStorage、cookie、localStorage。挂 layout 后连内存标记都不需要（组件根本不会重挂），因此代码里不留任何已播钩子（P10 防回潮）。
- **不加可见的跳过按钮**：跳过 = 点击任意处；动画不承载任何必须读完的信息（这也是 05 的硬约束）。
- **不做静态启动图与动画的版本联动**：静态启动图（Android manifest / iOS `apple-touch-startup-image`）始终提供，与本文无关。Android 系统开屏在前、本动画在后，用户可能连看两段品牌画面——接受（系统开屏是图标 + 纯色，与动画首帧同源，视觉上是同一件事的延续，见 05 首帧对齐要求）。
- **不允许用动画换首屏速度**：任何为播放动画而增加的阻塞脚本、额外资源加载都不允许（P5/P6 守门）。

## 4. 与加载态的分工（更正：不存在"空窗"，是两层天然叠合）

**先更正一个曾写错的判断**（2026-11-02）：本文件早先写"动画播完到内容出现之间有空白，需要加载态接住"——**这个前提是错的，从没有过空窗**。

核实：`NavShell.tsx:42` **静态导入** `NavMap`（非懒加载）；`NavMap.tsx:1622` 在 `phase === "loading"` 时即渲染 `.nav-map__cover`（`position: absolute; inset: 0` + **不透明** `background: var(--surface-dim)` + 骨架 + 「地图加载中…」）。开屏是 `position: fixed; z-index: 200` 盖在其上 ⇒ **开屏淡出即暴露下面那层，天然衔接**。

⇒ 因此 `BrandRouteLoader`（小 M 循环）的定位是**视觉升级**（骨架块 → 品牌 M），**不是补漏**。P7 保留不变（它验的是"不得空白"这个产品意图），但**理由按本条更正**——否则后人会误以为原本有空白缺陷、甚至去"修"一个不存在的空窗。

**仍然成立的产品要求**：

- **不得让用户看到空白或静止无反馈**（P7）。当前由 `.nav-map__cover` 满足，接入小 M 后由它继续满足。
- **两个 loading 表达不能打架**：`.nav-map__cover`（骨架 + 文案）与 `BrandRouteLoader`（小 M + 分步文案）**同一时刻只应有一种主导视觉**，不得并排出现两套骨架/两套文案。是"替换"还是"骨架淡出、小 M 淡入"，属设计决策，但**结果必须是一个**。
- 短加载（<300ms 就绪）时用户看不到明显 loading 态（与 04 §4.3 一致）；**这不靠"隐藏"，靠"够快"**——`phase` 就绪即移除，无需额外门控。
- `active` 必须绑真实 `phase`，不得绑开屏结束（见 §4.1 第 2 条）。

**适用范围（2026-11-02 补，挂载点改为 layout 后的连带影响）**：本节全部要求（含 P7 / P7a）**只在落到首页 `/` 时成立**——只有首页有地图容器与 `.nav-map__cover`。深链直接进入 `/help`、`/about`、`/favorites`、`/card`、`/line/<code>` 时，这些页面没有地图容器、没有 loading 层可暴露；开屏播完直接呈现页面内容，**不存在"末帧→加载态"交接场景，因此不适用本节要求**（也不构成缺陷）。

⇒ QA 注意：**不要用深链进内页去核 P7/P7a**，那里必然找不到加载态，会误判为失败。核 P7 必须从首页进入。

### 4.1 两个实现前提（不满足则 P7 守不住）

1. **加载态图标在地图容器内居中，不要挪到屏幕中心**（2026-11-02 修正，原稿写反了）。
   · 现状已正确：`.nav-map__cover` 是 `position: absolute; inset: 0` + flex 居中，相对 `.nav-map` 容器居中。
   · **语义理由（决定性）**：加载态表达的是「**这一块区域**在加载」。挪到屏幕中心会被读作「整个 App 在加载」——那是另一句话，且是错的话。
   · 因此**不存在"两只 M 必须同心对齐"的要求**，也不需要任何交叉淡化对齐方案。开屏（`position: fixed; z-index: 200`）淡出时，底下 `.nav-map__cover` 已在渲染（`phase` 初值即 `loading`，无门控、无需等待），淡出即暴露，天然衔接。
   · **可核要求（唯一保留的几何项）**：860–960ms 淡出期间**不得出现可辨识的双影**。这是可截图核验的；"位置同心"**不是**验收项。
   · **残留观察（诚实留痕，非约束）**：开屏 overlay 不透明，淡出期大 M（屏幕中心）与容器内 loading 态（容器中心，比屏幕中心高约 45px）会同时部分可见约 100ms。判断为不成问题——那是透明度溶解而非位移，且下方图形静止、无可跟踪的移动线索。若第二轮回看截 880ms / 920ms 两帧发现双影明显，修法是**压缩重叠窗口**（淡出 100ms→60ms 或起始提前到 840ms），**不是挪位置**。
2. **`active` 必须绑真实就绪信号，不得绑开屏结束**：`active = (phase === "loading")`（用 `NavMap.tsx:385` 已有的 `phase`），**不得**写成 `active = splashGone`。
   · 为什么后者错：它会造出**真正的**空窗——开屏撤走后才开始计时/开播，那段才是空白。绑真实信号则：地图 200ms 就绪 ⇒ 用户从未看到小 M（不闪）；地图 3s 就绪 ⇒ 小 M 早就在转，开屏撤走时已在转 ⇒ 无缝。
   · **注意现状差异**：`.nav-map__cover` 现在装的是骨架块（`rc-sk--big`）+ 文案「地图加载中…」，**不是** `BrandRouteLoader`。小 M 尚未接入。P7 的实现选择（替换骨架 / 骨架淡出+小 M 淡入 / 并存）属实现决策，但**产品要求不变**：该位置必须有可感知的加载反馈、绑真实 `phase`、且**同一时刻只有一种主导视觉**（见 §4）。

### 4.2 一个会让缺陷"隐身"的实现变化（必读）

开屏退出末帧已加 `pointer-events: none`。副作用：**遮挡型缺陷从"点不动"变成"完全无感"**——用户点不到下面的内容，但没有任何报错、没有视觉异常。

⇒ 因此 **QA 的 `guardNoResidualOverlay()`（每例 setup 后断言 `[data-splash-root] === null`）从"可选的卫生检查"升为不可省项**。它现在是唯一能抓住"覆盖层残留"的手段，P6/P9 依赖它成立。

**三种失效模式需要三道守卫，缺一漏一种**（2026-11-02 补，来自设计与实现的实测）：

| 守卫 | 测什么 | 失效模式 |
|---|---|---|
| `guardNoResidualOverlay()` | 容器**真移除**（`[data-splash-root] === null`） | 容器留在 DOM |
| `elementFromPoint` 穿透 | 容器在但**点得到下面** | 容器在且吞点击但视觉不可见 |
| `[data-splash-root].length === 1` | **双份挂载** | 曾同挂 `layout` + `page` ⇒ 两个 `fixed inset:0 z-200` 完全重叠，**肉眼绝对看不出**，第二份 `opacity` 钉 0 却吞点击 |

第三种的可怕之处：它既不是第一道能抓的（查 null，两份都在时语义不同），也可能被第二道漏掉。**P9 现在的作用就是这道守卫**（见 P9 的历史留痕）。
