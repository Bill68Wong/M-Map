### 开屏与加载动画

- `BrandSplash`：沿 logo 的 M 路线光点行进（300ms）→ 钻入钉帽孔 → 地图钉以钉尖为支点生长 + 落地弹跳 + 涟漪 → 整层淡出。总长 **960ms**。
- `BrandRouteLoader`：48px 循环版，真实加载 > 300ms 才出现，光点匀速沿 M 循环。
- **挂载在根 `layout.tsx`**：任何整页加载（冷启动 / 刷新 / 深链 / 分享链接 / 重开标签）都播一次。
- **客户端路由不播**：靠根布局在客户端导航中不重挂实现（结构性），**不设任何已播标记**。
- 观测钩子：`body[data-splash-state]` ∈ `playing / skipped / done / reduced`；`body[data-app-version]`。
- 技术：纯 CSS（`stroke-dashoffset` + `offset-path: path()`），无 Lottie、无 JS 运行时、零新增网络请求，体积 < 6KB。
- 无障碍：`prefers-reduced-motion` 下首帧即完整 logo（约 100ms 交接）；加载态文案进入 `aria-live` 区域。

## 二、本轮走查发现并修复的缺陷

| 编号 | 缺陷 | 性质 |
|---|---|---|
| D1 | `reduced-motion` 下地图钉消失 600ms 后凭空出现 | 全局杀开关只压 `animation-duration`、不清 `animation-delay`；`fill: both` 的 backwards 分支把钉钉在 `scale(0)` |
| D2 | 钉帽孔内亮点从 0ms 起常亮 17px 蓝盘 | 关键帧缺 `0% { opacity: 0 }`，`both` 取自然值 1 |
| D3 | 涟漪从 0ms 起挂 12px 亮环 | `from { opacity: .45 }` |
| D4 | 循环版光点完全不沿路线行进 | `offset-path` 只写在叙事版选择器上，未提到公共类 |
| D5 | 折点脉冲晚 106ms | 把「路程比」当线性时间比，`--ease-travel` 实为 ease-in-out（实际 370ms，非 416ms） |
| — | 开屏淡出期（860–960ms）仍拦截点击 | 补 `pointer-events: none` 作 fail-open 兜底 |

另有开发期缺陷一并消除：`sessionPlayed` 模块标记在 React StrictMode 双挂载下会导致覆盖层永不移除（dev 下整站不可点击）。改为挂根 layout 后该状态机被物理删除。

## 四、已知取舍（不隐藏）

1. **深链到无地图页（`/help`、`/about`）也会播 960ms** —— 「每次进入应用都播」的直接后果。备选方案（按路由白名单）会让「开屏在哪出现」变回不可预测，且清单会随路由新增而腐化，故不采用。可点击任意处跳过。
2. **`/favorites`、`/line/**` 深链同样播放** —— 同上。
3. **S3 匹配开关默认关闭** —— 判据参数（定位误差 60m、速度容差 6km/h、置信门槛）未经真车标定。开启前需跑影子运行校准。
4. **未真机验证项** —— 真机清单见 `08-交付说明-v3.7.0.md` §三（含 `X-Vercel-Id` 前缀 `hkg1`、`/api/health?warm=1` 的 `status==="ok"` 等只能在部署域名验的项）。

## 六、工程环境备忘（本轮新增）

`next build` **必须用 `npx next build`**。直接调用 `node node_modules/next/dist/bin/next build` 会导致 build worker 崩溃（`4294967295` / `.next/trace` EPERM），且报错位置每次不同，极易误判为文件系统拦截。

反过来，`next start` 建议用 `node node_modules/next/dist/bin/next start`（`npx next start` 的后台进程不持久）。
