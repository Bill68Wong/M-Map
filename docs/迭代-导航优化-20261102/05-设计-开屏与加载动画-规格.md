## 2. SVG 组件结构（从 BrandMark 派生，命名沿用 `.brand-mark__*` 模式）

复用 BrandMark 的内联 SVG 策略与 mask 结构，新增动画元素。**全部颜色走 CSS class，组件内零硬编码色值**（mask 的 #fff/#000 除外，与 BrandMark 同例）。

```
BrandSplash（或 BrandRouteLoader，小循环版同名组件不同 prop）
├─ <svg viewBox="1.15 0.85 60 60">
│   ├─ <defs> mask（复用 BrandMark 结构，id 用 useId() 生成）
│   ├─ g[mask]
│   │   ├─ path.brand-mark__route        ← 复用（动画目标：dashoffset）
│   │   └─ path.brand-mark__pin          ← 复用（动画目标：scale 弹跳）
│   ├─ circle.brand-mark__station        ×2 ← 复用站环（起 12,48 / 折 30,34）
│   ├─ circle.brand-anim__dot            ← 新增：光点，r=2.6，fill var(--brand-dot)
│   ├─ circle.brand-anim__hole-flash     ← 新增：钉帽孔内点亮，圆心(48,16) r=2.7
│   └─ circle.brand-anim__ripple         ← 新增：涟漪环，圆心(48,46) r=11 描边 2
└─ 观测：document.body.dataset.splashState（见 §7）
```

**新增 CSS class 与 Token（追加到 globals.css 品牌区段，不新增色值来源）：**

**光点与 mask 的层级定夺（v1.1，回应架构师）**：光点**不进 mask 组**，全程可见、压过站点镂空孔。理由：① 960ms 节奏下光点穿过 r=3.9 孔仅约 40–60ms，"消失再出现"读作闪烁而非"到站停靠"——做足"停靠感"需要 ≥100ms 停顿，时间预算不允许；② 连续不中断的行进才符合"走完全程直达终点"的叙事，到站语义已由折点站环脉冲（段 3）承担；③ 不与 mask id 耦合，实现更稳。光点钻入钉帽孔（段 4）是显式的 scale+opacity 动画，不依赖 mask 遮切。

```css
:root {
  --brand-dot: #ffffff;              /* 浅色：白（唯一例外色，等同 --accent-on 语义） */
}
@media (prefers-color-scheme: dark) {
  :root {
    --brand-dot: #1b4d8f;            /* 深色：复用亮色主题路线蓝的现成值——深底亮蓝路线上必须用深点才可见 */
  }
}
.brand-anim__dot        { fill: var(--brand-dot); }
.brand-anim__hole-flash { fill: var(--brand-route); }   /* 深色下即 #a8c7fa，顺带补偿深底钉绿 2.97:1 */
.brand-anim__ripple     { stroke: var(--brand-route); fill: none; }
```

深浅主题差异点（回答 team-lead 问题 6）：

- 路线/站环/钉自动随现有 `--brand-route/--brand-pin` 切换，无需额外处理。
- **光点必须换色**（上表 `--brand-dot`）：深色主题路线是亮蓝 #a8c7fa，白点在其上几乎不可见。
- **深底钉绿 2.97:1 的补偿**：不加新色，靠时序补偿——光点钻入瞬间钉帽孔内 `hole-flash` 以 `--brand-route`（深色下为亮蓝）点亮 120ms，深色主题里钉身获得一次高亮度"发光时刻"，随后弹跳定格。浅色主题该 flash 同样存在，无副作用。

## 3. 全屏叙事版分镜（总长 960ms，毫秒级）

统一缓动：

- `--ease-standard: cubic-bezier(0.2, 0, 0, 1)`（默认）
- 描边/光点共用 `--ease-travel: cubic-bezier(0.45, 0.05, 0.55, 0.95)`（对称 ease-in-out，保证两者进度锁定）
- **禁用** `cubic-bezier(0.68, -0.55, 0.265, 1.55)` 及一切 y 值出 [0,1] 区间的弹性 bezier——弹跳感全部用显式 scale 关键帧实现。

| #  | 时间        | 元素         | 动画                                                 | 缓动                              |
| -- | --------- | ---------- | -------------------------------------------------- | ------------------------------- |
| 0  | 0ms       | 整体首帧       | **站环 + 钉（含字标，若用 lockup）已就位，仅 M 描边为空**；背景与系统静态开屏同色 ⇒ 静态层→动画层切换时除 M 外像素级一致，唯一可见变化 = M 消失待重画（视为有意的开场动作） | —                               |
| 2  | 0–600ms   | 路线         | 生长：dashoffset 82.91→0                              | --ease-travel                   |
| 2' | 0–600ms   | 光点         | 行进：offset-distance 0%→100%（与段 2 同时长同缓动）；0–100ms 淡入 | --ease-travel                   |
| 3  | 310–430ms | 折点站环       | 脉冲：scale 1→1.15→1（**峰值 370ms = 光点过折点时刻**；光点走的是 ease-in-out，路程 69.28% 落在时间 61.6% 处，不是 416ms —— 见 v1.3 修正） | ease-standard                   |
| 4  | 580–660ms | 光点         | 钻孔：scale 1→0.35 + opacity 1→0（缩入 48,16 镂空孔）        | ease-in                         |
| 5  | 580–700ms | hole-flash | 点亮：opacity 0→0.9→0                                 | ease-out                        |
| 6  | 600–860ms | 钉          | 弹跳：scale 0→1（关键帧见 §4.3，transform-origin 48px 46px） | 分段 ease-standard                |
| 7  | 800–940ms | 涟漪         | 扩散：scale 0.18→1 + opacity 0.45→0（r=11 环，钉尖落定瞬间）    | ease-out                        |
| 8  | 860–960ms | 覆盖层        | 整层淡出 opacity 1→0 → 从 DOM 移除                        | ease-in cubic-bezier(0.4,0,1,1) |

> **v1.1 修订（架构师技术评估联动）**：原"起点站环充能"段（0–140ms）**删除**——首装场景下系统静态开屏已展示完整 logo（含站环），若动画层再把站环清空重画，用户会看到站环"闪没又出现"。站环改为首帧常驻，腾出的时间给了 M 描边（540ms→600ms），节奏反而更从容。

**交接红线（PM 第 1 条，实现缺陷级别）：**  
860–960ms 淡出期间首屏内容必须已在动画层之下渲染完成。顺序恒为：  
`内容就绪 → 覆盖层淡出 → 移除覆盖层`。  
任何"动画层先移除、内容后出现"的实现 = 缺陷（Apple 所述 unpleasant flash）。动画层是 `position: fixed` 覆盖层，背景为 bg token 非透明，淡出即露出下方已就绪内容。  
覆盖层容器固定携带 `data-splash-root` 属性随生灭（§7.1），跳过/播完移除容器时属性消失。

**播放条件与结束态：**

- 仅首装/大版本播放（判定归前端/架构，见 PM questions_for_user）。
- 加载先完成 → 动画走完立即进段 8；动画先完成 → 停在末帧静置等待（不循环不加戏）。
- 结束帧 = 完整静态 logo（M 路线 + 落定钉），与首屏导航栏 BrandMark 构图同源，交接无跳变。

**挂载与播放机制（架构决定，v1.2 补进）：**

- 覆盖层挂在**首页 `page.tsx`**，不挂根 layout（版本门读 cookie，挂根 layout 会把 favorites/help/line 全站拖进动态渲染）。
- 版本门 = cookie 方案，**SSR 直出动画版** ⇒ 动画从首帧就开始、零 hydration 依赖，逐帧完全由 CSS 驱动；客户端 JS 只做三件事：版本判定、播完/跳过后移除容器、写回 cookie。
- "静置等待"发生在覆盖层已由 SSR 渲染的前提下（§10 补丁 4）。

**层级红线（v1.2）：** 覆盖层 `z-index` 必须高于全站最高层（车辆层 z-index = 130，项目层级是显式数字纪律）⇒ 开屏覆盖层取 **z-index: 200**（留出插层空间），随容器移除而释放。

## 4. 关键帧草案（数值可直接抄进 @keyframes）

### 4.1 路线描边（段 2）

```css
.brand-anim--narrative .brand-mark__route {
  /* path 属性：pathLength="1"（见 §1），dasharray/offset 全部归一化 */
  stroke-dasharray: 1;
  /* fill-mode 红线：必须显式写 both（= forwards+backwards）。
     只写 forwards 的话，delay 期间元素露出自然样式（钉会提前可见）；
     完全省略的话，reduced-motion 全局杀开关（globals.css :541，0.01ms 瞬播完）
     会让动画跳回初始帧 ⇒ 用户看到空 M。见 §10 补丁 1。 */
  animation: brand-anim-route 600ms var(--ease-travel) 0ms both;
}
@keyframes brand-anim-route {
  from { stroke-dashoffset: 1; opacity: 0; }  /* opacity 同时消掉圆头 cap 在 offset=全长时残留的首点小圆 */
  1%   { opacity: 1; }
  to   { stroke-dashoffset: 0; opacity: 1; }
}
```

### 4.2 光点行进 + 钻孔（段 2' / 4）

```css
.brand-anim__dot {
  offset-path: path("M12 48 L12 16 L30 34 L48 16");  /* 与路线 path 逐字符一致 */
  offset-distance: 0%;
  offset-rotate: 0deg;                                /* 圆点无需旋转 */
  animation:
    brand-anim-dot-travel 600ms var(--ease-travel) 0ms both,
    brand-anim-dot-in      100ms linear 0ms both,
    brand-anim-dot-drill   80ms ease-in 580ms both;
}
@keyframes brand-anim-dot-travel { from { offset-distance: 0%; } to { offset-distance: 100%; } }
@keyframes brand-anim-dot-in     { from { opacity: 0; } to { opacity: 1; } }
@keyframes brand-anim-dot-drill  { to { transform: scale(0.35); opacity: 0; } }

/* offset-path 降级红线（§10 补丁 2）：不支持的引擎（iOS 15-）里光点不会停在路径起点，
   而是回到常规布局位置"乱飞"。用 @supports 显式钉死或隐藏——推荐隐藏（路线描边仍有完整叙事）。 */
@supports not (offset-path: path("M0 0")) {
  .brand-anim__dot { display: none; }
}
```

### 4.3 钉弹跳（段 6）—— 显式关键帧，非弹性 bezier

```css
.brand-anim--narrative .brand-mark__pin {
  transform-box: view-box;          /* 关键：让 transform-origin 按 viewBox 用户单位解析 */
  transform-origin: 48px 46px;      /* 钉尖 */
  animation: brand-anim-pin 260ms 600ms both;
}
@keyframes brand-anim-pin {
  0%   { transform: scale(0); }        /* ease-standard 出 */
  55%  { transform: scale(1.06); }     /* overshoot */
  78%  { transform: scale(0.97); }
  100% { transform: scale(1); }        /* 每段之间由浏览器按 keyframe timing 插值 */
}
```

### 4.4 站环脉冲（段 3）／涟漪（段 7）／hole-flash（段 5）

```css
.brand-anim--narrative .brand-mark__station:nth-of-type(2) {  /* 折点站环 (30,34) */
  transform-box: fill-box; transform-origin: center;
  animation: brand-anim-pulse 120ms ease-standard 310ms both;
}
@keyframes brand-anim-pulse { 50% { transform: scale(1.15); } }

.brand-anim__ripple {
  transform-box: fill-box; transform-origin: center;
  animation: brand-anim-ripple 140ms ease-out 800ms both;
}
/* ⚠️ v1.3 修正（走查 D3）：from 的 opacity 必须为 0（原写 0.45 ⇒ backwards 分支让钉尖挂一个
   12px 亮环长达 800ms）。可见度在 8%（≈11ms）内爬到 0.45，肉眼即"立刻出现"，不影响观感。 */
@keyframes brand-anim-ripple {
  from { transform: scale(0.18); opacity: 0; }
  8%   { opacity: 0.45; }
  to   { transform: scale(1); opacity: 0; }
}
/* 涟漪仅 scale+opacity（可合成）。禁用 filter: blur()（架构师约束：逐帧重绘，低端 Android 掉帧）；
   设计上涟漪不需要模糊边缘——细描边环自然淡出即可。 */

.brand-anim__hole-flash { animation: brand-anim-flash 120ms ease-out 580ms both; }
/* ⚠️ v1.3 修正（走查 D2）：必须显式写 0% opacity: 0。否则 fill-mode both 的 backwards 分支
   在 0–580ms 钉住的是元素"自然值"opacity:1 ⇒ 首帧就在钉帽位置亮一个 17px 蓝盘，提前泄底。 */
@keyframes brand-anim-flash { 0%, 1% { opacity: 0; } 40% { opacity: 0.9; } to { opacity: 0; } }
```

### 4.5 覆盖层淡出（段 8）

```css
.brand-splash__overlay { animation: brand-splash-exit 100ms cubic-bezier(0.4, 0, 1, 1) 860ms both; }
@keyframes brand-splash-exit { to { opacity: 0; } }
/* 播完/跳过后由前端移除 DOM；点击跳过 = 立即以 ≤120ms 淡出并移除 */
```

## 5. 加载小循环版（BrandRouteLoader，48–64px）

使用场景（PM 边界）：真实加载 >300ms 才出现；地图保持可见可操作；M 图标固定在分步文案行左侧，不随文案换行跳动。**动画是配角，文案才是主角。**

- **路线 + 站环 + 钉全程静态常驻**（不描边、不弹跳），唯一变量是光点——画面主体恒定，循环无接缝。
- **⚠️ v1.3（走查 D4）：循环版必须自带 `offset-path`。** `offset-path` 不能只在 `.brand-anim--narrative` 上定义——循环版没有它，`offset-distance` 完全失效，光点会停在 `cx/cy` 缺省的 (0,0)（画布左上角外侧，实测全程不动），"沿 M 走"的核心语义丢失。建议把 `offset-path` / `offset-rotate` 提升到公共 `.brand-anim__dot`，两个变体共用。

```css
.brand-anim__dot {                                   /* 公共：两个变体都吃 */
  offset-path: path("M12 48 L12 16 L30 34 L48 16");
  offset-rotate: 0deg;
}
```
- 循环周期 **1200ms**，`animation-iteration-count: infinite`：

| 时间（周期内）     | 内容                                              | 缓动                                |
| ----------- | ----------------------------------------------- | --------------------------------- |
| 0–140ms     | 光点在起点站环淡入（opacity 0→1）                          | ease-out                          |
| 0–1200ms    | 光点 offset-distance 0→100%                       | **linear**（匀速=通勤感，且循环 seam 处不会顿挫） |
| 832–1012ms  | 折点站环脉冲（光点 69.3% 处，832ms）                        | ease-standard                     |
| 1060–1200ms | 光点在钉帽孔处淡出 + scale→0.35（与下一周期起点淡出跨 seam 重叠，视觉连续） | ease-in                           |
| 1160–1400ms | 钉呼吸：scale 1→1.05→1（240ms，每圈光点到达触发一次）            | ease-standard                     |

- 两光点方案弃用：单光点 + seam 处 crossfade 已连续；60px 小尺寸上双光点会显 busy。
- 涟漪不进循环版（每圈都涟漪太吵），到达信号由钉呼吸承担。

### 5.1 两种形态（v1.6 定稿，回应架构师"加载态有两个调用点"）

同一组件、同一动画语汇，**两种形态**——差异只在尺寸与定位，不在动效：

| 形态 | 场景 | 尺寸 | 定位 | 文案 | 蒙层 |
|---|---|---|---|---|---|
| **A · 内联** | 请求等待（收藏回放触发路线规划等） | **48px** | 分步文案行**左侧**，`--space-2`（8px）间距，不随换行跳动 | 必带 `label`（文案是主角） | 无 |
| **B · 容器内居中** | 开屏结束 → 地图就绪的空窗（P7） | **48px** | **地图容器内**居中（`.nav-map__cover`：`absolute; inset:0; flex; center`）；`.brand-loader` 整体 134×48 居中 | `label` 传"地图加载中…"/"定位中…" | 无（cover 自带 `--surface-dim` 底） |

> **v1.8 修正（第二轮走查实测 N2）**：B 的实际布局是 **`flex-direction: row`**（图标左、文案右，`gap: 8px`），不是我原写的"图标上文案下（column）"。**采纳 row，改规格**——理由：① 与 A 形态布局**零差异**，"两种加载动画"的可能性进一步降低；② 图标+文字横排是加载提示的通用样式；③ 整体 134px 占 390px 屏 34%，视觉稳定。实测 `.brand-loader` 中心正好在 cover 中心 (195,390)，只是 svg 因 row 布局偏左 43px——这是预期，不是缺陷。

**裁定：**

1. **B 取 48px，两形态同尺寸。** 我此前论证 64px 时写"B 无 label、无蒙层、独占容器中央，要独自承担'系统在动'的信号"——**这个前提是错的，我没读 cover 结构就下了结论**。实际 `NavMap.tsx` 的 cover 里**一直有可见文案**（"地图加载中…"/"定位中…"）。⇒ B **有文案陪伴**，与 A 是同一信号量关系（文案是主角、图标是配角），48px 正确，且两形态尺寸完全一致、更统一。
   > 我上一轮说"64px 只靠信号量论证成立"——那个信号量论证本身就建立在不存在的"无文案"前提上，一并作废。
2. **B 定位在「地图容器内」。** 加载态的语义是「**这一块区域**在加载」，就该待在地图容器里；挪到屏幕中心会让用户以为「整个 App 在加载」。（基于已作废的交叉淡化方案而写的"必须屏幕居中"**已废**。）
3. **不加蒙层 —— 可接受，且必须不加。** ① 加蒙层 = 又造一次遮挡，等于把开屏的遮挡延续一段，违背"开屏撤走就还给用户地图"；② 加载态存在的时段恰好是"地图未就绪"⇒ 底下是 `.nav-map__cover` 的**不透明纯色底**（`--surface-dim`），不存在对比度问题。**这是时段决定的，不是"凑合能看"。**
4. **不加 opacity 降低、不加任何容器样式**（无 `surface` 底、无 `radius`、无阴影）。
5. **a11y（关键，容易被纯视觉讨论漏掉）**：`BrandRouteLoader` 自带 `role="status"` + `aria-live="polite"`，但其中的 svg 是 `aria-hidden="true"`。若文案留在组件**外面**，则 **live region 内容为空 ⇒ 屏幕阅读器不播**，且"定位中…"→"地图加载中…"的切换也听不到。
   ⇒ **必须把文案作为 `label` 传入组件**，使文案落在 live region **内部**。（v1.8 已实现：live region = `.brand-loader` 本身，`textContent` 长度 6，实测可播报。）
   ⇒ **不要**把 `aria-label` 挂在 svg 上（`aria-hidden` 元素不参与可访问名称计算）。
6. **B 的门控 —— v1.8 修正：`map-cover` slot 下必须归零。**

   > **第二轮走查实测缺陷 N1（P1）**：骨架 `rc-sk--big` 移除后，cover 内只剩 `BrandRouteLoader`，而它有 `GATE_MS = 300` 门控 ⇒ **t=0–300ms 的 cover 是完全空白的不透明容器**（实测：0ms / 125ms / 205ms 时 `children.length = 0`、`textContent.length = 0`；303ms 才出现图标+文案）。
   >
   > - **正常路径**（不跳过）：前 300ms 被开屏覆盖层遮住 ⇒ 不可见，无影响；
   > - **跳过路径**：用户 125ms 跳过 ⇒ **看到约 175ms 纯空白地图容器**——点跳过是为了快点看到内容，结果先看到空白，是可感知的体验损伤；
   > - **无开屏路径**（客户端路由回首页）：空白 300ms。
   >
   > ⇒ **修法：`GATE_MS = slot === "map-cover" ? 0 : 300`。** 理由：cover 的出现（`phase === "loading"`）本身已是"确实在加载"的信号，不需要二次门控；"闪现图标+文案"远好于"闪现空白"。A 形态（`request` slot）保持 300ms 门控不变。

**替换而非叠加（回答架构师的实现路径）**：cover 内 `rc-sk--big`（**62×30 的 shimmer 矩形骨架**）应被 BrandRouteLoader **替换**，不许并存——两个活动指示器同屏 = 信号冲突。视觉重量相当（62×30 骨架 → 48×48 图标 + 8px + 文案），且从"无意义占位"升级为"有品牌含义的活动指示器"，是净收益。文案语义的两种状态（"地图加载中…" vs "定位中…"）**保留**——它区分了两个真实阶段，正合 PM「文案必须对应真实阶段」的原则。

> 一致性结论：A 与 B 是同一个 mark、同一套 keyframes（1200ms 循环）、**同一尺寸 48px**、**同一 row 布局**，只有定位（文案行左侧 / cover 内居中）与文案来源不同。两形态布局零差异，用户不会感知到"两种加载动画"。

## 6. reduced-motion 降级（`prefers-reduced-motion: reduce`）

| 场景       | 显示内容                                                           |
| -------- | -------------------------------------------------------------- |
| 全屏开屏（首装） | **静止末帧**：完整静态 logo 定格态，淡出交接同 §3 顺序（PM 第 4 条硬约束）                |
| 加载小循环    | **静态 mark（光点不出现）**；存活信号由文本承担——A 形态用可见 label，B 形态用 visually-hidden 文本（见 §5.1 第 5 条） |
| 引擎不支持 offset-path（iOS 15-） | 静态 logo（与"静止末帧"同一渲染出口）；光点由 `@supports not (offset-path: path("M0 0"))` 隐藏（代码见 §4.2 / §10 #2） |

> 触发条件区分（架构师要求验收分开核）：`prefers-reduced-motion` 是**用户偏好**，`@supports` 是**浏览器能力**——两者渲染出口相同（静态 logo），但触发条件、机验手段不同：前者核 `body[data-splash-state]="reduced"`，后者核光点元素 `display:none` 且叙事版其余动画正常播放。

> **v1.6 自我修正（加载循环版的 reduced-motion 口径）**：我原先写"M 静止 + 光点极低幅度呼吸（0.7↔1）"——**这条我撤回**。理由很直接：**呼吸也是 motion**，用户明确要求"减弱动态效果"，我给他一个持续脉冲 = 违反诉求本身，只是幅度小到我认为无害。正确做法是**完全静止 + 由文本承担存活信号**（A 有可见 label，B 有 visually-hidden 文本）。这也与实现现状一致（全局杀开关把循环压成单次 ⇒ 光点停在 opacity 0 ⇒ 静态 mark），架构师裁定"符合设计意图"我认同。

`data-splash-state` 相应置 `reduced`（见 §7），机验降级生效。

**⚠️ 全局杀开关与 fill-mode 红线（v1.2，架构师核出的静默坑）**：项目 `globals.css` 已有 9 处 reduced-motion media query，其中 `:541` 是 `* { animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; }` ⇒ reduced-motion 用户的动画**瞬间播完、不报错**，停在哪个状态完全取决于 `animation-fill-mode`：

- **红线：本规格每条 animation 必须显式写 fill-mode（本规格统一用 `both`，语义包含 forwards）**。省略 fill-mode ⇒ 瞬播完跳回初始帧 ⇒ 用户看到空 M（描边未画、钉未长）。
- 为什么是 `both` 而不是裸 `forwards`：delay 期间需要 backwards 钉住首帧关键帧（钉 0% 是 scale(0)，裸 forwards 会让钉在 600ms 前提前以 scale(1) 可见）。
- 列入验收：reduced-motion 环境下截帧必须是静止末帧（完整 logo），禁止空 M。

### 6.1 ⚠️ v1.3 补充：杀开关清 duration，**不清 delay**（走查 D1）

全局杀开关只写 `animation-duration: 0.01ms !important` + `animation-iteration-count: 1 !important`，**`animation-delay` 原样保留**。⇒ 凡带 delay 的段（钉 600ms、flash 580ms、涟漪 800ms、overlay 860ms）在 reduced-motion 下都会：delay 期间被 backwards 分支**钉在 0% 关键帧**，随后瞬跳到末帧。实测后果：**钉在前 600ms 完全不可见**，600ms 后"凭空蹦出"，860ms 才淡出，总耗时 901ms——"静止末帧完整 logo"验收点不成立。

修法（reduced-motion 专用块，前端直接抄）：

```css
@media (prefers-reduced-motion: reduce) {
  .brand-splash__mark,
  .brand-splash__mark * { animation: none !important; }   /* 一次性呈现完整 logo */
  .brand-splash__mark .brand-mark__pin { transform: none !important; }
  .brand-anim__dot,
  .brand-anim__hole-flash,
  .brand-anim__ripple { opacity: 0 !important; }          /* 三个"行进/到达"元素不出现 */

  /* 覆盖层立即淡出；⚠️ 必须沿用同名 keyframes，JS 的 animationend 靠它移除容器 */
  .brand-splash__overlay { animation: brand-splash-exit 100ms linear 0ms both !important; }
}
```

**reduced 下 overlay 提前到 100ms 移除 —— 设计裁定：接受（v1.7）。**

- **理由**：reduced 用户明确要求减少动态。让他对着一个**静止** logo 白等 860ms，是"没有动态的等待"——既无信息增益也无视觉价值，纯属浪费。100ms 淡出保留了"柔和交接"（避免硬切），又不拖延。
- **代价**：改变"按正常时机移除"这条验收（860ms）⇒ 验收须**按路径分开**：正常态断 ~860–960ms 移除，reduced 态断 **~100ms** 移除。已同步 QA。
- **⚠️ 一个必须核的时序风险（reduced 特有）**：`data-splash-state="reduced"` 的写入发生在 React `useEffect`（paint 之后）；而 overlay 的 100ms 动画从首帧就开始。若页面重负载导致 effect 延迟到 100ms 之后才执行，会出现**容器已被移除、状态还没记上**的竞态 ⇒ `reduced` 断言偶发失败（典型表现：CI 全绿、低端机偶红）。
  ⇒ 验收时不要只看"有没有写 reduced"，要在**容器尚在时**采一次（如 `t≈50ms`）确认 state 已是 `reduced`。
  ⇒ 若实测确有竞态，修法不是在 CSS 侧加 delay，而是把 reduced 判定提前到**渲染前**（如首帧内联脚本或 `useLayoutEffect`），保证状态先于动画结束写入。

效果：reduced-motion 总耗时从 901ms 降到 ≈100ms，画面为完整静态 logo。

## 7. 观测钩子（PM 建议，验收断言用）

### 7.1 容器钩子 `[data-splash-root]`

覆盖层容器元素上**固定携带** `data-splash-root` 属性（全页唯一实例），随容器生灭：

- 跳过/播完移除容器时属性随之消失——QA 断言「跳过后 100ms 内可交互」依赖 `document.querySelector('[data-splash-root]') === null`。
- **仅作定位钩子，不复用任何样式类**（样式类会随改版重命名，钩子不会）；容器自身的视觉样式照常走 class。

### 7.2 状态钩子 `body[data-splash-state]`

`document.body.dataset.splashState` 取以下**四个值**之一：

| 值         | 语义                           | 状态切换时机       |
| --------- | ---------------------------- | ------------ |
| `playing` | 960ms 叙事版播放中                 | 动画层挂载进 DOM 时 |
| `skipped` | 点击跳过（动画层立即 ≤120ms 淡出移除，不留常驻） | 点击时          |
| `done`    | 自然播完                         | 段 8 淡出启动时    |
| `reduced` | reduced-motion 命中，静止末帧       | 组件挂载时判定      |

保持至组件卸载不清空——「跳过后首屏立即可用」（skipped）、「降级生效」（reduced）、「自然播完」（done）三条均可机验。

> **v1.7 定案（代码已核实）**：`blocked` **已从枚举删除**，现为 **4 值**。
> 依据：挂载点移到根 `layout.tsx`（`layout.tsx:88` 一处挂载，`page.tsx` 已无）+ `sessionPlayed` 模块标记物理删除（`BrandSplash.tsx` 内 0 处引用）+ `type SplashState = "playing" | "skipped" | "done" | "reduced"`。
>
> ⇒ 三个原本会"不播"的场景，现在都不产生状态值：
> - **客户端路由跳转**：layout 不重挂 ⇒ **结构性不播**，组件生命周期不启动，无状态写入。
> - **bfcache 还原**（`pageshow.persisted`）：**只移除容器，不重播**，无状态写入。
>
> ⇒ QA 断言改法（重要，旧口径已失效）：
> - 「路由跳转不播」→ 断言新页面 `[data-splash-root]` **不存在**，**不要断 `blocked`**（该值已无）。
> - 「bfcache 不播」→ 断言 `[data-splash-root]` 不存在。
> - 「整页加载播」→ `playing` + 容器存在。
> - 「不重播」→ 断言 **`playing` 全程只出现一次**（比 `blocked` 更强：`blocked` 只证明"到了没播"，`playing` 次数直接证明"没再播"）。

## 8. 给前端的实现提示（最容易踩的三个点）

1. **dashoffset 与 offset-distance 必须同时长、同缓动函数、同 path 字符串**，否则光点与描边端点脱节（错位在折角处会被放大到肉眼可见）。offset-path 的 path() 坐标解析在 SVG 用户坐标系内，与 viewBox 单位一致，直接抄 `M12 48 L12 16 L30 34 L48 16`。
2. **SVG transform 的坐标系**：钉的 transform-origin 是用户单位 `48px 46px`，必须配 `transform-box: view-box`（或 fill-box，见各段代码）；不设 transform-box 时 origin 相对的是元素自身包围盒，钉会从错误位置缩放。站环脉冲同理用 `transform-box: fill-box; transform-origin: center`。
3. **颜色与 id**：颜色只走 `.brand-mark__* / .brand-anim__*` CSS class（var() 写进 SVG 表现属性跨引擎不可靠，BrandMark 注释里有实测结论）；mask id 必须用 `useId()` 生成，避免同页多次渲染冲突。体积预算：一个组件 + 约 60 行 CSS 关键帧，随首屏内联渲染，无网络请求——不许为动画引入任何额外资源文件。

## 11. v1.3 · 播放条件变更 + 末帧→加载态交接（负责人裁定 2026-11-02）

### 11.1 频率：**每次整页加载都播**（含内页深链）

负责人裁定：开屏动画**每次进入应用都播**，目的是优化首屏等待体验；原「仅首装/大版本播一次」作废（版本门/cookie 判定移除）。视觉（§1–§6）不变。

生命周期（v1.7 定案，**代码已核实**）：

- 挂载点在**根 `layout.tsx`**（`layout.tsx:4` import、`:88` `<BrandSplash />`；`page.tsx` 已无挂载）。
- **会播**：冷启动、F5 刷新、**深链任意页面（含 `/help`、`/line/xxx`、`/card` 等内页）**、分享链接、重开标签 —— 只要发生**整页加载**就播。

- **不播**（且**不产生任何状态值**，见 §7.2）：
  - **应用内客户端路由跳转**（`/favorites`→`/`、`/help`↔`/`、收藏回放回首页等）—— layout **不重挂** ⇒ **结构性不播**；
  - **bfcache 还原**（`pageshow.persisted`）—— **只移除容器，不重播**。
- **不使用任何"已播标记"**（`sessionPlayed` 已物理删除）。「客户端路由不播」由 layout 不重挂这个**结构事实**保证，不靠状态机 —— 这同时从根上消除了 StrictMode 双挂载缺陷。

> v1.6 那段"挂 page.tsx ⇒ 深链内页不播是设计意图"**已作废**，不要再据此实现或验收。

### 11.2 前提：动画不得推迟首屏渲染（显式写成前提）

**动画层存在期间，首屏（地图容器 + 底部面板结构）必须已在 DOM 中渲染完成**——动画是"盖在已渲染内容之上的覆盖层"，不是"内容的前置门"。§3 的交接红线以此为前提：先有内容，再有覆盖层淡出。

### 11.3 末帧 → 加载态：**天然暴露，无需过渡设计**（v1.5 终裁）

**我原先写的「交叉淡化 / 187→56px 收缩」方案已作废**——不是算错，是**这个场景在新实现结构下不存在**。team-lead 核实实现后的裁定：

- `NavMap.tsx:1622` 的地图 loading 态**本来就在渲染**；`.nav-map__cover` 是 `position: absolute; inset: 0`（相对地图容器，**局部**，`globals.css:2185`），一直在跑。
- 开屏覆盖层是 `position: fixed; z-index: 200`（**全屏**），**盖在它上面**。

⇒ 860–960ms 开屏淡出时，**底下已经有一个加载态在跑**。用户看到的是「大 M 淡出 → 露出已经在转的加载态」。

> **⚠️ 表述精确化（PM 核出，我已核实）**：覆盖层底下当前装的是 **`rc-sk--big` 骨架块（62×30 shimmer）+ `nav-map__cover-text` 文案**，**不是 BrandRouteLoader**（该组件此前零引用）。所以：
> - 「底下已有加载态在跑」——**成立**；
> - 「露出已经在转的小 M」——**目前不成立**，要等 loader 接入替换骨架后才成立。
>
> ⇒ 结论「天然过渡、零过渡代码」依然有效（有加载反馈即不需要设计过渡），**但第二轮实测"两只 M 溶解"必须等接入之后再做**，否则截到的是"骨架 → 骨架"，测不到目标现象。

**零过渡代码、零几何对齐、零空帧。**

| 分支 | 条件 | 视觉 | 交接 |
|---|---|---|---|
| ① 快路径 | 动画结束 + 首屏已可用 | 段 8 整层淡出（860–960ms），末帧 = 完整静态 logo | 覆盖层淡出 → 露出首屏 BrandMark |
| ② 慢网 | 动画结束 + 地图未就绪 | 覆盖层照常淡出 860–960ms；**底下 loading 态从 300ms 就在跑**（接入后 = 小 M + 文案） | **天然暴露**，无过渡动画 |
| ③ 短加载 | 首屏 <300ms 就绪 | 加载态门控未触发 ⇒ 底下本来就没有 loading 态 | 同分支 ① |

时序冲突口径：地图在播完前就绪 ⇒ 覆盖层淡出后直接是地图（无小 M）；动画未播完但地图没就绪 ⇒ 照常走完 960ms，**不提前打断**。

**两条明确不做的事（记录以免日后被"重新发明"）：**
1. **不把加载态挪到屏幕中心**。加载态的语义是「**这一块区域**在加载」，它就该待在地图容器里；挪到屏幕中心会让用户以为「整个 App 在加载」，反而错了。我此前基于交叉淡化方案写的「必须屏幕居中」约束**随之作废**（那 45px 差异只在"挪出去对齐"时才成为问题）。
2. **不做 logo 尺寸插值**。「品牌开屏」与「地图正在加载」是两个视觉阶段，中间有 100ms 淡出，人眼不要求位置连续；且两者不是"同一个东西的延续"。

### 11.3.1 残留观察：淡出期 100ms 内两者短暂同屏 —— **已知并接受**（v1.7 定案）

「天然暴露」不等于"零重叠"。开屏 overlay 是 `background: var(--bg)` **不透明层**，淡出 860–960ms 期间 opacity 从 1→0 ⇒ **大 M（屏幕中心）与底下的加载态（地图容器中心）会同时部分可见约 100ms**，中心相距约 **45px**。挂 `layout.tsx` 后此现象照样存在。

**结论：接受，不修。** 理由（PM 已采纳并写进 06）：

1. **100ms ≈ 6 帧**，两者不透明度都在 0.3–0.7 低区交错，不存在"两个都清晰可辨"的时刻。
2. **两者语义不同，用户不会要求位置连续**：大 M 全屏居中 = **品牌开屏**；加载态在地图区 = **区域加载**。这是两个视觉阶段，不是同一个东西的延续。
3. **为对齐 45px 把加载态挪到屏幕中心，反而破坏「这一块区域在加载」的语义** —— 挪位置的成本（语义错误）远高于收益（消除一段看不见的错位）。

> **诚实留痕（不写成约束）**：不记录的话，下一个人还会重新推导一遍 45px，然后得出同样的错误结论。若第二轮走查发现明显跳跃再议——届时修法是**压缩重叠窗口**（overlay 淡出 100ms→60ms，或起始提前到 840ms），**不是挪位置**。
> （06 §4.1 已按此改写：删掉"位置同心"这个不可核项，换成可核的 P7a「860–960ms 淡出期间不得出现可辨识的双影，核 880/920ms 两帧」。）

### 11.3.2 两层底色的衔接：**不改全局 token**（回应架构师第 4 条）

开屏 overlay 背景 = `--bg`；`.nav-map__cover` 背景 = `--surface-dim`。淡出瞬间理论上会有底色跳变。**实测两个主题的差异**：

| 主题 | `--bg` | `--surface-dim` | 对比度 | 判断 |
|---|---|---|---|---|
| 浅色 | `#f2f4f0` | `#eaece7`（=`--surface-2`） | **1.075 : 1** | 几乎不可见，不处理 |
| 深色 | `#111318` | `#2a2d34` | **1.348 : 1**（L 0.0065 → 0.0262，约 4 倍亮度） | 可察觉，但方向正确 |

**结论：接受现状，不改任何色值。** 三条理由：

1. **不改 `--surface-dim`**：它在 `globals.css` 被 20+ 处使用，是"次表面"的全局设计语言；为一次开屏动画改它，会波及全站，且破坏 cover 作为"加载容器表面"的语义（cover 若与 `--bg` 同色，就失去"这里浮起一块地图区域"的形体感）。
2. **深色 1.348:1 的方向是对的**：从页面底（更暗）过渡到容器面（略亮），读作"地图区域浮现"——是合理的空间线索，不是错误。且它发生在 100ms `opacity` **渐变**内，是溶解而非切换，不会产生"闪一下"的观感。
3. **若第二轮实测发现深色下像"面板突然亮起"**，修法是把 **overlay 背景从 `--bg` 改为 `--surface-dim`**（让开屏与 cover 同色，消除跳变），**不是改 cover**。改动画层只影响一处、可回滚；改全局 token 影响 20+ 处。

### 11.4 长等待的信息量：**靠文案递进**（保留）

过渡不需要设计，但"慢网等待过久"仍需处理——不靠动效，靠文案：

- **文案必须对应「真实已发生的阶段」**（PM 原则：填充内容必须与任务相关，编造的进度文案在出错时会变成谎言）。例：真实阶段依次为"取实时到站"→"计算步行"→"排组合方案"，则文案随之推进；**禁止**写"已完成 80%""马上就好"这类无依据表述。
- 动效恒定（1200ms/圈不变），信息由文案承担（PM 口径"文案是主角"）。
- **不冻结动效**：静止图形在 2s 以上等待里会被读成"卡住了"，这是加载态最不该犯的错。「大 M 走一遍 → 小 M 继续循环」不重复：尺寸差约 2.9 倍（187→64）、中间隔 100ms 淡出，读作"到达后继续工作"，不是二次播放。

### 11.5 观测钩子：加载版**不新增状态值**

- `data-splash-state` 四值**语义不变**；加载态出现时它**保持 `done`**（或 `reduced`），不新增 `loading` 之类的值——两者是不同维度：开屏层在/不在 vs 页面在加载。
- 加载版用独立布尔属性：容器上 `data-loading-route="1"`，移除时属性随容器消失（与 `[data-splash-root]` 同一套"随生灭"纪律）。
- QA 断言可用：`[data-loading-route]` 存在 ⇔ 地图 loading 态在跑（>300ms 门已过）；`[data-splash-root]` 消失 ⇔ 开屏层已退出。两者**可以同时存在**（慢网分支②的天然暴露窗口），这是正常的，不是冲突。

### 11.6 走查发现（D1–D5）

实现层缺陷与修法已单列在 `09-视觉走查-开屏与加载动画.md`（含可直接抄的补丁）：D1 reduced-motion 钉不可见（delay 未清）、D2 hole-flash 首帧常亮、D3 ripple 首帧常亮、D4 循环版缺 `offset-path`、D5 折点脉冲相位晚 106ms。§4.4 / §5 / §6 已按修法更新，前端照改即可。

**D1 定性（team-lead 终裁，采信）**：**P0，且比"空 M"更糟**——空 M 至少是"没画"，而 reduced-motion 用户看到的是"钉画了又没了、600ms 后凭空出现"，是**三个矛盾状态连续**。且会让 QA 的 S6/P4「静止末帧完整 logo」直接红。

## 12. 全站加载态替换规格（v1.9 · 2026-11-03）

> 负责人需求（原文）：「把整个项目所有需要加载时的等待动画都应用 M Map logo 式加载动画……沿 M 字母走一遍又一遍直到加载完成。」
> 本节覆盖 `rc-sk` 骨架的**全部 5 处使用点**（`grep -rn "rc-sk" src --include=*.tsx` 实测）+ 已接入的 map-cover 共 6 处。**只出规格，不含实现。**

### 12.0 两条总纲（先读，决定下面所有条目）

**总纲一 · 占位与指示分离——骨架的两个作用要拆开处理。**
骨架屏同时干两件事：①「占住空间防内容填充时跳动」②「指示正在加载」。替换时**不能把①丢掉**：
- **指示** → 一律换成 BrandRouteLoader（负责人需求）；
- **占位** → 用**容器轮廓 + `min-height`** 保住，不用骨架线条保住。
⇒ 通用公式：**「M（BrandRouteLoader）+ 宿主容器轮廓 + `min-height` 占位」**，而不是"裸 M 直接替换骨架 DOM"——后者会让容器塌缩，内容到达时页面"弹一下"。

**总纲二 · 门控随场景：`map-cover` 归零，其余 300ms。**
§5.1 第 6 条已裁定 `map-cover` 门控为 0（cover 本身就是加载信号）。本节新增位置**全部采用 300ms 门控**（与 `request` 相同）：这些位置都是**用户主动触发后的等待**（点方案卡、发起搜索、路由切换），快路径（<300ms）下闪一个 M 是噪音——与 map-cover"被动等待、无其它反馈"的场景本质不同。
⇒ `GATE_MS = slot === "map-cover" ? 0 : 300` 保持不变，新增 slot 落入 300 分支。

### 12.1 尺寸分级（两档，不设第三档）

| 档 | 尺寸 | 适用 | 理由 |
|---|---|---|---|
| **标准** | **48px** | 整页/面板级等待（map-cover、recommend 页、路由级 loading） | 现有规格档位，不新增 |
| **紧凑** | **32px** | **卡片内部**等待（结果列表等待卡、详情卡内） | 卡片高度有限（`rc` padding 14+12 + 内容，单卡 ≈120–150px），48px 占卡片高度 1/3 以上，喧宾夺主；32px 为卡片内视觉重心与留白的平衡点 |

不设 64px 档：整页级等待场景（recommend）**已有标题+副标题文字作为主信息**，M 是辅助指示，48px 足够；三档会带来"哪个场景用哪档"的持续争论成本。

### 12.5 slot 扩展与门控

```
slot 枚举：map-cover | request | list | detail
门控：    GATE_MS_BY_SLOT = { "map-cover": 0, request: 300, list: 300, detail: 300 }   ← 查表，与实现同构
```

- **v1.9.1 修正**：门控表述从三元改为**查表**——实现（`BrandRouteLoader.tsx:51`）已是 `GATE_MS_BY_SLOT` 表驱动，规格以实现同构，避免"语义相同、形式不同"的漂移。
- **⚠️ 新 slot 必须同时在表里加行**：查表实现下，`GATE_MS_BY_SLOT[slot]` 缺 key 会返回 `undefined` ⇒ `setTimeout(fn, undefined)` **立即执行 ⇒ 门控静默失效**（新 slot 直接闪现，无任何报错）。新增 `list` / `detail` 时务必同步加 `list: 300, detail: 300` 两行——**表与枚举必须同步增删**，这是本节唯一的实现红线。
  > **落地状态（已核代码）**：表类型已标注为 `Record<NonNullable<BrandRouteLoaderProps["slot"]>, number>`（`BrandRouteLoader.tsx:52`），枚举加值而表缺行 ⇒ **TS2739 编译期直接红**——这条红线已由类型系统物理封死，不再依赖人的记性。
- 新增 `list` / `detail` 两值**仅为 QA 定位与断言用**（`data-loader-slot`），门控行为与 `request` 完全相同（300ms）。
- **不要**为四个 slot 写四种门控或把查表改成 per-slot 函数/状态机——查表加行即完，改函数是过度设计（架构师已列为防呆条款）。
- A5（`data-loader-root/mode/slot` 随容器生灭）对新增位置同样适用。

### 12.6 建议保留骨架屏的位置 —— **无**

逐位置判断后**没有**需要保留 `rc-sk` 的位置：

- 列表类（①）：骨架的"形状预览"价值被"真结果数量不定"削弱，等待卡更诚实；
- 详情类（②⑤）：详情结构在加载前不可预知（不同方案卡段数不同），骨架线条是假预览；
- 整页类（③④）：已有真实文案承担信息，M 承担活动性。

⇒ 全部替换后，`rc-sk` 系列 CSS（L1718–1745 + `rc-shimmer` keyframes）可整体删除（前端确认无其它引用后）。**`--surface-dim` 等色值 token 不动**（cover 等仍在用）。

1. **③④ 同批**（双层同形约束，单独换任何一层 = 自造跳动）；

- 每处：M 是否居中、label 是否在 live region 内（`role="status"` 含文案）、`min-height` 是否生效（内容到达时不塌缩）；
