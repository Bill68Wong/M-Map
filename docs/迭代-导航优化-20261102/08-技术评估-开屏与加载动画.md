## 〇、决策变更横幅（2026-11-02 · 版本门被产品层整体废除）

负责人裁定「每次进入应用都有开屏动画」，原始需求是「趁首页地图还在加载时用开屏优化用户体验」——目标是**优化等待**，不是品牌仪式。本节置顶，**后续实现与验收以此为准**。

### 作废（勿再引用，勿照此实现）

| 作废内容 | 位置 |
|---|---|
| 版本门三种做法（A cookie 门 / B localStorage 门 / C 根 layout + cookie） | §二 |
| **cookie 单门裁决**（含「localStorage 时序上无合法执行时机」论证） | §二 |
| `mmap.splash.ver` 键名、版本比对、major/minor 判定、记账时机 | §二 |
| **Safari ITP 对 JS 写 cookie 的 7 天上限取舍** | §二 |
| 「挂载在 `page.tsx` 而非根 layout，因为读 cookie 会拖动态渲染」 | §二 |

作废原因：**门本身不该存在**。不是选型错了——单门裁决在「存在版本门」这个前提下时序论证成立；是 upstream 的产品前提被推翻。作废后**不需要任何持久化媒介**（cookie / localStorage / sessionStorage 全部不需要），P10 的防回潮断言因此天然成立。

### 仍然有效（本次实现的实际依据，勿动）

- **§一 浏览器支持矩阵**：`offset-path` / `offset-distance` Safari 16+（WebKit 官方 Safari 16.0 release notes + MDN）、`stroke-dashoffset`、`pathLength="1"` 归一化、`@supports not` 降级路径；
- **§二 首帧时序**：SSR 直出、零 hydration 依赖、动画资源首帧构造性就绪（keyframes 进 `globals.css`、SVG 内联、不动态 import）；
- **§三 体积预算四条红线**：不引第三方库、不动态 import、颜色走 `.brand-*` class 绑 token、可合成属性优先 + 涟漪禁 `filter: blur()`；
- **§四 `prefers-reduced-motion` 的 `fill-mode` 静默坑**（本文最有价值的一条）：全局杀开关（`globals.css:541`）把动画压成 0.01ms 单次，若缺 `forwards`/`both` ⇒ 跳回初始帧 ⇒ reduced-motion 用户看到**空 M**，且不报错。规格 v1.1 统一用 `both`，已覆盖；
- **工程纪律**：mask id 用 `useId()`、光点置于 mask 组外（规格 v1.1 §2）、层级显式数字（z-200 > 车辆 130）、`[data-splash-root]` 真移除（禁 opacity/visibility/pointer-events 三种假移除）。

### 废除后的边界（技术含义）

| 场景 | 行为 | 实现手段 |
|---|---|---|
| 冷启动 / 任意整页加载（含 F5、深链、PWA 启动） | **播** | SSR 无条件输出容器，CSS 动画首绘即开始 |
| 应用内客户端路由（底导互跳、收藏回放回首页） | **不播** | 挂载点选在**不随客户端导航重挂**的层（见 §五） |
| 暖启动：bfcache 还原 / 切后台切回 | **不播** | 容器早已从 DOM 移除，快照里没有它；`pageshow.persisted` 仅作中播离场时的兜底移除 |

**关键结论**：暖启动与客户端路由的「不播」都**不需要任何持久标记**——「已播」这个状态由**结构本身**承载（容器播完即移除，且不重挂），它自失效、不会过期、不受浏览器清理策略影响。这比任何一种存储门都更稳。

## 〇之二、实现期发现（2026-11-02 · 代码层，属评审不属评估）

**`next dev` 下开屏层永久遮挡、整站不可点击**。`BrandSplash.tsx` 的 effect 用模块级 `sessionPlayed` 做提前 return：

```ts
if (sessionPlayed) { stateRef.current = "blocked"; ...; return; }   // ← 提前返回
sessionPlayed = true;
```

本项目未显式配置 `reactStrictMode`，而 Next 源码注释明确 App Router 缺省开启（`node_modules/next/dist/build/define-env.js:126-127`：`// When next.config.js does not have reactStrictMode it's enabled by default.`）⇒ dev 下 effect 跑两遍：

1. 第 1 遍：建立全部监听 + 2500ms 兜底计时器；
2. cleanup：卸监听 + `clearTimeout(backstop)`；
3. 第 2 遍：`sessionPlayed` 已 true ⇒ 记 `blocked` 后 return ⇒ **监听与兜底都不重建**；
4. `gone` 仍 false ⇒ 容器留在 DOM。`.brand-splash__overlay`（`globals.css:8591`）是 `position:fixed; inset:0; z-index:200` 且**无 `pointer-events:none`** ⇒ 960ms 后 opacity 归 0，视觉完全正常但**吞掉全站点击**，而 `data-splash-state` 却是 `blocked`（自相矛盾）。

生产构建**当时**不受影响（StrictMode 双调用仅 development），但前端调试与 QA 若在 dev 上跑，会撞一个极具误导性的现象——看起来像路由/按钮失效。

**根治方式不是打补丁，是改标记的置位时机**：把「effect 开头置 `true`」改为「只在 `markDone()` / `skip()` 里置 `true`」，并把 effect 早退判据从「`if (sessionPlayed) return`」换成「`if (!overlayRef.current) { 记 blocked; return }`」。这样 StrictMode 首遍 effect 时标记仍为 false ⇒ 两遍都走完整流程 ⇒ 遮挡消失，且不需要 cleanup 回滚分支（见 §五末段）。

### 同型缺陷升级：双份挂载 ⇒ **生产环境**也会出现幽灵遮挡层

排查时发现 `BrandSplash` 被**同时挂载两处**（2026-11-02 当时状态）：

```
src/app/layout.tsx:4   import BrandSplash ...
src/app/layout.tsx:88  <BrandSplash />
src/app/page.tsx:18    import BrandSplash ...
src/app/page.tsx:80    <BrandSplash />
```

React effect **子先于父**执行 ⇒

1. SSR HTML 里输出**两个** `[data-splash-root]`（服务端 `sessionPlayed` 恒 false）⇒ P9「`length <= 1`」必红；
2. `page` 的实例（children）effect 先跑：`sessionPlayed=false` → 置 true → 完整播放 → 960ms 自移除；
3. `layout` 的实例 effect 随后跑：`sessionPlayed` 已 true → 走 `if (sessionPlayed) {…return}` → **提前返回，其容器永久留在 DOM**，`opacity` 被 `both` 钉在 0。

⇒ 一个**不可见但吞掉全站点击**的覆盖层，且 `data-splash-state` 显示 `blocked`（自洽、不报错）。**这次与 StrictMode 无关** —— 说明「提前 return 时容器未移除」这个缺陷模式有两个触发源（dev 双调用 / 任意双挂载）。

> **2026-11-02 后续更新（重要）**：前端随后**删除了 `sessionPlayed` 标记**、早退判据改为 `if (!overlayRef.current) return`（DOM 事实）⇒ 上面这条「双挂载产生幽灵层」的**推演链已不成立**（没有标记，两个实例都会完整播放并各自移除）。双挂载的残余后果降为：SSR 输出 2 个 `[data-splash-root]` ⇒ **P9 红** + 一份重复动画开销，**不是用户可感故障**。
>
> **但这不等于「提前 return」这个模式安全了**：只要将来任何人重新引入一个"在 effect 开头判标记就 return"的分支，dev 双调用与双挂载都会让它复发。所以仍须保留两条纪律：① effect 幂等可重入，早退判据用 DOM 事实；② 全站只允许一处挂载。

**结论**：① effect 必须幂等可重入（见上）；② 全站 `BrandSplash` 只允许存在**一处**挂载。后者应作为验收项：`querySelectorAll('[data-splash-root]').length <= 1`（即 PM 的 P9）在代码层必须由「单一挂载点」保证，而不是靠运行时互斥。

## 一、浏览器支持矩阵

| 能力 | Chrome/Edge | Firefox | Safari / iOS Safari | 结论 |
|---|---|---|---|---|
| `offset-path: path()` / `offset-distance` 动画 | 55+/56+ | 72+ | **16+ / 16+**（WebKit 官方 Safari 16.0 发布说明原文：「WebKit now supports CSS Offset Path」；MDN compat 同口径） | **iOS 16+ 可用**，与项目目标一致 |
| `stroke-dashoffset` 动画 | 全支持 | 全支持 | 全支持（远早于 16） | 无风险 |
| `pathLength` 属性（把 dash 归一化到 0..1，免 JS 算长度） | ✓ | ✓ | ✓（`<path>` 上无已知坑；WebKit 的 pathLength 历史 bug 集中在 `<line>`/`<circle>`，本项目用 `<path>`） | **必须用**，别在 JS 里算路径长度 |
| `@supports (offset-path: path("M0 0"))` 特征检测 | 56+ | 72+ | **13.1+**（`path()` 本身 Safari 13.1 就进 @supports） | 检测本身可以放心用 |
| `transform-box: fill-box` + `transform-origin`（钉以钉尖为支点生长） | ✓ | ✓ | 11+ | 无风险 |

**网上有一个相反说法，需要正面回应**：有社区问答称「Safari 直到 17.4 才支持、16 完全忽略、且 `@supports` 返回 true 但 `path()` 解析失败」。这与 **WebKit 官方 Safari 16.0 发布说明**与 MDN 兼容表直接矛盾，且该问答混淆了旧属性名 `motion-path` 与现行 `offset-path`（`@supports (motion-path: …)` 在任何浏览器都是 false）。**我采信一手来源（WebKit 官方 + MDN）**：iOS 16+ 可用。
但该问答描述的失败模式——「**检测通过却运行失败**，元素重置到 transform 原点」——值得防御：`offset-path` 不被支持时，元素**不会**停在路径起点，而是回到它的**常规布局位置**（对 SVG 子元素即文档流原点附近）⇒ 光点会「飘」到奇怪的地方。
⇒ **降级实现不能只是"不写 offset-path"**：必须用 `@supports not (offset-path: path("M0 0"))` 把光点的**静态位置显式钉在路径起点**（或直接隐藏光点），再叠加设计的降级方案（静态 logo + 光点呼吸 opacity）。这样即便真遇到"声称支持但行为异常"的引擎，光点也不会乱飞。
设计侧的降级方向（静态 logo + 呼吸）**不需要调整**，只需补「光点静态位置显式声明」这一条。

**其他已知引擎差异**（均不影响本方案）：`offset-anchor` Safari 支持较晚（本方案用不到）；`offset-position` 更晚（用不到）。

## 二、首帧时序（这是四问里唯一会「做错」的地方）

**现状数字**：首页 HTML TTFB 热 520–570ms、体积 22.7KB；JS 15 chunk 共 223KB br（异步加载）；`layout.tsx` 目前是 `<body>{children}</body>` 极简结构；**没有根级 `loading.tsx`**。

**必须钉死的第一条：开屏层必须出现在服务端渲染的 HTML 里（SSR），不能是客户端挂载。**
客户端挂载 = 白屏 → hydration → 才出现开屏 ⇒ 白屏期**变长**而不是被遮住，与目标相反。
SSR 输出的开屏是纯标记 + CSS，**首帧即显示，不依赖任何 JS**。

**挂载位置建议：`page.tsx`（首页）而不是 `layout.tsx`。** 下列三条是版本门时期的理由（**均随门废除而失效**，结论正确但理由已换）：

> ⚠️ 版本门废除后，本节三条理由不再成立。挂载点的现行依据见 **§五**（两条相反口径并存，待 team-lead 终裁）；此处保留原文仅为留痕。
- 首页已经是 `force-dynamic` ⇒ 在这里读 `cookies()` **零额外代价**；
- 若放进根 `layout.tsx` 并读 cookie，会把**全站所有页面**（favorites / help / line 全景页这些本可静态化的页面）一起拖进动态渲染 —— 这是真实的回归，不是理论代价；
- PWA `start_url = "/"` ⇒ 「打开应用」的语义本来就落在首页；深链进 `/favorites` 拿不到开屏，可接受。

**版本门（「首装 + 大版本更新才播叙事版」）的三种做法**：

| 做法 | 效果 | 代价 |
|---|---|---|
| **A. Cookie 门（推荐，已定为主门）**：服务端读 `mmap.splash.ver` cookie，≠ 当前版本 ⇒ SSR 直接输出**动画版**；客户端播完写回 cookie | 动画**从首帧就开始**，零 hydration 依赖；且不会有「先看到完整 logo、然后清空重画」的跳变 | 首页读 cookie（已是 dynamic，零代价）；每请求多约 20B 请求头 |
| B. localStorage 门（前端在 hydration 后决定） | 实现最简 | 动画要等 hydration 才开始（约 200–600ms）；且会看到「完整 logo → 清空 → 重画」一次跳变（SSR 画的是完整 logo，动画第 0 帧是空 M）——每次大版本更新出现一次 |
| C. 根 layout + cookie | 深链也覆盖 | **把全站拖进动态渲染**，不建议 |

**推荐 A**。若团队想省掉 cookie，B 也可接受 —— 跳变每次版本更新只发生一次，且发生在「用户刚打开应用、正盯着开屏看」的时刻，观感可辩解；但要**当作已知取舍写下来**，不要当成没注意到。

**版本键与主门（已冻结，见 `02-竞品调研-行业做法.md` 附录 A5 + 本节裁决）**：

- **主门 = cookie，单门**：服务端读 cookie **`mmap.splash.ver`**，≠ `appVersion` ⇒ SSR 直接输出动画版；客户端播完/跳过后写回。裁决理由：SSR 首帧要求门判定在服务端（请求时定输出），localStorage 请求时不可达，做不了主门；**不做双门**——cookie 与 localStorage 各存一份会引入两个真相源，同步缺陷面大于任何收益。
- **此前的 localStorage 键 `mmap.splash.lastVersion` 提案作废**（存储介质定为 cookie，键名随介质走）。QA 预置/断言对象 = cookie（`context.addCookies`）；「存储不可用」模拟对象 = cookie 而非 localStorage。
- 值 = `appVersion`（构建期自 `package.json` 注入，与 DSAT UA 同源）字符串精确比对；**禁布尔**——「播没播过」的布尔值同样无法表达「大版本更新后应重播」，这条禁令在 cookie 介质下同等适用。键名为实现侧**导出常量**。
- 已知取舍（写入实现注释，不当没注意到）：写回走 `document.cookie` 时，Safari ITP 对 JS 写入的 cookie 有 7 天上限 ⇒ 最坏情况是 Safari 用户 7 天后同版本重播一次开屏（约 1s 一次性动画，观感可辩解）。不为此增设「写 cookie 端点」——为一个边缘观感加一个端点是过度设计。MVP 后若要彻底规避，用既有请求链路的服务端 Set-Cookie，不属于本期。
- 通用纪律不变：**任何「是否做过 X」的持久标记，键里必须带版本**；配套只读钩子 **`body[data-app-version]`** 本期落，为页面内唯一可读版本来源（与服务端门同源同一个构建期常量，不引入第二个版本来源）。

**「动画资源就绪晚于首帧怎么办」——按推荐的实现方式，这个问题不存在**：
- keyframes 写进 `globals.css`（本来就是首帧关键路径，**零新增请求**）；
- SVG 标记内联在 HTML 里（**零新增请求**）；
- ⇒ 资源在首帧**构造性就绪**。前提是遵守第三节的体积红线（不拆独立文件、不动态 import）。

**SSR 闪烁**：SSR 输出什么、客户端接手什么，分工如下：
- **SSR（服务端）**：无条件输出完整动画层（首帧即动画第 0 帧，纯标记 + CSS，零 JS 依赖）；
- **客户端**：只做三件事——①reduced-motion 判定（`matchMedia`，CSS 设不了 data 属性）；②播完/跳过/bfcache 后**移除容器**；③写 `data-splash-state` 与 `body[data-app-version]` 两个只读钩子。动画本身**完全由 CSS 驱动**，JS 不参与逐帧。
- 跳过的可交互性：**容器必须从 DOM 移除**（不是 `opacity:0` / `pointer-events:none`），否则"跳过后首屏立即可用"无法成立。这一点与附录 A5 的 `data-splash-state` 契约对齐。

**加载小循环（48px，真实加载 >300ms 才出现）**：
- 用 `setTimeout(300)` 门控：300ms 内完成就不显示（避免快路径闪烁）；
- reduced-motion 下的处理见第四节：mark 内部动画全部 `animation: none` ⇒ 静态 mark，另需隐藏光点/亮点/涟漪三类末帧不该出现的元素（已落地）。
- 详细两形态约束见下方「加载态两形态」。

## 三、体积预算

| 项 | 量级 | 说明 |
|---|---|---|
| keyframes + 降级规则（进 `globals.css`） | 约 2–3KB 原始（br 后 <1KB） | `globals.css` 本来就是首帧关键路径 ⇒ **零新增请求** |
| 内联 SVG 标记（进 HTML） | 约 1–2KB | HTML 22.7KB → +7% ⇒ 解析增量 ~1ms |
| 客户端逻辑（版本门 + 跳过 + 移除 + 写 cookie + 钩子） | 约 1–2KB | 并进既有 chunk 或新增 ~1KB gzip 小 chunk |
| **合计** | **< 6KB 原始** | 相对 223KB br JS / 22.7KB HTML，**首帧影响可忽略** |

**实现红线（四条，都是硬的）**：
1. **不引第三方库**（Lottie 已排除）——本项目 JS 预算 223KB br，任何动画库都是数倍于本动画本身的体积；
2. **不做动态 import、不拆独立 .css/.js 文件**——动画资源必须随首帧到达（见第二节），动态 import 会把它推迟到 hydration 之后；
3. **颜色一律走 `.brand-*` class 绑 token，禁止写在 SVG 表现属性里** —— `BrandMark.tsx` 注释里有 headless 实测结论：Chromium 对颜色类表现属性能解析 `var()`，但长度类不支持、跨引擎无统一保证（w3c/svgwg#1031）。动画里新增的元素（光点、涟漪、钉）必须沿用同一模式；
4. **动画属性选择**：`offset-distance` / `transform` / `opacity` 是可合成属性，光点与涟漪走这些；`stroke-dashoffset` 会触发逐帧重绘（不可合成），但 60–96px 的 logo 尺寸下开销可接受——**不要**因此改用 canvas；同样**避免**对涟漪用 `filter: blur()`（重绘大户，低端机会掉帧，涟漪用 scale + opacity 即可）。

**加载态两形态（规格 §5.1，实现约束）**：

> **修订记录**：本表初版为「B = 56px + 屏幕中心」，**已作废**。作废原因：那套约束基于「需要在屏幕级 fixed 层做交叉淡化并几何对齐」这一错误前提。核实后的实际结构不同（见下），无需任何几何对齐。

|---|---|---|---|---|---|---|

> **全站扩展（负责人需求，规格 §12 v1.9）**：全站加载等待统一换 BrandRouteLoader，slot 枚举扩展为 **`map-cover` / `request` / `list` / `detail`** 四值。`list`（结果列表等待卡）、`detail`（详情/card 页）**仅用于 QA 定位断言**——门控行为与 `request` 完全相同，实现是表里多落一行分支，**不得为四个 slot 写四种门控**。

**GATE_MS 护栏（两档语义不同，勿当作同一参数调）**：

| slot | `GATE_MS` | 为什么 |
|---|---|---|
| `map-cover` | **0，任何 >0 都算回归** | cover 容器随 `phase==="loading"` 即刻出现（含底色），cover 的存在**本身就是"确实在加载"的信号**，不需二次门控；且开屏 z-200 全屏遮着这段加载，门 >0 只会在**跳过路径**（约 100ms 撤走）重开空窗——QA 实测 N1：跳过后空窗 147ms（+115ms 撤走 → +262ms 才有内容），根因就是 300ms 门。 |
| `request` / `list` / `detail` | **300，不可改小** | 用户**主动触发**后的等待：快路径（<300ms）闪一下 M 是噪音（NN/g：<1s 无需反馈）。这三类位置没有"容器已出现"的前置信号，门控是防闪烁的唯一手段。 |

**⛔ 实现红线：查表缺 key = 门控静默失效（规格 §12.5 v1.9.1）**——`GATE_MS_BY_SLOT[slot]` 若 slot 加了枚举值而表里没加行，返回 `undefined` ⇒ `setTimeout(fn, undefined)` **立即执行** ⇒ 新位置门控消失、光点闪现，**无任何报错**（tsc/build/普通断言全绿——本轮反复撞击的静默缺陷类型）。

**已落地（2026-11-02 核）**：表类型为 `Record<NonNullable<BrandRouteLoaderProps["slot"]>, number>`（`BrandRouteLoader.tsx:52`），**缺行在编译期直接红**（对象字面量缺键 ⇒ TS2739），四行全齐（map-cover/request/list/detail），已过 build。**后续新增 slot 的纪律由此类型自动执行，不依赖"记得加行"**——编译器比人可靠。

**占位与指示分离（全站替换的通用规则）**：骨架干两件事——指示（"在加载"）+ 占位（防布局跳动）。换 BrandRouteLoader 时**指示换成 M 循环，占位改用「容器轮廓 + min-height」保住**，不是裸 M 换骨架 DOM。各位置 min-height：结果列表等待卡 112px、详情 120px、recommend 240px（规格 §12）。**⛔ ③④（recommend 的 `page.tsx` 骨架与 `loading.tsx`）必须同批替换**——`loading.tsx` 的注释明确"两层形状一致 → 骨架不跳动"，只换一层 = 自造跳动。这是全站替换最容易踩的坑。

**替换完成后的清理**：`rc-sk` 系列 CSS（L1718–1745 + `rc-shimmer` keyframes）整体删除（前端核实无其它引用后）；`--surface-dim` token **不动**（`.nav-map__cover` 在用）。新位置不新增任何 `@media` 块——reduced 下既有 `animation: none` 按类名自动覆盖，**不会复发"reduced 块重复"**。

**为什么 B 是"容器内居中"而不是"屏幕居中"——三条已核实的结构事实**：

1. `NavShell.tsx:42` 是 `import NavMap from "./NavMap"`，**静态导入非懒加载** ⇒ NavMap 在 SSR 首帧就在；
2. `NavMap.tsx:1622` 在 `phase === "loading"` 时渲染 `.nav-map__cover`；`globals.css:2185` 里它是 `position:absolute; inset:0; display:flex; align-items:center; justify-content:center; background: var(--surface-dim)` —— **容器内居中 + 不透明底**，从 t=0 就在；
3. 开屏是 `fixed; z-index:200` 盖在它上面 ⇒ **淡出即暴露，天然过渡**，不存在"两个图层要几何对齐"的问题。

⇒ 语义也对齐：加载态描述的是「**这一块区域**在加载」，放到屏幕中心会让用户误以为「整个 App 在加载」。

**实现（必须"替代"不是"叠加"，三个细节）**：

1. **`.nav-map__cover` 里的 `rc-sk--big` 是 62×30 的 shimmer 骨架矩形，不是指示器** ⇒ 用 `BrandRouteLoader` **替换**它，两者**不可并存**（两个活动指示器同屏 = 信号冲突）。视觉重量相当（48×48 略高约 18px，cover 绝对铺满可吸收），且从"无意义占位"升级为"有品牌含义的活动指示器"，净收益。
2. **布局：cover 是 `flex-direction: column; gap: 8px`（图标上、文案下）**，而 `.brand-loader` 当前是 `display: inline-flex; align-items: center`（横向）⇒ 宿主需覆盖为纵向，**或组件加一个 direction prop**。⛔ **不得**把 `.brand-loader` 全局改成 column（A 形态要横排）。
3. **⛔ a11y（纯视觉讨论最容易漏的一条）**：`BrandRouteLoader` 自带 `role="status" aria-live="polite"`，其中 svg 是 `aria-hidden`。若文案留在组件**外面**（cover 那个 span），**live region 内容为空 ⇒ 屏幕阅读器什么都不播**，且「定位中…」→「地图加载中…」的切换也不会播。
   ⇒ **把 cover 的文案作为 `label` 传进组件**（组件已支持），文案落进 live region 内部。**视觉不变**（正好匹配 column 布局），且让 A/B 的 a11y 逻辑统一。
   ⇒ ⛔ 不要把 `aria-label` 挂在那个 svg 上 —— 它 `aria-hidden="true"`，不参与可访问名称计算。

**KEEP 的两条**：
- **不加蒙层、不加卡片底/圆角/阴影、不降 opacity**："不抢"靠无底色、无边框、单色图形达成；虚弱图标在慢网下反而易被读成"故障"。加蒙层 = 又造一次遮挡，等于把开屏的遮挡延续一段，违背"开屏撤走就还给用户地图"。
- A/B 同一个 mark、同一套 1200ms keyframes，只有定位与 `label` 差异 ⇒ 用户不会感知到"两种加载动画"。

**B 为什么没有对比度问题（时段决定的，不是"凑合能看"）**：加载态存在的时段恰好是"**地图未就绪**" ⇒ 底下是 `.nav-map__cover` 的**纯色容器底**，不是彩色底图；等底图渲染出来，加载态已撤。

**两层底色衔接（已裁定：不改任何 token）**：`.nav-map__cover` 用 `--surface-dim`，开屏 overlay 用 `--bg`，实测对比度浅色 1.075:1（几乎不可见）、深色 1.348:1（可察觉但方向正确：页面底更暗 → 容器面略亮，读作"地图区域浮现"，且发生在 100ms `opacity` 渐变内，是溶解不是切换）。

- ⛔ **不改 `--surface-dim`**：它在 `globals.css` 用 20+ 处，是全局"次表面"语言；为一次开屏改它会波及全站，且破坏 cover 的形体感（与 `--bg` 同色就失去"这里浮起一块地图区域"的观感）。
- 若第二轮实测深色下像"面板突然亮起"：**改 overlay 背景 `--bg` → `--surface-dim`**（开屏与 cover 同色，跳变归零），**不是改 cover**——改动画层只影响一处、可回滚。

**一条必须实测的残留（开屏 → 地图 cover 的重叠窗口）**：overlay 是**不透明** `background: var(--bg)`，在 860–960ms 淡出时 `opacity` 1→0 ⇒ **大 M 与底下 cover 里的小 M 会同时部分可见约 100ms，两者中心相距约 45px**（overlay 居中于屏幕，cover 居中于地图容器，后者 `top:0; bottom: calc(tabbar + safe-bottom)`）。

- 判断：**预计不成问题**——这 100ms 是透明度溶解、不是位移，人眼对"同形状不同透明度"的容忍度远高于"同形状不同位置"。
- **但必须实测**：第二轮走查截 880ms / 920ms 两帧确认。若双影明显，修法是**压缩重叠窗口**（overlay 淡出 100ms→60ms，或起始提前到 840ms），**不是挪位置**。

附加三条工程纪律（沿用项目既有模式）：
- **mask id 必须唯一**：`BrandMark.tsx` 用 `useId()` 生成 mask id，首页同时存在多个品牌 SVG ⇒ 开屏自己的 mask 不能用固定 id（会撞）；
- **层级**：开屏层 z-index 必须高于全站最高层（车辆 130）——项目层级纪律是显式数字，别用"随便一个大数"；
- **光点置于 mask 组之外**（设计已定夺，规格 v1.1 §2）：光点全程可见、不参与挖孔，z 序在路线之上；孔内穿越的"停靠感"由折点站环脉冲承担（时刻见规格 §4），不做光点闪没。实现上少一个 mask id 跨实例同步点。

**首帧变体（已采纳，规格 v1.1 §3）——与 SSR 静态层的衔接约束**：
- 动画第 0 帧 = 站环 + 钉（含字标）就位、仅 M 为空；背景与 SSR 静态开屏同色 ⇒ 静态层 → 动画层的切换**除 M 外像素级一致**，M 消失待重画读作有意开场，不存在「整体清空重画」跳变；
- 原站环充能段删除，腾出的时间给 M 描边（节奏与各段时刻见规格 v1.3 §4，此处不复制）。

## 四、prefers-reduced-motion —— 项目有全局开关，但**开屏仍需补一个专用块**

`grep` 结果：`globals.css` 里有 **9 处** `@media (prefers-reduced-motion: reduce)`，其中 `:541` 是**全局杀开关**：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    ...
  }
}
```

**初版在这里给出的结论是错的，已被设计师的走查推翻（缺陷编号 D1）。以下是修正后的版本。**

**初版错误结论**：「reduced-motion 用户的动画会被压到 0.01ms 单次 ⇒ 描边瞬间画完、光点瞬间到位 ⇒ 显示静止末帧自动达成，不需要为开屏单独写 `@media` 块」。

**为什么错**：杀开关清的是 `animation-duration`，**没有清 `animation-delay`**。duration 变成 0.01ms，但 delay 原样保留 ⇒ **每个元素在它自己的 delay 到点时才瞬间跳到末帧**，而不是统统在 t=0 完成。

> 数值口径：本节引用的 delay 值（钉 600ms 为其最大者）来自 `globals.css` 实值，**唯一数值源是 `05-设计-开屏与加载动画-规格.md` §4**；此处只引用解释本缺陷因果所必需的那个值，不复述完整时刻表。各段具体时刻随视觉迭代会变（本轮已发生过一次 416→310ms 的修正），要核请查规格。

⇒ reduced-motion 用户实际看到的是**长达 600ms 的"半成品"画面**，且是**分阶段跳变**的：

| 时刻 | 画面 |
|---|---|
| 0 → 钉 delay 到点前（600ms） | M 路线已画完、站环在、光点停在路径末端、孔内亮点可见、**钉完全不可见**（`both` 的 backwards 分支把它钉在 `scale(0)`）、涟漪是一圈低不透明度的小环 |
| 途中 | 折点站环脉冲闪一下、孔内亮点灭、光点消失（各自 delay 到点时一次性跳变） |
| 600ms | **钉凭空弹出**（`scale(0)` → `scale(1)` 一帧完成） |
| 收起 | 涟漪消失、覆盖层淡出、容器移除 |

这不是"静止末帧"，是**一个缺了钉子的 logo 挂 600ms 后钉子突然出现**——比不给动画更糟，且它是静默的（不报错、tsc 与构建全过）。

**修正后的红线（已实现，验收单独核）**：

1. **reduced-motion 专用块让 mark「首帧即末帧」**。实际落地方案（`.brand-splash__mark * { animation: none !important }`）比"归零 delay"更彻底：动画全关 ⇒ 元素取自然值 = 静态完整 logo（M 全描边 + 两站环 + 钉）。
   - **⚠️ 通用陷阱：`animation: none` ≠ 元素消失，而是"停在初始帧/自然值"。** 所以 reduced 降级的正确写法永远是「先 `animation: none`，再显式给末态样式」，缺一不可。本项目的三处实例：光点靠 `offset-path` 定位，无动画时停在 offset 0 = 路径起点 (12,48)，**会以一个小圆点僵在起点站环处**；孔内亮点无动画时取自然 `opacity`；涟漪同理。三者均须显式 `opacity: 0 !important` 兜住。
   - **覆盖层仍用同名 `brand-splash-exit`**：JS 靠 `e.animationName === "brand-splash-exit"` 匹配来移除容器，**改名 ⇒ 容器永不移除**。
   - ⚠️ **实际实现把 reduced 下 overlay 的 exit 改成 `100ms linear` 无 delay**（而非正常态的 860ms delay）⇒ reduced 用户约 100ms 就看到内容，不用白等 860ms。**这是有意的改进**：reduced 用户已无动画可看，让他对着静止 logo 白等 860ms 是零信息增益的纯等待；100ms 保留了"溶解"而非"硬切"的最小可信时长。
   - **⚠️ 对 QA 的两条影响**：① P4 若断"容器按正常时机（860ms）移除"会**红**（实际 ~100ms）⇒ 改断「≤200ms 移除」；② 末帧采样窗口从 ~700ms 缩到 **0–100ms** ⇒ 700ms 时容器已不在，取不到 computed style 会假红。
   - **⚠️ 断言方法要求（避免偶发红）**：`data-splash-state` 在 `useEffect`（paint 之后）写入，弱设备 hydration 可能晚于固定采样时刻 ⇒ **必须用 `waitForFunction` / MutationObserver 等状态出现，不得在固定 t 采样**。核查确认实现侧不存在"容器先移除、状态没写"的竞态：状态写入在 effect 顶部（`:60`）同步执行，而所有 `removeNow()` 调用点（`:90/:98/:105/:134`）都在其后。
2. **`animation-fill-mode: both` 是强制，不能只写 `forwards`**。`forwards` 只有 forwards 语义，**delay 期间元素按基础样式渲染**——钉在 0–600ms 会以 `scale(1)` 完整可见，600ms 突然跳 `scale(0)` 再弹回 ⇒ **钉子先出现、消失、再出现**。`both` = backwards + forwards，delay 期间钉在 `0%` 关键帧（`scale(0)`），这才是"未开始"的正确表现。
   ⇒ 修订本人初版措辞：不是「`forwards`（或等价 `both`）」，而是「**必须 `both`；只有 `forwards` 会产生 delay 期提前可见的缺陷**」。当前实现全部 `both`，正确。
3. `data-splash-state` 契约以 `02-竞品调研-行业做法.md` 附录 A5 + **§五 终态**为准：**4 值** `playing / skipped / done / reduced`。要点：
   - 互斥优先级 `skipped > done > reduced > playing`，**仅同一挂载实例内**比较；
   - `reduced` 的语义：reduced-motion 下**自然播完记 `reduced`**（不是 `done`），用户主动跳过记 `skipped`（跨 reduced 与否）；
   - **容器钩子 `[data-splash-root]`**：挂在覆盖层容器上、随容器生灭，供 QA 稳定定位（样式类不可靠，会随改版重命名）；
   - 「点击后 ≤120ms 可交互」的双条件断言：`data-splash-state=skipped` **且** `document.querySelector('[data-splash-root]') === null`；明文禁止 `visibility:hidden` / `opacity:0` / `pointer-events:none` 三种假移除；
   - `reduced` 的取值需 JS 用 `matchMedia('(prefers-reduced-motion: reduce)')` 判定（CSS 设不了 data 属性）；
   - **只读钩子 `body[data-app-version]`**（保留）：构建期注入 `appVersion`，用于线上排障确认构建与用例记录。**不参与任何判定，不属开屏验收范围**。
4. **加载小循环在 reduced-motion 下必须是静态 mark，不做"小幅度呼吸"**。设计侧已主动撤回早前"光点呼吸 0.7↔1"的口径 —— 呼吸同样是 motion，用户明确要求减弱动态效果时给持续脉冲就是违反诉求本身（"幅度小到无害"是自我说服）。正确做法：**完全静止 + 文本承担存活信号**（A 的可见 `label` / B 传入 `label` 落进 live region）。

| `sessionPlayed` 模块标记 | **已物理删除** | 结构承载"已播"（不重挂即不播），不需要可变状态 |
| bfcache（`pageshow.persisted`） | 只 `removeNow()`，**不写状态** | 容器早已不在快照里，移除即可 |
| 配套只读钩子 | `body[data-app-version]` | 构建期注入，不参与判定 |

**P1c 的正确写法（本轮最容易写错的一条断言）**：

layout 方案下「客户端路由不播」**不产生任何状态写入** —— 组件不重挂，`data-splash-state` 停在上一次的值（多为 `done`）。因此：

- 断 `state === "blocked"` ⇒ **永远红**（该值不存在）；
- 只断 `[data-splash-root] === null` ⇒ **有效**，但必须配**前置正向**（本轮此前已确认过 root 出现过，P1/P1b 已验），否则"从没渲染过"与"渲染后被正确抑制"不可区分；
- 更稳的写法（QA 已采用）：断「`playing` 整轮出现次数 === 1」+「导航后 root 不存在」。

**为什么「断行为」优于「断状态值」（本轮最可复用的一条）**：`blocked` 只能证明"到了但没播"，`playing` 出现次数直接证明"没再播"。更关键的是**枚举本轮从 4 → 5 → 4 翻了三轮** —— 若断言绑状态值，每轮都要重写一批用例；绑行为则一条都不用改。状态值会随实现方案变，**行为不会**。

**P1d（深链整页加载也播）的定性：回归守卫，不是待修功能**。它在当前 layout 方案下**应绿**（深链 `/help`、`/line/MT1` 确实会播）。它红只有一种可能：**有人把挂载点挪回 `page.tsx`** —— 那时深链内页完全不播，违反「整页加载都播」这条结构特征。**一条断言的价值不等于"现在红不红"，而等于"它能阻止哪种具体的退化"** —— 挂载点这个决定本轮翻了四次，没有断言钉住它，第五次翻的时候没人会知道代价。同 P9（防双挂载回潮）。

**「绿断言该不该留」的判据（供后续所有迭代复用）**：

> 一条绿断言的价值 = **它钉住的退化有多可能发生** × **发生后有多隐蔽**。

不是所有绿断言都值得留。P9（双挂载）与 P1d（挂载点回退）两个乘数都大：挂载点本轮翻了 4 次 ⇒ 可能性高；失效都**静默**（双挂载肉眼看不出但吞点击；深链不播用户只当"今天没开屏"）⇒ 隐蔽性高。

反例：若一条绿断言钉的是"几乎不会发生、且发生了立刻可见"的退化，那它是负债（维护成本 > 保护价值）。

⇒ **判据不是"绿不绿"，是"静默 × 可能"。**

**代价（产品已知并接受）**：任意整页加载都播 960ms，含无地图页（`/help`、`/about`）与深链（`/line/MT1`、`/card`）。这是"每次进入应用都播"的直接后果。**不做路由白名单** —— 那等于把版本门换个形式加回来，且让"哪些页有开屏"不可预测。

**若 team-lead 最终仍要回退到 `page.tsx`**，三处必须同步改，缺一即成 bug：

1. `layout.tsx` 删 import 与 `<BrandSplash />`，`page.tsx` 加回；
2. **必须恢复 `sessionPlayed` 模块标记** —— 挂 page 时组件会重挂，删了标记则每次点底导回首页都重播 960ms；
3. 枚举回 5 值 + P1c 改断 `blocked`。

> ⚠️ **第 2 条的真实成本不是那 1 行变量，是它带来的 3 条必须同时成立的纪律**：① 置位只能在 `markDone()` / `skip()` 里（不能在 effect 开头）；② early-return 判据必须用「`overlayRef.current` 是否存在」而非标记；③ cleanup 必须可重入。三条缺任一条，dev StrictMode 遮挡缺陷就复发（effect 第二遍提前 return ⇒ 监听不重建 ⇒ 容器永留 DOM ⇒ 吞掉全站点击）。**这是 page 方案的持续正确性负担**，也是本轮最终选 layout 的实质理由——不是 layout 覆盖面更大，而是它把"已播"交给 DOM 结构承载，不再需要一个会过期的状态机。

**回退后的验证必须是两道，缺一会假绿**：

1. **先断容器真移除**：`next dev` 打开首页 → 等 2 秒 → 切 `/favorites` → 切回 `/` → 断言 `document.querySelectorAll('[data-splash-root]').length === 0`；
2. **再断可交互**：同一切回动作后，`elementFromPoint` 命中测试或点击底导，确认能点动。

> ⚠️ **为什么"能点动"单独不算过**：这个缺陷的触发依赖 StrictMode 双调用**真的发生**。若某次运行没触发（构建模式、React 版本、路由情况差异），即便 3 条纪律一条都没做到，页面也照样能点动 ⇒ 得出假绿。**只有"容器真的不在 DOM 里"才是纪律生效的直接证据**；"能点动"只是它的一个可观察后果，不是充分条件。
>
> 同型假绿：`opacity: 0` 的残留容器在**未加 `pointer-events: none`** 时仍会吞点击，但如果测试点的是覆盖层之外的空白区，也会"点得动"。所以命中测试必须**点在首屏内容上**，不能点空白。

### 一条仍然有效的历史结论（与挂载点无关，供后人）

**标记媒介若将来需要**，只能选「随 document 销毁」的媒介，不能选持久化媒介：

| 媒介 | 生命周期 | 满足「F5 每次都播」 | 结论 |
|---|---|---|---|
| 模块级内存变量 | 随 document 销毁 | **满足**（F5 ⇒ 模块重新求值 ⇒ 重置） | 唯一可用 |
| `sessionStorage` | 同 tab 跨刷新保留 | 破坏（F5 后被拦） | 禁止 |
| cookie / localStorage | 跨会话 | 破坏（P10 也会红） | 禁止 |

且若写标记：**不在 effect 开头置 `true`，只在 `markDone()` / `skip()` 里置 `true`**；early-return 判据用「`overlayRef.current` 是否存在」而非标记本身 —— 判据从"标记状态"换成"DOM 事实"，StrictMode 双调用天然无害（见 §〇之二）。

## 六、P5 / P7 / P10 三条硬约束的实现成本

### P5（动画不得推迟首屏渲染）—— 已天然成立，但有一条实现禁令

现状：无论挂 `page.tsx`（`<BrandSplash />` 与 `<NavShell />` 同级）还是挂根 `layout.tsx`（`<BrandSplash />` 与 `{children}` 同级），splash 都是首屏的**兄弟节点**，同一份 HTML 同时到达 ⇒ 动画层存在期间首屏（地图容器 + 底部面板结构）已在 DOM。

**禁令**：不得把 children 放进 splash 的条件渲染里（`{ready && children}`），也不得为等动画而延后挂载首屏。splash 只能是首屏的**兄弟**，永远不能是**祖先**。若将来挂载点变化，同样遵守此条。

### P7（动画结束但内容未就绪 ⇒ 接加载态）—— 行为**一直满足**，且已接入品牌加载态

**先更正本文初版的一个错判**：初版写「`BrandRouteLoader` 零引用 ⇒ 慢网下动画播完到首屏就绪的空窗**没有任何东西接住**」。这句是错的。核实后的事实：

- `NavShell.tsx:42` 是 `import NavMap from "./NavMap"`，**静态导入非懒加载** ⇒ NavMap 在 SSR 首帧就在；
- `NavMap.tsx:1622` 在 `phase === "loading"` 时渲染 `.nav-map__cover`：`position:absolute; inset:0` + 不透明 `--surface-dim` 底 + `rc-sk` skeleton + 文案「地图加载中…」/「定位中…」；
- 开屏 `fixed; z-index:200` 盖在其上 ⇒ 淡出即暴露 ⇒ **P7 的"不得空白"在产品行为上一直满足，从来没有空窗**。

⇒ `BrandRouteLoader` 的定位是**视觉升级**（把通用 skeleton 换成品牌 M 循环），**不是 P7 的补漏**。它的缺失不会造成空白，只会造成：
1. 品牌语汇不连续（开屏是 M 动画，加载态是通用 skeleton）；
2. **QA 的 P7 没有断言靶子** —— `[data-loader-root]` 不存在，断言无处落。

**因此 P7 的正确落法（三件，缺一不可）**：

1. **`active` 绑真实信号**：`NavMap.tsx:385` 的 `phase === "loading"`（全站唯一可机验的地图就绪信号），**不要**另造定时器，也**不要**绑 `splashGone`（后者会造出 960–1260ms 真空窗，正是 P7 要禁的）。
2. **渲染位置**：在 `.nav-map__cover` 内部**替代** `rc-sk`（文案保留），天然继承 `absolute; inset:0` 的居中与不透明底，不新增定位样式。见 §三「加载态两形态」。
3. **钩子**：`[data-loader-root]` + `[data-loader-mode="loop"]` + `[data-loader-slot]`。

现状（`NavMap.tsx:1633`）：`<BrandRouteLoader active size={48} slot="map-cover" label={locating ? "定位中…" : "地图加载中…"} />`，外部 span 已删（cover 内只剩 loader，注释含 a11y 理由）。核对结果：

⇒ **P7 三层验收全部可跑**：① 行为层（开屏容器移除后 cover 仍在且文案非空）；② 钩子层（`[data-loader-root][data-loader-mode="loop"][data-loader-slot="map-cover"]`）；③ a11y 层（`[data-loader-root]` 的 textContent 非空——**不需要独立钩子**，见下）。

**「要不要为 label / cover 另加钩子」的裁决：不加**（QA 曾建议 `data-loader-label` / `data-cover-root`）：

- **a11y 断言**：label 由组件渲染在 `[data-loader-root]` **内部** ⇒ 定位 root 后读 `textContent` 即可，等价且零新增钩子；
- **cover 定位**：`map-cover` 位门控为 0 ⇒ loader 与 cover **同帧出现、同源消失**（都随 `phase` 生灭）⇒ `[data-loader-root]` 存在 ⟺ cover 存在，一个钩子等价两端；
- **原则**：钩子是**契约面**，每加一个都是长期维护承诺（命名、文档、QA 迁移）。项目纪律是"定位页面元素用 data 钩子"，不是"每个元素都配钩子"；且 P4b 已确立"取样式值用样式类、定位元素用 data 钩子"的区分——label 的文本内容属于前者。**钩子数量最小化**与"钩子必须是契约"是同一条纪律的两面。
- **⛔ 例外条款（QA 补强，P7c 实证）**：**当断言的目的本身就是验证两个机制的同步性时，检测器必须独立于被验证方** —— 否则失同步时两者一起缺席，断言恒真，抓不到本来要抓的 bug（"让被告兼任法官"）。实证：`GATE_MS=300` 时代 cover 存在而 loader 不在**真实发生过**（N1），若 P7c 用 `[data-loader-root]` 定位，该缺陷复现时断言恒真。⇒ P7c 保留 `.nav-map__cover` 样式类定位是**有意的例外**：它定位的是一个"其存在性本身待验证"的元素，不适用"定位应存在元素用 data 钩子"的前提。两条的适用边界由断言**目的**决定。

**关于钩子的裁决（不采用 `data-loader-state`）**：该组件在 `!active || !visible` 时 `return null`，「未加载」在 DOM 里根本没有节点 ⇒ `state="idle"` 不可表示，属性只能恒为 `"loading"`，形成恒真断言（永远绿，等于没断言）。`mode` 携带真实信息，且 06 §6 已按 `mode` 写。`slot` 用于消歧两个调用点，避免 `querySelectorAll('[data-loader-root]').length` 含混。

### P10（不得新增开屏相关持久键）—— 无门后天然成立，但需一处守门

版本门代码已全部移除（`src/lib/splash/version.ts` 只剩 `APP_VERSION` 常量，注释明确「不要加回来」；`grep` 确认 `src/components/brand/`、`src/app/page.tsx` 无 `document.cookie` / `localStorage` / `sessionStorage` 写入）。
