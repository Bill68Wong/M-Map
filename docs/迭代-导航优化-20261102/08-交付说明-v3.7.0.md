## 三、上线后必须线上/真机确认的清单

### 1. 函数区域真的搬到香港
- **现象**：用户无感
- **通过**：`curl -sI <域名>/api/health | grep -i x-vercel-id` 前缀为 `hkg1`；`/api/health` 的 `regions` 为 `["hkg1"]`
- **失败最可能**：Hobby 拒绝该配置导致部署在 build 前失败（回滚 = 删 `vercel.json` 的 `regions` 重部署）

### 2. 冷启动耗时真降
- **通过**：`stats.staticMs` 显著低于基线（基线有 1725/2197/3162ms 尖峰）；热态 P50 ≤ 2000ms、冷态 P50 ≤ 5000ms（`PERF_BASE` 指预览域跑 `.verify/perf/measure-nav.mjs`）
- **失败最可能**：pooler 对 hkg1 来源有额外握手成本

### 3. 静态缓存真的写进去了
- **通过**：`GET /api/health?warm=1` → `cache.staticRows.status === "ok"` 且 `sizeBytes ∈ [0.8MB, 2MB)`
- **注意**：**本地 tsx 必为 `error`**（非 Next 运行时无 `incrementalCache`），只认部署域名
- **失败最可能**：`skipped-oversize`（超 2MB）或 `error`（Data Cache 抛错）

### 4. 几何缓存版本令牌没打爆查询量
- **通过**：Supabase 查询数同口径对比，增幅 10~20% 量级
- **失败最可能**：令牌 5s 进程缓存失效，每帧都新查

### 5. 匹配算法上线方式（**待决策**）

| 方式 | 用户可见影响 | 能拿到什么数据 | 改代码 | 出结论 |
|---|---|---|---|---|
| **A. 开关关着 + 影子日志** | 无（算出 high 也不锁牌） | 完整分布：`confidence/score/margin/logL/frames/poolSize/reasons/ranking`，可与人工核对车牌 | 约 15 行临时日志 | 3 趟乘车（含 1 条环线、每趟 ≥6 分钟）≈ 半天 |
| B. 直接开开关 | 有（high 会锁牌，报站改由车牌驱动） | 只有最终行为；**拿不到 medium 占比**（medium 不锁牌、不留痕） | 不用 | 3 趟，但「中置信频率」只能主观观察 |
| C. 本轮不做 | 无 | 无 | 不用 | — |

**开启门槛（A/B 通用）**：高置信率 ≥70%、**误锁数必须为 0**、medium ≤30%、low ≤10%。
**关键差异**：A 与 B 不是「保守 vs 激进」，而是**能回答的问题不同** —— 只有 A 能给出「中置信频率」的量化判据。

### 6. 中置信频率
- **通过**：`data-match-pending="1"` 累计时长占 riding 时长 <20%，且不应持续 >60s
- **失败最可能**：池里停靠/总站车多（1 帧 ⇒ 撞 `frames ≥ 2` 门）；或 σ_p 过小

### 7. 折叠栏首次展开延迟
- **通过**：详情主体 ≤1s（改前被折叠栏拖到 3.8s）；展开后报站文案 ≤3.5s；**等待期不得显示「暂无到站信息」**
- **注意**：本次改的是「把折叠栏移出首包」，**没有**降低折叠栏自身耗时

### 8. 断网 / 切后台恢复
- **通过**：切后台 2 分钟后回前台 2s 内发出一次车辆请求；断网时 `data-veh=stale/failed` 且蓝点不消失；恢复后回 `fresh`

### 9. 高德配额
- **通过**：调用量与改前持平；`stats.multiStrategyMs > 0` 的比例不过高（说明补查频繁触发）

### 10. 区分「获取失败」是网络问题还是内部 bug

**当前代码形态**（`:727` 写 `fresh` → `:861` catch 覆盖成 `failed`，同一 tick 内）：

| 观察 | 判定 |
|---|---|
| Network 面板 `200` + 有 `vehicles`，但 `data-veh` 最终 `failed` | **代码异常**（帧已到手又抛） |
| 从不出现 `fresh`，一直 `failed` + `net::ERR_*` | **网络问题** |

⚠️ 不要用「恢复网络后回 fresh」判断「是网络问题」—— 代码异常也会先写 fresh。

## 四、本轮推翻的既有判断（供后续参考）

| 原判断 | 实际 | 依据 |
|---|---|---|
| 静态数据 3.07MB 超 2MB 上限、必须拆包 | **1.20MB，一直正常**；3.07MB 是 v3.6.1 之前的历史值 | 逐表实测体积 |
| `issuedAt` 作为缓存命中下界（防旧数据） | **命中率≈0**，会让每次导航真打高德、提速归零 | 缓存条目必然早于本次发起时刻 |
| 导航进度几何缓存只影响视觉 | **参与锁车判定**；失效方向是「拒绝锁车」 | `p` 是形状派生量 |
| `mileM` 字段可让两轴可比 | **原点不同**（线路起点 vs 上车站）⇒ 系统性偏差数百米至数公里 | 架构师复核 |
| 改阈值 2→1 与删整段门是「互补变异」 | **数学等价**（前置守卫保证 `frames ≥ 1`，门恒真） | 两种变异红条完全相同 |
| `catch` 到 `TypeError` 即代码异常 | **浏览器网络失败抛的正是 `TypeError: Failed to fetch`** | 需按「`r.json()` 是否已成功」判位置 |
