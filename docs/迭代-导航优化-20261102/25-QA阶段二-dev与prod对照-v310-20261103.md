### 2.1 AC-25 / AC-26（拖图后 `data-map-follow` 应变 `free`）— **dev-only 环境差异**

### 2.4 AC-44（riding 当前乘车段 `data-nav-leg`）— **前提不成立，不可判，非缺陷**

dev3 实测：`riding` 可达（`evidence=manual(手动标记上车)`），但 `data-nav-leg=null`。

**直接原因（代码级，非"门控未满足"这种模糊描述）**：`NavDetailBody.tsx:540-543` 只在

```js
track && track.phase === "riding" && track.prog && i === track.legIndex
```

成立时才把 `nav`（内含 `legIndex`）传给 `NavStrip`；`NavStrip.tsx:167` 再
`data-nav-leg={nav && nav.legIndex != null ? String(nav.legIndex) : undefined}`。
本轮 `track.prog === null` ⇒ `nav === null` ⇒ 属性**按设计缺省**。

而 `track.prog` 为 null 的直接原因是本轮**没有走到自动上车**：R1（车辆帧自动判定）在本轮窗口内未命中，
riding 是**手动标记上车**进入的，此前 `youmark=0`、四态计数全 0、`state=built`（几何够）——三点互相印证。

⇒ 与 `07 §1`「仅当前乘车段写」一致，**不是缺陷**；但 AC-44 在本轮配置下**不可判**，
按纪律记 **FAIL / 未覆盖**（生产上 26 路有在途车 `MY7560`，真机/等待自动上车命中后才能验）。

### 2.5 D-8（单码标签圆角 = 6px）— **过期判据：6px 在 group 上，不在 seg 上（两环境同红）**

运行期实测（dev 与 prod 一致）：

```
.route-stack__group  → border-radius: 6px · overflow: hidden
  .route-stack__seg  → border-radius: 0px（恒为 0，这是它的常态）
```

`globals.css:3377-3381` 把 `--radius-chip` (6px) 给了 **`.route-stack__group`** 并用 `overflow:hidden` 裁角；
`seg` 本身从不带圆角。脚本却读 `seg` 的 `borderTopLeftRadius` ⇒ 恒 0 ⇒ **必然红**。
**视觉要求实际达成**（单码块 = 6px 圆角外框 + 无斜切），只是断言读错了节点。
改法（待批）：改读 `.route-stack__group:has(.route-stack__seg:only-child)` 的 radius，并保留 `seg.clip === "none"`。
