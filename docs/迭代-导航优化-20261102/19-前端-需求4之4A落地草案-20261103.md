### 1.4 `cutColored(pts, iBoard, iAlight, loop)` — `:210-228`

| 分支 | 代码 | 语义 |
|---|---|---|
| 非环线 · `ib ≤ ia` | `pts.slice(ib, ia + 1)` | 正向切片，首点=board、末点=alight |
| 非环线 · `ib > ia` | `pts.slice(ia, ib + 1).reverse()` | **倒序切片**。几何点集与 `[ia..ib]` 相同，但顺序反转 ⇒ `showDir:true` 的**箭头方向相反**（这就是 D4-7「倒着开」的可视化机制，已确认 `nav-map-overview.ts:46/63` 两条 polyline 都开 `showDir`） |
| 环线 · `ia ≥ ib` | `pts.slice(ib, ia + 1)` | 前向弧 |
| 环线 · `ia < ib` | `pts.slice(ib).concat(pts.slice(0, ia + 1))` | **环绕弧**（后段 + 前段拼接） |

**关键结论（本轮新发现）**：环线分支**恒取「索引递增」那一条弧**，**从不**取反向弧。所以「取最短弧」**不可能**在 `cutColored` 里实现 —— 它只能通过**换一对 `(iBoard, iAlight)` 的趟次**来达成。⇒ `cutColored` 无需改动（这也让对拍用例 ③④⑤ 原样通过）。

## 2. 4-A 的三个变体（含实测对拍数字）

对拍方法：93 条线路 × 全部方向 × 站距 {1,2,4,8} 跳 = **9531 条样本**。
判据 `chainLen` = 站序上相邻站坐标链长（**独立于 shape 几何**）；`ratio = 弧长 / chainLen`，理想 1.0~1.6。
「过短回归」= `ratio < 0.5` **且** `board↔alight 直线 > 50m`（不落分支④）**且** 现状 `ratio ∈ [0.8, 2.5]`（现状本来是对的）。

|---|---|---|---|---|---|---|
| V0 现状 | 全局最近 + 索引定 wrap | — | 9531 | — | — | — |
| **V1 纯 min-arc** | 枚举全部 ≤tol 组合取最短前向弧 | 1366 | 8159 | 6 | **140** | 0 |

## 3. 复杂度上界（实测，非估算）

| 量 | 实测值 | 出处 |
|---|---|---|
| `route_shapes` 行数 / 线路数 | 117 / 93 | `.verify/_q4a-probe.ts` P1 |
| 单条 shape 顶点数 | min 48 · **p50 424** · p90 728 · p99 1033 · **max 1676**（26/0） | 同上 |
| 全部 shape 顶点总数 | 53 794（**单次 detail 只涉 1~5 条线** ⇒ 实际扫描量千级） | 同上 |
| 单站 ≤80m 内的「趟次」数 k | 实测 **1~4**（26 号线 alight 出现 4 趟） | P2 |
| 组合数 `kBoard × kAlight` | 实测 **最大 8**（8 个 (leg,shape) 对中） | P2 |
| 理论最坏组合数 | `k²`；环线单次往返 ⇒ k ≤ 2；某线路若来回共走同一条路 m 次 ⇒ k ≤ m。**取 k ≤ 4 ⇒ 组合 ≤ 16** | 推导 |

**复杂度结论**：`passesOnPath` 是 O(n)（一次扫描收集全部 ≤tol 顶点），枚举组合是 O(k²)（≤16），每组合的前向弧长是 **O(1)**（用预计算 `cum[]` 差分，**不做经纬度直线、不做逐点累加**）。
⇒ 单段总代价 ≈ `O(n) + O(k²)`，与原实现 `O(n)` **同阶**，实测可忽略（1676 点 × 5 段 ≈ 8k 次 `distM`）。
⇒ **不需要空间索引、不需要缓存、不做 Web Worker。**

**「最短弧」怎么算（定稿口径）**：
- 用 **`cumDistM(pts)` 预计算的沿索引累计里程**做差分，**不是**经纬度直线距离。理由：彩段是沿折线画的，用户看到的就是这条折线的长度；直线距离对绕行线路没有意义。
- 环线两条弧 = `forward = cum[ia] - cum[ib]`（`ia ≥ ib`）与 `wrap = total - cum[ib] + cum[ia]`（`ia < ib`）。**两者都是「索引递增」方向**，与 `cutColored` 的两个环线分支一一对应。
- `total = cum[n-1]`（闭合边 ≤ 25m 由 `LOOP_EPS_M` 保证可忽略）。
- **注意**：这里算的「弧长」只用于**择优打分**，不参与绘制（绘制仍由 `cutColored` 决定），所以两者不可能不一致。

### 4.2 新增两个纯函数（插在 `nearestOnPath` 之后，`:139` 后）

```ts
/**
 * ★ 4-A：返回 ≤ tolM 的**全部趟次**（按索引升序；簇内保留最近顶点）。
 *   `nearestOnPath` 原样保留 —— 它是对拍用例②的直测对象，也是 useRideTracking 的 import，
 *   **不要替换**（替换会同时改变「GPS 投影」「安全网」两处行为，超出本需求边界）。
 */
export function passesOnPath(
  pts: LL[],
  p: { lng: number; lat: number },
  tolM: number = TOL_M,
): { from: number; to: number; best: number; distM: number }[] {
  const q: LL = [p.lng, p.lat];
  const hits: { i: number; d: number }[] = [];
  for (let i = 0; i < pts.length; i++) {
    const d = distM(pts[i], q);
    if (d <= tolM) hits.push({ i, d });
  }
  const out: { from: number; to: number; best: number; distM: number }[] = [];
  for (const h of hits) {
    const last = out[out.length - 1];
    if (last && h.i - last.to <= PASS_MERGE_GAP) {
      last.to = h.i;
      if (h.d < last.distM) { last.distM = h.d; last.best = h.i; }
    } else {
      out.push({ from: h.i, to: h.i, best: h.i, distM: h.d });
    }
  }
  return out;
}

/**
 * ★ 4-A：前向弧长（沿索引递增；`cum` = `cumDistM(pts)`）。
 *   环线 `ia < ib` ⇒ 环绕弧；非环线 `ia < ib` ⇒ `Infinity`（倒序弧不算合法前向弧）。
 */
export function forwardArcM(cum: number[], iBoard: number, iAlight: number, loop: boolean): number {
  if (iAlight >= iBoard) return cum[iAlight] - cum[iBoard];
  if (!loop) return Infinity;
  return cum[cum.length - 1] - cum[iBoard] + cum[iAlight];
}
```

```ts
    // ① 原解（保持原语义，也是回落基准）
    const nb = nearestOnPath(pts, board);
    const na = nearestOnPath(pts, alight);
    if (nb.distM > tolM || na.distM > tolM) continue;      // ← 容差门原样保留

    const loop = isLoop(pts, shape.startStop, shape.endStop);

    // ② ★ 4-A：内层重选配对（详见 pickPair）
    const pair = pickPair(pts, board, alight, loop, tolM, mids);

    const candidate: ChooseShapeResult = {
      shape,
      dir: shape.dir ?? null,
      iBoard: pair.iBoard,
      iAlight: pair.iAlight,
      dBoard: nb.distM,        // ← 仍是「站点到线」的最近距离，语义不变（外层评分用）
      dAlight: na.distM,
      pts,
      loop,
      repicked: pair.repicked,
      orderViolations: pair.violations,
    };

    // ③ 外层择优 —— **完全不动**（score = dBoard + dAlight；并列优先正向）
    const score = nb.distM + na.distM;
    const forward = pair.iBoard <= pair.iAlight;
    const bestForward = best ? best.iBoard <= best.iAlight : false;
    if (
      score < bestScore - 1e-6 ||
      (Math.abs(score - bestScore) <= 1e-6 && forward && !bestForward)
    ) {
      best = candidate;
      bestScore = score;
    }
  }
  return best;
}

/**
 * ★ 4-A 内层配对：在**同一条 shape** 上挑一对 (iBoard, iAlight) 趟次。
 *
 * 择优序（字典序）：
 *   ① 站序违反数最小（中间站的最近投影须单调落在弧内）
 *   ② 弧长最短
 * 两道护栏：
 *   · `arc ≥ MIN_ARC_M`、`arc ≤ 现状弧 × MAX_GROW_RATIO`（只缩短不延长）
 *   · 无合法候选 / 站序判据不可用且超限 ⇒ **原样返回 nearestOnPath 的解**（= 现状，永不更差）
 */
function pickPair(
  pts: LL[],
  board: { lng: number; lat: number },
  alight: { lng: number; lat: number },
  loop: boolean,
  tolM: number,
  mids: { lng: number; lat: number }[],
): { iBoard: number; iAlight: number; repicked: boolean; violations: number } {
  const nb = nearestOnPath(pts, board);
  const na = nearestOnPath(pts, alight);
  const base = { iBoard: nb.idx, iAlight: na.idx, repicked: false, violations: -1 };

  const cum = cumDistM(pts);
  const curArr = cutColored(pts, nb.idx, na.idx, loop);   // ← cutColored 未改，可安全前置调用
  const curArc = curArr && curArr.length >= 2 ? cumDistM(curArr).slice(-1)[0] : Infinity;

  const kb = passesOnPath(pts, board, tolM);
  const ka = passesOnPath(pts, alight, tolM);
  if (!kb.length || !ka.length) return base;

  const midIdx = mids.map((m) => nearestOnPath(pts, m).idx);
  const n = pts.length;
  let chosen: { iBoard: number; iAlight: number; arc: number; violations: number } | null = null;

  for (const x of kb) {
    for (const y of ka) {
      const arc = forwardArcM(cum, x.best, y.best, loop);
      if (!Number.isFinite(arc) || arc < MIN_ARC_M) continue;   // 退化守卫（同顶点/相邻顶点）
      // 站序：中间站投影须单调且落在 [iBoard, iAlight] 内（环线展开到弧坐标）
      let violations = 0;
      let prev = x.best;
      const end = y.best >= x.best ? y.best : y.best + n;
      for (const mi of midIdx) {
        const idx = loop && mi < x.best ? mi + n : mi;
        if (idx < prev || idx > end) violations++;
        else prev = idx;
      }
      if (
        !chosen ||
        violations < chosen.violations ||
        (violations === chosen.violations && arc < chosen.arc)
      ) {
        chosen = { iBoard: x.best, iAlight: y.best, arc, violations };
      }
    }
  }

  if (!chosen) return base;                                        // 无合法前向弧 ⇒ 现状（非环线 reverse 就靠这一条）
  if (chosen.iBoard === nb.idx && chosen.iAlight === na.idx) return { ...base, violations: chosen.violations };
  if (Number.isFinite(curArc) && chosen.arc > curArc * MAX_GROW_RATIO)
    return { ...base, violations: chosen.violations };             // 只缩短不延长

  return { iBoard: chosen.iBoard, iAlight: chosen.iAlight, repicked: true, violations: chosen.violations };
}
```

### 4.4 `cutColored` `[不改]`（`:210-228`）

**一行都不改。** 理由：
1. 环线「最短弧」是**通过换趟次**达成的，不是通过换 wrap 方向（§1.4）。改 `cutColored` 属于多余风险。
2. 非环线 `iBoard > iAlight` 的 `reverse()` 分支**必须保留** —— 实测 21A（planId 900000）就是靠它才不降级：`iB=418 > iA=268`、`loop=false` ⇒ 合法前向弧数为 0 ⇒ `pickPair` 回落原解 ⇒ `cutColored` 走 reverse ⇒ 彩段 4537m（绕行比 1.59，合理）。**如果硬性禁止 reverse，这张卡会直接变「整线着色」。**
3. 对拍用例 ③④⑤ 直测 `cutColored` 三个分支，不动则 8 条断言原样通过。

> 关于「箭头倒着开」：`showDir:true` 确实会画反箭头，但那是**非环线且几何反向**才有的现象，属既有行为（D4-7）。4-A 的正确做法是**换趟次**（若另一趟存在），换不到时**保持现状**而不是硬反转。**建议另开需求**处理「dir 与 shape 存储方向不一致」（根治需要契约带 `dir`，见 §7 风险 R4）。
