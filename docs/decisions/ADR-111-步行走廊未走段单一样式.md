# ADR-111：步行走廊「未走」段收敛为单一 (色, 宽, 透明度)，差异只保留方向箭头

## Status

Accepted（2026-11-04，team-lead 裁定采 designer 定稿；
**否决了架构初版的 `--map-walk-op-now: 1 → 0.55`**，理由见 Decision §2）

## Background

用户反馈：已走是灰色（符合预期），未走的部分出现深浅两种绿。

排查结论：**「未走两种绿」在当前设计下必然出现，不是绘制 bug。**未走几何有三档同色不同参数：

| 层 | 语义 | 色 | 宽 | 透明 | z | 证据 |
|---|---|---|---|---|---|---|
| `nowPath` | 当前步剩余部分 | `--map-walk-ahead` `#0b6e4f` | 7 | **1** | 73 | `src/components/nav/nav-map-walk.ts:71-76`、`src/app/globals.css:7728-7731` |
| `aheadPath` | 当前步之后所有步 | 同色 | 6 | **0.55** | 70 | `nav-map-walk.ts:65-70`、`globals.css:7727/7730` |
| `ghost`（ahead） | 另一段步行走廊 | 同色 | 4 | **0.4** | 68 | `nav-map-walk.ts:77-82`、`:212-216`、`globals.css:7742-7745` |

设计文档原把这定义为「三通道区分（色/宽/透明）」（`nav-map-walk.ts:6-11`），产品口径是「未走只有一种绿」。冲突在**口径**，不在实现。

逐一排除的其它假设：

- 「`now` 与 `ahead` 在同一段折线上重叠」 —— 排除，结构互斥：`ahead = steps.slice(idx+1)`，`now = splitStepByRatio(steps[idx]).remaining`（`src/components/nav/NavMap.tsx:1454-1456`），只共享 1 个顶点。
- 「相邻 step 端点重叠叠加」 —— **是放大器，不是主因**：共享顶点 + `lineCap:"round"`（`nav-map-walk.ts:102`）⇒ 每个 step 交界多一个直径约 7px 的深绿圆点；且 `/api/nav/walk` 存在被丢弃的步（`src/app/api/nav/walk/route.ts:122-125` 注释），可能造成几何断裂。
- 「外部道路 / 无路网回退走不同分支」 —— 不成立：几何来源唯一（`walk/route.ts:101` 只调 `fetchWalkingSteps`），`src/lib/walk/` 内无几何回退生成。
- 「多次绘制未清理旧图层」 —— 排除：`ensureWalkLayers` 幂等复用（`nav-map-walk.ts:118-142`），`apply` 走增量 `setPath`、空则 `map.remove`（`NavMap.tsx:1479-1490`），ghost 走 key-diff（`nav-map-walk.ts:230-252`）。

**主因**：同为「未走」的 `now` 与 `ahead` 各自保留了一套可独立调参的 CSS 变量 ⇒ 任何一次「只改一半」都会重现本缺陷。

## Decision

### 1. 未走段最终参数（采 designer 定稿）

```
color  = --map-walk-unwalked-color (= var(--map-walk-ahead), #0b6e4f)
weight = 6      (--map-walk-w-unwalked)
opacity= 0.75   (--map-walk-op-unwalked)
```

`now` 与 `ahead` **三项全等**。差异只保留 `zIndex`（73 / 70）与 `showDir` 方向箭头（`now` 为 true，`ahead` 为 false）——
**不再用颜色 / 粗细 / 透明度表达当前步**。

Token 层做法（三段式弃用，只增不改名）：

1. **定义保留**：7 个旧变量名一字不删（回滚安全、外部引用不破）；
2. **值改别名**：`--map-walk-w-now` / `--map-walk-w-ahead` → `var(--map-walk-w-unwalked)`；
   `--map-walk-op-now` / `--map-walk-op-ahead` → `var(--map-walk-op-unwalked)`；
   `--map-walk-w-ghost` → `var(--map-walk-w-corridor)`；`--map-walk-op-ghost` → `var(--map-walk-op-corridor)`；
   `--map-walk-op-ghost-done` → `var(--map-walk-op-done)`；
3. **`src/` 内引用归零**：含 `nav-map-walk.ts` 的 `readWalkStyle()`。CI 守卫（0 命中，globals.css 定义行除外）：

```
grep -rnE '\-\-map-walk-(w|op)-(now|ahead)\b' src/
grep -rn 'map-walk-op-ghost' src/
```

`readWalkStyle()` 硬编码兜底值同步为 `6 / 0.75 / 6 / 0.75 / 4 / 0.6 / 0.85` ——
主题失效（CSS 变量取不到）时会静默变样，这是本项目踩过的坑。

### 2. 为什么 0.75 而不是架构初版建议的 0.55

`#0b6e4f` 以不透明度 α 混到纯白后，按 WCAG 2.x 相对亮度公式算对比度（架构**独立复算**，非引用）：

| α | 混白后 RGB | 混纯白 | 混 `#f2f2f2` | 3:1 达标 |
|---|---|---|---|---|
| 0.40 | — | 1.89:1 | 1.84:1 | 否 |
| **0.55** | rgb(121,175,158) | **2.48:1** | 2.38:1 | 否 |
| 0.60 | — | 2.73:1 | 2.60:1 | 否 |
| **0.75** | rgb(72,146,123) | **3.69:1** | 3.44:1 | 是 |
| 1.00 | rgb(11,110,79) | 6.25:1 | 5.59:1 | 是 |

RGB 与 designer 记录逐通道一致（0.55 → (121,175,158)、0.75 → (72,146,123)）。
对比度 0.75 我算 3.69:1（她 3.70）、0.55 我算 2.48:1（她 2.26）—— 差异可能因她按底图瓦片色而非纯白混色，
**但两档达标/不达标结论完全一致**，故采她的定值。

**否决 0.55 的核心理由（不是口味）**：0.55 低于 WCAG 1.4.11 图形元素 3:1 下限。
把 `now` 也降到 0.55 虽然是最小改动，但它是把一条**本来就不达标**的线复制成两条 ——
属于「把缺陷统一化」。初版方案「只改 1 行、回滚成本最低」的优点**是真实的**，
但改完对比度仍是 2.48:1 ⇒ 用「改动小」换「缺陷长期存在」，不成立。

### 3. 结构性约束（本缺陷的真正成因，比色值更重要）

本次缺陷的成因不是色值错，而是**存在两套可独立调参的变量**（`--map-walk-op-ahead` 与 `--map-walk-op-now`）。
只改值不改结构，下次一定有人只改一半。因此定案**选「合并」而不是「注释强制同改」**：

- 单一语义组：`--map-walk-unwalked-color` / `--map-walk-w-unwalked: 6` / `--map-walk-op-unwalked: 0.75`；
- 走廊独立组：`--map-walk-w-corridor: 4` / `--map-walk-op-corridor: 0.6`；
- **`readWalkStyle()` 返回结构由「三套并列」改为「三组语义」**：`{ unwalked, walked, corridor, z }`；
- **`nowPath` 与 `aheadPath` 拿到的是同一个对象引用**，不是两份相等的值
  ⇒「给 `now` 单独调透明度」在**类型层面**就不成立（不再是靠人记得，而是写不出来）。

这是本 ADR 最关键的一条。初版把选择权留给了 Token 文件（「合并 or 注释强制同改」二选一），
designer 选了**合并 + 类型层阻断**，比注释约束强一个量级，采纳。

### 4. ghost 层：独立且明确**不**与未走段同值

`opacity 0.4 → 0.6`，保留「走廊参考线」语义 —— 它应明显弱于未走段，否则地图上会同时出现两条等权重的路径，用户无法判断该走哪条。

> 这条注记同时挡掉了架构曾担心的风险：把三档「抹平成同一个 0.75」。ghost **不是**未走段，
> 它是「另一段路程的预告/已过」，语义不同 ⇒ 允许且应当不同值。

### 5. `lineCap` / `lineJoin` 保持 `round`（但交界圆点不会完全消失，必须登记为已知残留）

**结论与 designer 一致：不改 `butt`。**但她的**理由需要修正一处**，否则真机验收会把它当新缺陷。

designer 的判断是「三元组统一成 0.75 后，圆点与两侧完全同色，交界自然成为连续圆角曲线」。
**这一句在数学上不成立**：两条折线是两个独立 `AMap.Polyline`，在共享顶点处是**两次独立的 source-over 合成**，不是「同一颜色画一次」。

```
单层 α=0.75                    → 合成 α=0.75   rgb(72,146,123)
两层叠绘 α=1−(1−0.75)² = 0.9375 → 合成 α=0.9375 rgb(26,119,90)
每通道差 Δrgb = [46, 27, 33]
```

对照修改前（`now` α=1 叠 `ahead` α=0.55）：`rgb(121,175,158)` vs `rgb(11,110,79)`，Δrgb = [110, 65, 79]。

⇒ 圆点的对比度**降低约 58%，但没有消失**。真机上仍能看到一个约 6px（= `strokeWeight`）的略深绿点。
必须把它登记为「**已知残留、已量化、已接受**」，不能写成「自然消失」—— 否则 C-5/C-6 的真机取色会把它当新缺陷重新提。

**为什么不改 `butt`**：两个相邻线段用 `butt` 端帽时，各自的端面垂直于**自己的**走向；
在弯道（步行路径绝大多数不是直线）上两端面不共线 ⇒ 弯道外侧留 V 形缺口、内侧重叠。
这是用一个更明显的缺陷换一个已被量化的小缺陷，不划算。`lineJoin: "round"` 同理保留。

三个可选解，按代价排序：

| 选项 | 做法 | 交界圆点 | 代价 | 结论 |
|---|---|---|---|---|
| **A（定案）** | 保持 `round`，接受 Δrgb=[46,27,33] 的残留 | 存在（弱） | 0 | **采纳** |
| B | `now ∪ ahead` 合并为**一条** `Polyline` 绘制，方向引导只靠 `showDir` | **完全消失** | 失去 `zIndex 73/70` 的层级差（合并后无意义）；当前步不再有独立图层，`showDir` 会覆盖整条路 | 若真机确认圆点仍碍眼，这是唯一能真正消掉的方案 —— 需 designer 重新定案，**不得**由实现者自行选择 |
| C | `lineCap: "butt"` | 消除圆点，但新增弯道 V 形缺口 | 弯道断口 | **否决** |

### 6. C-6 的可断言形式（AMap 是 canvas，不能按 DOM 写）

**先纠一个坑（designer 提醒，成立）**：`AMap.Polyline` 不是 DOM 元素，是 canvas 绘制 ⇒
`querySelector` / `getComputedStyle` 读不到任何折线样式。按 DOM 思路写断言必然空转。

**一级（CI 门禁，本 ADR 采纳）**：注入假构造器捕获 `new AMap.Polyline(opts)` 的入参。
`nav-map-walk.ts:36-38` 定义 `PolylineCtor` 时已为注入留好口子，无需改生产代码签名。

1. 从捕获到的折线里找**首尾相接**的两条（`endA[last] ≈ startB[0]`，容差 1e-6）；
2. `assert.equal` 比较 `strokeColor` / `strokeOpacity` / `strokeWeight` 三项**全等，不设容差**（0.75 与 0.7499 是两个值）；
3. 白名单：只允许 `zIndex`（73/70）与 `showDir`（true/false）不同；**其余任何字段不同即失败**。

**二级（发版前一次，不作门禁）**：Playwright 截图 → PNG 解码 → 沿路径**法向**取中轴（避开 1px 抗锯齿），
接缝前后各 5 点，RGB 每通道差 ≤ 3。不作门禁的原因：底图瓦片含建筑/绿地/水域，局部底色会污染 α 反推。

> ⚠️ 一级断言**只覆盖「两侧三元组相等」**（C-6 的原义），**不覆盖交界圆点**。
> 圆点属「两个相等样式的叠绘后果」，任何样式断言都测不出来 —— 这正是 §5 必须把它登记为已知残留的原因。

## Consequences

正面：

- 「未走两种绿」从**必然出现**变为**不可能出现**：同色、同宽、同透明度，且两侧共用同一组变量 ⇒ 结构上无法「只改一半」。
- 对比度 3.69:1 达 3:1 下限，可读性有量化保障，不是口味。
- 通道差异改由 `showDir` 方向箭头承担 —— 保住了「下一步往哪走」这一唯一视觉引导，代价是箭头渲染成本（AMap 原生，无额外实现）。
- C-6 用**假构造器捕获 `new AMap.Polyline(opts)` 入参**的方式实现（Decision §6），在 CI 里跑、不依赖真机截图；
  且 `nav-map-walk.ts:36-38` 的 `PolylineCtor` 已为注入留好口子 ⇒ **不为测试改生产代码签名**。
- 结构收口后，「只改一半」从「靠纪律避免」升级为「类型层面写不出来」：`nowPath` 与 `aheadPath` 持有同一个对象引用。

负面（均已承接）：

- 改动面比初版的「1 行」大：`globals.css` 7 个变量改别名 + 新增 5 个，`nav-map-walk.ts` 的 `readWalkStyle` 返回结构与读取键全部重写。回滚方式相应从「1 行」变为「7 个别名还原为字面量 + 还原 `readWalkStyle` 返回结构」（可脚本化，一次性）。**这仍是整个批次里回滚最简单的一项** —— 不触碰任何判定逻辑。
- 当前步的强化**只能靠方向箭头**（原先靠「更深+更粗+更高层」三重）。若真机反馈「看不出当前步」，承接方式是调箭头尺寸/颜色对比，**不得**把 `now` 的透明度或宽度改回独立值 —— 那是本次缺陷的复发路径。
- **交界圆点降为弱残留（Δrgb=[46,27,33]），未消失**，见 Decision §5。已量化、已接受；若真机仍碍眼，只能走 §5 选项 B（合并为单条折线），需 designer 重新定案。
- 两条对比度豁免必须在 Token 注释里写明，否则将来无障碍审计会把它们当新缺陷提出来：
  1. `ghost`（0.6 → 2.73:1）低于 3:1，但它是**走廊参考线**（非当前要走的路径），不计入图形对比度要求；
  2. `done`（`#8c93a0` @ 0.85 → 2.53:1）低于 3:1，但已走段是**去强调**语义（用户不再需要它）。

验收判据：直接采用 designer 的 C-1 ~ C-10（见 `docs/迭代-导航修复-20261104/03-设计-导航信息层与步行线规范.md` §4.5.1–4.5.5、§4.6、§4.6.1）。其中：

| 判据 | 形式 | 本 ADR 的补充约定 |
|---|---|---|
| **C-1** | `styleOf("now")` 与 `styleOf("ahead")` 的 `{color, weight, opacity}` 逐字段 `===` | 结构收口后两者是**同一对象引用** ⇒ C-1 退化为 `assert.strictEqual(now.unwalked, ahead.unwalked)`，更强的断言 |
| **C-2** | `globals.css` 中 `-op-ahead` / `-op-now` 只允许 `var(--map-walk-op-unwalked)`，不得出现 `0.55` / `1` 字面量 | — |
| **C-3** | `nav-map-walk.ts` 0 个颜色字面量（`#fff`/`#000` 也不允许） | 兜底值只能写数值（6/0.75/4/0.6/0.85），不能写色值 |
| **C-6** | 接缝两侧 `(strokeColor, strokeOpacity, strokeWeight)` 全等，**不设容差** | **必须进 CI**，实现方式见 Decision §6（假构造器捕获入参）。它精准锁死「同一段连续路径上出现两种绿」的复发路径 |
| **C-8** | 对比度 ≥ 3.0:1 | 即 Decision §2 的表格（0.75 → 3.69:1） |
| C-4 / C-5 / C-7 / C-9 / C-10 | designer 原文 | C-10 的「ghost opacity 不高于当前段」即 Decision §4 的注记 |

**CI 守卫（与 C-2 并列，纯 grep，无需跑图）**：

```
grep -rnE '\-\-map-walk-(w|op)-(now|ahead)\b' src/    # 期望 0 命中（globals.css 定义行除外）
grep -rn 'map-walk-op-ghost' src/                      # 期望 0 命中（同上）
```

> ⚠️ C-6 与上述 grep **都不覆盖交界圆点**。圆点由「两个相等样式的叠绘」产生，任何样式断言都测不出来
> ⇒ 它是 Decision §5 登记的**已知残留**（Δrgb=[46,27,33]），验收时应按「已接受」处理，不得据此判失败。
