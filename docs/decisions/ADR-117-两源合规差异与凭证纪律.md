# ADR-117：两源分别合规、入库凭证纪律、未知值只陈述我方边界

## Status

Accepted（2026-11-06 · 迭代批次 `docs/迭代-跨境交通-20261106/`）

> 条款引文均贴原文与链接。海事局条款页**不分条不编号**，文中 C1–C4 一律为
> **【我方引用编号】**，不是条款页的条号，不得当作官方条号对外引用。
> 本 ADR 只记录义务边界与禁令，不复述 spec §4 的断言表、字段表与门禁脚本清单。

## ① 我们选了什么

**一、两源不合并，各按自己的条款设义务。**

机场（`data.gov.mo` 开放数据）：义务仅「註明數據來源＋取得日期」。条款依据转引自 spec §4.1
（行 1184）：「data.gov.mo《UseClause》第 2 条：『完全開放數據…無須另行得到書面或其他方式的授權』」。
须如实记录两处边界：spec 该行自述「**本轮未重新核对条款原文，以 `02-调取计划.md` §一所录为准**」；
且本轮查 `02-调取计划.md` 只找到 API 端点 URL，**仓库内未记录该条款页 URL**。因此本 ADR
不补写链接、不把「第 2 条」当作已核实条号，商业化前必须回源核对。

船（`澳門特別行政區海事及水務局`，非商业许可）：条款页
`https://www.marine.gov.mo/subpage.aspx?a_id=1432716165`（页脚「最後修改日期:07-07-2016」，
**该页不分条不编号**，见 spec §4.2 行 1194/1195）。四条硬义务，均贴原文：

- 【我方引用编号 C1】来源 + 日期 + 内容准确（spec §4.2 行 1194）：
  「本網站的任何內容，除屬於第三方外，均可供非商業性使用、複製及再發佈而無須得到海事及水務局
  書面同意，**但必須註明內容來源於"澳門特別行政區海事及水務局"以及獲得內容的日期**；必須確保
  所複製的內容準確」。署名须逐字使用官方全称「澳門特別行政區海事及水務局」，不得简写为
  「海事局」或「海事及水務局」（spec 行 1197）。
- 【我方引用编号 C2】不得改写内容（spec §4.3 行 1205）：
  「無論是商業性或非商業性複製或再發佈，**均不可以修改任何內容**，除非得到海事及水務局的
  特別書面授權」。
- 【我方引用编号 C3】不得做非首页深链（spec §4.4 行 1216，页内小标题「￭ 連到本網站」）：
  「外部網站直接連到本網站的首頁無需得到批准，但仍必須在超連結上使用本網站的官方名稱。
  **如果要連結到非首頁，則必須事前得到海事及水務局的書面授權。**」
- 【我方引用编号 C4】不得商业性再发布（spec §4.5 行 1225）：
  「未得到書面授權，**禁止**對本網站全部或部分內容作任何形式的**商業性**複製或再發佈」。

**二、凭证纪律（起因：ADR 是版本库唯一的文档入库面）。**
`.gitignore` 第 77–81 行忽略 `/docs/*`，例外只有 `!/docs/decisions/` + `!/docs/brand-export/`
与 `!/docs/decisions/ADR-*`；spec §4.6 行 1230–1239 记 `git ls-files docs` 实测只有 23 个文件
（15 个 `ADR-1xx-*.md` + 8 个 `brand-export/*.png`），本轮复测 ADR 数仍为 15。由此定：

- **向 ADR 写入前必须跑** `grep -rn "APPCODE [A-Za-z0-9]\{20,\}" docs/decisions/`，0 命中才写
  （spec §4.6 后果 1，行 1246）。ADR 是散文、天然会写「怎么调上游」，最容易顺手贴上真实调用示例。
- `.env.example` **被 git 跟踪**（本轮 `git ls-files .env.example` 有输出；spec 行 1248/1251），
  `.gitignore:71` 的 `.env*` 对已跟踪文件不生效 ⇒ 绝不可写真实凭证；**禁止对它执行
  `git rm --cached`**。
- spec 本身不入库（`/docs/*`），不能当团队唯一口径来源；长期存活的决策必须落成 ADR
  （spec 行 1374、§4.6 后果 4 行 1249）。
- 修改 `.gitignore` 第 71 / 77–81 行前，须先跑全仓扫描
  `grep -rn "APPCODE [A-Za-z0-9]\{20,\}" docs/ .verify/ .workbuddy/`（spec 行 1247）。

**三、本轮新增的通用规则（team-lead 与设计侧本轮定，不在 spec §9）：**

> **描述未知时，只能陈述我方边界（「未能識別」），不得断言上游状态（「未提供」）。**

词族七词：`哨兵` / `占位符` / `无意义值` / `未公開` / `未公佈` / `不提供` / `未提供`
**禁令的边界：禁的是「替上游断言」，不是禁「陈述自己的边界」。只有清单没有边界会被过度扩张到
所有负面词。**

适用范围：用户可见文案 + `aria-label` + 代码注释 + **标识符 + 类名**（后三者给下一个人抄，
IDE 自动补全传播最快）。

判断口诀（原样）：`把这句话读给「上游的工程师」听。如果他会反驳「我们没这么说 / 我们没说这是原因」，就是越界。`

事实依据：`scripts/fixtures/xborder/airport-arr.json` 有 6 条 `status` 是字面量 `"0"`
（本轮 `grep -c` 实测 = 6，见该文件行 543/551/559/567/575/583；spec §2.10.1 行 929 记「`0` × 6」）。
我们只知道「上游返回 0、我方白名单不认」，**不知道 0 的语义**，故不能写成「上游未提供状态」。
出处边界须如实记录：本轮以 GNU grep 扫 `docs/ src/ scripts/`（含被忽略文件），**未找到这条通用
禁令的既有文档条目**，其唯一出处是本轮 team-lead 的口述裁决；仓库内存在同源先例
`docs/迭代-v360-20261029/01-产品-需求对账与验收标准.md:34`（「『官方主表不列』不等于『已停运』…
只能判定『官方当期不提供』，不能据此推断线路已取消」）。

## ② 为什么不是另一个（含被否方案的具体代价）

**两源一刀切（统一归一、统一署名、统一深链规则）。** 代价是两条硬义务同时被触发：
若统一做 `trim()` 之外的归一（大小写、繁简、去括号、词典映射），直接违反【我方引用编号 C2】，
spec 行 319 给的实例是把「香港上環」写成「香港上环」、把「待航」写成「待出发」都算修改内容；
违反的后果是非商业许可的书面授权前置义务生效，船侧数据源整体不可用。若反过来把机场也锁死，
则机场侧本只需「註明來源＋取得日期」，白白放弃开放数据自由度，且两源混在同一个弹窗家族里，
一个统一一个不统一会立刻被用户看成「这里能改那里不能改」（spec 行 319）。若给船侧加
「查看原文」链到 `departure.aspx`，违反【我方引用编号 C3】非首页深链须事前书面授权
（spec 行 1216–1218）。

**把明文 APPCODE 写进 ADR「方便下一个人照着调」。** 代价：ADR 是版本库唯一入库的文档面，
写进去等于进公开仓库。本仓库已有因「公开仓库含政府系统鉴权算法逆向实现 + 大规模自动采集证据」
被卷入账号级封禁约 5 周的事故（`docs/复盘-GitHub封号事故-20261028.md` 行 4/13/23/42–45）；
spec 行 1168 记本轮已把 docs 下明文 APPCODE 全部替换为 `AACM_APPCODE` 引用、`docs/` 下 0 命中；
`02-调取计划.md` 行 36 记「留明文只会招致平台轮换，没有收益」。故纪律是「入库前先扫」而非
「写完再删」：扫描成本一次 grep，漏掉的代价是一次公开面暴露加平台轮换凭证。

**用 `git rm --cached .env.example` 把示例文件移出索引以求干净。** 代价见 spec 行 1251 原文：
「它就会瞬间变成被忽略文件、后续改动再也进不了版本库，且没有任何提示」。配置契约静默消失，
且无人收到告警。

**把未知状态写成「上游未提供 / 未公開 / 这是无意义值」。** 代价：这是对上游状态的断言，
我方没有证据——fixture 里的 `"0"` 只证明「上游返回了 0」与「我方白名单不认」，不证明
「上游没有状态」或「0 是占位符」。一旦这样写进标识符或类名，IDE 自动补全会把这个错误前提
传播给下一个人，后续有人据「上游不提供」去设计兜底或删字段，就把我方认知边界误固化成上游事实。
本仓库已就该形状吃过亏：`docs/迭代-v360-20261029/01-产品-需求对账与验收标准.md:34` 记 DSAT
的「官方主表不列」曾被误读为「已停运」。

## ③ 什么条件下重新评估

- **商业化**（贴广告、会员费、卖数据）：船侧必须先取得书面授权，机场侧须核对
  `data.gov.mo` 商业使用条款（spec §4.5 行 1226）。这一条同时是「回源核对机场条款页 URL 与
  条款原文」的触发点——本 ADR ① 中标注的转引与链接缺口须在此时补实。
- **任一上游条款页改版或 URL 变更**：重新贴原文与链接，重新确认 C1–C4 是否仍成立；
  C1–C4 是我方引用编号，随引用对象变化须同步，不得沿用旧编号指代新内容。
- **`.gitignore` 第 71 / 77–81 行被改动**（有人要把 docs 纳回版本库）：先跑全仓凭证扫描再谈
  （spec 行 1247）。
